## Overview

Add Progressive Web App capabilities to Xtimator so that field contractors can install it on their phone's home screen and use it like a native app. The app must load even when offline, show previously cached estimates in read-only mode, and present a proper install prompt at the right moment.

This is a bounded infrastructure enhancement — no new features, no new data model. Scope is strictly: installable + offline shell + read-only cache.

---

## Goals

- Xtimator passes all Lighthouse PWA installability checks
- Contractors can add it to iOS Safari and Android Chrome home screen
- App shell loads offline (no blank screen when there's no internet)
- Previously visited estimates list and detail pages load from cache when offline
- Install prompt surfaces after the user has created their first estimate
- All existing functionality unchanged when online

## Non-Goals

- Push notifications (→ Phase 77, already planned)
- Offline estimate creation or audio recording
- Background sync / queue mutations for later
- Native app store submission

---

## Tech Decisions

| Decision | Choice | Reason |
|----------|--------|--------|
| Service worker library | `@ducanh2912/next-pwa` | Zero-config, Workbox-backed, App Router compatible, large community |
| Offline strategy | Read-only cache (Strategy B) | Supabase auth + AI + S3 make full offline impractical |
| Manifest | Keep existing `app/manifest.ts` | Already dynamic + branding-aware; just needs real fallback icons |
| Icons | Static PNGs in `public/icons/` | Reliable, no runtime generation needed |
| Install prompt | Custom component, shown post-first-estimate | Avoids annoying users who haven't engaged yet |

---

## Caching Strategy

| Resource | Strategy | Rationale |
|----------|----------|-----------|
| App shell (HTML/JS/CSS) | **Cache First** (pre-cached) | Always load instantly |
| Static assets in `public/` | **Cache First** | Fonts, SVGs, CSV template |
| Supabase GET calls (estimates list, detail) | **Stale-While-Revalidate** | Show cached data, refresh in background |
| S3 photos | **Cache First** with 50 MB limit | Heavy but needed for offline viewing |
| Auth endpoints | **Network Only** | Can't auth offline |
| AI / mutation API routes | **Network Only** | Server-side AI, never cacheable |

## Implementation Tasks

### Task 1 — Icons & Manifest Polish
- Generate `public/icons/icon-192.png`, `icon-512.png`, `icon-maskable-192.png`, `icon-maskable-512.png`
- Update `app/manifest.ts` fallback icons array to point to `/icons/*`
- Add `apple-touch-icon` link to `app/layout.tsx`

### Task 2 — Viewport & Meta Tags
- Export `viewport` const from `app/layout.tsx` (Next.js 15 pattern)
- Add `theme-color` (dark `#0a0a0f`, light `#ffffff`) with `media` attribute
- Add `apple-mobile-web-app-capable` and `apple-mobile-web-app-status-bar-style` meta tags
- Verify manifest link is auto-injected by Next.js (it is, via `app/manifest.ts`)

### Task 3 — Service Worker Setup
- Install `@ducanh2912/next-pwa`
- Wrap `next.config.ts` with `withPWA({ dest: 'public', disable: process.env.NODE_ENV === 'development' })`
- Configure `runtimeCaching` rules matching the strategy table above
- Add `public/sw.js` and `public/workbox-*.js` to `.gitignore`
- Add `app/offline/page.tsx` — simple branded offline fallback page
- Register fallback route in withPWA config

### Task 4 — Install Prompt
- Create `components/pwa/use-install-prompt.ts` — captures `beforeinstallprompt`, tracks dismissed state in localStorage
- Create `components/pwa/InstallBanner.tsx` — bottom banner: "Install Xtimator for quick access" + Install / Not now
- Show banner only when: PWA not already installed + user has ≥1 estimate + not previously dismissed
- Mount in `app/(app)/layout.tsx` so it only shows to authenticated users

### Task 5 — Offline UX
- Create `components/pwa/OfflineIndicator.tsx` — subtle top bar "You're offline — showing cached data" using `navigator.onLine` + `online`/`offline` events
- Mount in app shell layout
- Disable create/record CTAs when offline (grey out + tooltip "Requires internet connection")

### Task 6 — QA & Lighthouse
- Verify Lighthouse PWA score ≥ 90 on mobile simulation
- Test install flow on iOS Safari (Add to Home Screen) and Android Chrome
- Test offline: kill network, reload, confirm cached estimates visible
- Test online recovery: reconnect, confirm data refreshes
