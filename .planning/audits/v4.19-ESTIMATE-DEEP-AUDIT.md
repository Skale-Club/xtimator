# v4.19 Deep Audit — Estimate Generation & Editing System

**Date:** 2026-07-17
**Method:** 6 parallel adversarial verification passes (capture/upload, transcription, photo/vision, AI generation core, editor/save path, refine + trust boundary). Every finding below was CONFIRMED against source with file:line evidence; refuted first-pass claims were dropped. This document is the research input for the v4.19 roadmap and phase plans.

---

## A. Trust boundary (CRITICAL)

**A1. A sent/viewed/signed/accepted estimate remains fully editable — no guard at ANY layer.**
- UI: `isReadOnly = !state.is_current` only (`components/workspace/estimate/estimate-editor.tsx:222`).
- Action: `saveEstimate` (`lib/actions/estimate.ts:48-356`) has zero checks on `sent_at`/`client_response`/signatures/`is_current`.
- RLS: company-membership only, no status predicate (`supabase/migrations/20260526000001:140-142`).
- Triggers: only `trg_set_estimate_seq` (BEFORE INSERT).
- Refine route blocks only `!is_current` (`app/api/estimates/[id]/refine/route.ts:93-99`), not sent/signed.

**A2. Signed-then-edited scenario, traced end-to-end:** client signs $12,400 → owner edits to $15,000 →
- Public link re-renders **live rows** ($15,000) — `lib/queries/share.ts:117-138, 243-246`, no cache, share_token has no status filter.
- On-demand PDF re-renders live ($15,000) — `app/api/estimates/[id]/pdf/route.ts:44-52`, ETag keyed on `updated_at`.
- Emailed PDF is generated at send (`send/route.ts:171-194`) but **never stored** — no immutable server-side evidence exists.
- `estimate_signatures` stores signature PNG + IP + UA but **no amount, no items** (`migrations/20260519000002:13-23`).
- `saveEstimate` writes **zero** activity rows; no `estimate_updated` event type exists anywhere. Tampering is invisible in the audit trail.

**A3. New-version path is safe by accident:** `createBlankEstimate` flips `is_current` but the signed row keeps its `share_token`; the old link keeps showing signed content. In-place editing is the dangerous path — and the product steers users to it.

**Fix direction:** (1) snapshot-on-sign — `signed_content JSONB` + `signed_total` on `estimate_signatures`, populated in `sign/route.ts:73-83`; share/PDF render from snapshot when a signature exists (~0.5d). (2) freeze-on-send/sign — server-side guard in `saveEstimate` + refine route; UI forces "create new version" (~1.5-2d). (3) `estimate_updated` activity event on every save.

## B. Save path atomicity & version authority (HIGH)

**B1. `saveEstimate` is non-atomic — header first.** Ordered writes: estimate header incl. totals + `updated_at=now()` (`:130-163`) → sections insert/update (`:190-303`) → per-section orphan item deletes (`:306-322`) → orphan section deletes (`:326-343`) → project total (`:347-352`). No transaction/RPC. Failure at any later step leaves header totals ≠ items.

**B2. Session poisoning (the compounding bug):** a partial failure commits the new `updated_at` but returns generic `{error}`; client keeps stale `expectedUpdatedAt` → every subsequent save returns `{conflict:true}` → user is told "changed elsewhere" (false) and the only offered exit ("Load latest version") **discards their edits**. One transient DB hiccup ⇒ forced data loss.

**B3. Silent write to superseded version:** no `updated_at` trigger on `estimates`; the supersede `UPDATE ... is_current=false` (`:393-396`) doesn't bump `updated_at`, so a stale open tab passes the optimistic check and writes to the orphaned old version with zero feedback. No server-side `is_current` guard exists.

**B4. False-clean:** `MARK_SAVED` (`use-estimate-reducer.ts:476-477`) clears `isDirty` unconditionally; a keystroke landing during an in-flight save (payload snapshotted at `estimate-editor.tsx:240`) is stranded — no dirty indicator, no beforeunload warning.

**B5. Temp-id churn:** `MARK_SAVED` never remaps `temp-` ids to server ids, so every subsequent save re-INSERTs those rows and orphan-deletes the previous ones — write amplification + a transient duplicate window.

**B6. Conflict UX:** conflicted autosave re-fires on every keystroke (state-dependency effect, `estimate-editor.tsx:363-373`), stacking 15s toasts; the only resolution is a destructive reload.

**B7. Validation gaps** (`lib/schemas/estimate.ts`): `quantity`/`unit_price`/line `discount`/`cost`/`markup_pct` accept **negatives** (finite-only); caps allow 200×500 = 100k items (sequential-write DoS shape). Currency/language are NOT writable via save (verified safe).

**B8. Client preview ≠ server totals:** reducer `recalculate` (`use-estimate-reducer.ts:139-177`) applies flat tax only — no `tax_config` per-category, ignores per-line `taxable`. With labor-exempt tax_config active, a $30k estimate shows **$1,200 more tax in the editor** than persists. Corollary: `taxable=false` toggle is currently a **no-op** in the flat path (server also ignores it — `compute-totals.ts:142`).

**B9. Editor performance:** `estimate-document.tsx` (2,025 lines) has zero `useMemo`/`memo`; every keystroke recalculates + re-renders the whole tree under dnd-kit.

**Fix direction:** single Postgres RPC (compare-and-set `updated_at` + `is_current` guard + all upserts + orphan deletes atomic, returns real ids + new `updated_at`); `moddatetime` trigger on estimates; dirty-epoch reconciliation in `MARK_SAVED`; id remap; conflict backoff + non-destructive resolution; zod `.min(0)` + realistic caps; shared engine (or adopt server totals on save) for preview parity.

## C. AI generation core (HIGH)

**C1. No timeout on the PRIMARY generation fetch** — `lib/ai/providers/openrouter.ts:191` has no AbortSignal (every `openrouter-client.ts` call has 120/300s). A hung socket never throws ⇒ **Gemini fallback unreachable**, Inngest step pinned. Same gap: `lib/ai/needs-details.ts:87`, `lib/estimate/price-research/adapters/openrouter-web.ts:154`, `anthropic-web.ts:66` (SDK default 10min).

**C2. `max_tokens: 4096` is tight** — a rich 40-50-item estimate needs ~2,900-4,400 output tokens. Truncation → unterminated JSON → generic "malformed tool-call arguments" → falls to Gemini fallback (NOT the schema-retry; Gemini has no output cap so it often self-heals, masking the cause). `finish_reason` is never read — a lucky truncation persists a **silent partial estimate**.

**C3. Live OpenRouter tool schema is missing `taxable`/`tax_category`/`cost`/`markup_pct`** (`openrouter.ts:23-77` vs `gemini.ts:144-154`, zod `schema.ts:31-43`). On the primary path the model is never asked for them ⇒ per-category tax (TAX-03) and cost+markup (MARK-01) only work via Gemini fallback or refine.

**C4. Quality gate is only `total > 0 && has items`** (`vagueness.ts:41-46`; `assess.ts` adds nothing else). No duplicate-line detection, no qty-0-with-price flag, no per-estimate total ceiling (only $1M **per unit** clamp — quantity unbounded). `quality-signal.ts` warns Sentry at ≥15% discrepancy but never blocks. Auto-refine (cap 1) only rescues the $0/empty case with a one-sentence hint.

**C5. Default temperature** on all estimate generation (no `temperature` set anywhere in the estimate providers) — maximizes run-to-run price variance.

**C6. Non-transactional version-flip → insert** (`lib/services/generate-estimate.ts:441-582`): crash window leaves a project with no current estimate, or an estimate with totals but zero items.

**C7. Minor:** unbounded aggregate prompt (per-field 50k cap only, unlimited transcript/photo counts); within-tenant client mis-link via normalized-name collision (`:230-269`, tenant-scoped — cross-tenant REFUTED); dead `lib/ai/providers/anthropic.ts` adapter; model-id drift (`claude-sonnet-5` vs research fallback `claude-sonnet-4`).

## D. Billing & cost integrity (MEDIUM-HIGH)

**D1. Refine has NO credit gate** — `refine/route.ts` runs Whisper+Vision+Claude behind only `refinePerMinute` (10/min). A zero-balance company cannot generate but can refine indefinitely at platform cost. Grep `checkCredits` in `app/api/estimates/**` → 0 matches.

**D2. Whisper cost keys on CLIENT-declared `duration_seconds`** (validated only 0<d≤900 — `lib/actions/recording.ts:255`; cost at `transcribe-audio.ts:254`). Declaring 1s on a 10-min take → cost $0.0001 → debit `round(0.045)=0` credits ⇒ **one credit funds unlimited transcription**. Compounded by: quota `audio_minutes` is a no-op (`lib/quota.ts:82-84`), `maxAudioMinutesPerEstimate` entitlement (2/15/30) is **enforced nowhere** (dead entitlement), `checkCredits` fails open on read error.

**D3. Retry re-pays Whisper:** a generate-stage Retry re-dispatches the whole pipeline; the transcribe job has no transcript-exists short-circuit ⇒ second real Whisper call + duplicate `ai_cost_events` row (no unique on `(attempt_id, operation_type)` — `phase110_ai_cost_events.sql:43-45`). Customer charged once (idempotent debit — correct); platform pays N×, measured cost inflated N×.

**D4. Photo-batch cost roll-up is dead code:** `analyzePhotoOR(base64, mimeType)` called WITHOUT `costContext` (`analyze-photos.ts:176`; also `multimodal.ts:64`) ⇒ cost rows get random attemptId + null company (`openrouter-client.ts:284-292`) ⇒ the debit read-back (`:251-270`) matches zero rows every time ⇒ `photo_batch` debit records null cost. Latent until charging calibration tightens.

**D5. Provider misattribution:** `transcribeAudioOR` discards `servedBy` (`openrouter-client.ts:169`); OpenAI-direct fallback recorded as `openrouter` in `ai_cost_events` + `pipeline_events`.

**D6. No worker-side audio size cap** (bucket caps at 50MB — `initial_schema.sql:270`); blob fully buffered + base64 (+33%) in memory. No Whisper `language` hint despite the resolved-language cascade (PT-BR short-clip quality loss; output-language cascade itself is NOT corrupted — verified).

## E. Photo pipeline fidelity (HIGH product quality)

**E1. Photos 21-50 are silently never analyzed:** `load-photos` is `.order('sort_order').limit(20)` (`analyze-photos.ts:151`) — always the FIRST 20; re-dispatch never reaches 21+. Server allows 50/project. No user notice, no `ai_description IS NULL` re-analyze path.

**E2. User captions never reach generation:** `generate-estimate.ts:187-189` reads only `ai_description`; `photos.caption` ("north wall, 12ft ceiling") is rendered in share/PDF but discarded from the estimate prompt.

**E3. One bad photo fails the whole batch:** `Promise.all` (`analyze-photos.ts:158`) rejects on first exhausted step ⇒ estimate never generates in the capture auto-chain; already-analyzed descriptions persist unmetered. Refine's `ingestMultimodal` (`multimodal.ts:62-69`) skips failures — same primitive, opposite policy.

**E4. `max_tokens: 300`, `finish_reason` never read** — mid-sentence truncated descriptions saved as-is. Gemini vision fallback has NO cap (asymmetric outputs).

**E5. Structured-extraction opportunity:** tool-call vision (zod: surfaces/measurements/materials/damage + overall_description) into `photos.ai_extraction JSONB`; serialize a compact measurements table into the prompt. ~1.3-1.7× per-photo cost; biggest quality lever for measurement-heavy trades.

## F. Capture & upload resilience (HIGH product)

**F1. Single-shot uploads, no retry** (`capture-recorder.tsx:812` audio, `:732` photo → `supabase-provider.ts:28-41`). Blob exists only in memory (recorder started with no timeslice — single chunk at stop). Failure window on 1 Mbps uplink: 40s-2min. Manual Retry (max 2) exists but is mount-bound.

**F2. `beforeunload` guard drops exactly when upload starts** (`:508-513` gated on `isRecording`, which is false during upload/dispatch).

**F3. There is NO service worker:** `public/sw.js` is a self-destruct worker (no fetch handler, unregisters itself); `SWRegister` actively unregisters + deletes caches. `OfflineIndicator` claims "showing cached data" — **false copy, no cache exists**. Zero IndexedDB usage in app code.

**F4. Draft persistence only in 1 of 3 capture flows** — `draftKey` passed only by `new-project-wizard.tsx:166`; the `?capture=` popup and legacy route persist nothing.

**F5. Permanent storage orphans:** upload precedes the DB row + credit gate — out-of-credits user uploads full blob then gets blocked ⇒ orphaned audio object that `cleanup-audio.ts` (row-driven) can never see. Photos have NO cleanup at all; failed row-create + removed error-thumbnail = permanent orphan.

**F6. iOS backgrounding mid-recording** → track mute/inactive → auto-submits truncated audio with **overstated** wall-clock duration.

**Fix ladder:** retry wrapper w/ backoff in `lib/storage` (~0.5d) → beforeunload covers upload window (~1h) → IndexedDB blob persist + "Resume upload" (~2-3d, the real fix; fail-soft for iOS eviction/private mode) → bucket-reconciliation cron (~1-2d). TUS resumable: defer (breaks the StorageProvider abstraction, low ROI at ≤10MB).

## G. Refine safety (MEDIUM)

**G1. Refine reads the PERSISTED estimate** (`refine/route.ts:90`), not editor state; no `isDirty` guard on the dialog ⇒ user can lose their edit AND get a refine computed on stale data (both race branches lose).

**G2. `APPLY_REFINEMENT` regenerates every section/item id** (`use-estimate-reducer.ts:503,508,536`) ⇒ next save deletes + reinserts 100% of rows (`created_at` reset; blast radius contained — no external FKs to item ids, `estimate_photos` keys on estimate_id; `price_source`/tax/markup fields ARE preserved — earlier regression already fixed).

**G3. No review-before-apply:** refinement replaces the tree immediately ("review and save"); no diff, no per-change accept/reject, no undo stack anywhere in the editor.
