<objective>
Fix the accessibility / DevTools warning "Incorrect use of <label for=FORM_ELEMENT>" on the signup and login pages.

Root cause: `<FormControl>` is a Radix `Slot.Root` that forwards `id={formItemId}` to its first DOM child. On password fields, the first child is the `<div className="relative">` wrapper (for positioning the eye-toggle) instead of the `<Input>`. The id lands on a non-form element, so `<FormLabel htmlFor={formItemId}>` points at the wrapper div.

Fix: invert the nesting so `<FormControl>` wraps only `<Input>`, while the relative wrapper now sits OUTSIDE `<FormControl>` and contains both `<FormControl><Input/></FormControl>` and the `<button>` toggle. This routes the id to the actual `<input>` element while keeping the toggle visually positioned.

Purpose: clean accessibility, no a11y/DevTools regressions on the two highest-visibility unauthenticated pages.
Output: edited signup-form.tsx (2 password fields) and login-form.tsx (1 password field). No changes to `components/ui/form.tsx`.
</objective>

function FormControl({ ...props }: React.ComponentProps<typeof Slot.Root>) {
