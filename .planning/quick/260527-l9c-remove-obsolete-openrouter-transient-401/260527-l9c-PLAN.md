<objective>
Remove the obsolete OpenRouter transient-401 "User not found" special case from `lib/ai/openrouter-client.ts` and restore correct behavior: ANY 4xx (including 401) throws immediately as a real auth/config error, while only 5xx and network errors retry then fall back to OpenAI direct.

Purpose: OpenRouter deployed a fix on 2026-02-20 so that infrastructure/auth-lookup failures now return 503, not 401. A `401 "User not found"` today is therefore a GENUINE auth failure (dead/invalid/revoked key) — confirmed in production 2026-05-27 where a dead key caused all AI tasks to fail while the "transient" treatment masked the real error and wasted a retry. Every AI task in the app routes through this one key (lib/ai/index.ts), so masking real 401s is high-impact.

Output: A single-file mechanical refactor — delete one helper function, simplify two 4xx guards, and correct the doc/inline comments. Exported signature and the 5xx/network resilience path are untouched.
</objective>
