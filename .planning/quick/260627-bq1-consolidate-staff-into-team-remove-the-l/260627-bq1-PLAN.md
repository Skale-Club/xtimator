# Consolidate Staff into Team

## Goal

Make Team the single member-management surface. Team invitations collect the
member's display name, acceptance persists that name on `company_members`, and
PDF estimates continue resolving “Prepared by” from the creating member.

## Tasks

1. Add `display_name` to pending company invites and thread it through Team
   invite validation, storage, roster data, UI, and acceptance.
2. Remove the legacy Staff navigation, component, and server actions; preserve
   `/settings/staff` as a redirect to `/settings/team`.
3. Add regression coverage for invite-name persistence, acceptance attribution,
   legacy-surface removal, and the migration contract.
4. Run focused tests, lint, production-source typecheck, and a production build.

## Must Haves

- Team is the only visible settings entry for company users.
- Inviting a teammate requires a human-readable name and email.
- Accepted membership rows contain `display_name`, enabling the existing PDF
  `Prepared by` lookup through `created_by_user_id`.
- No production code writes or queries role `staff`.
- Existing `/settings/staff` bookmarks redirect safely to Team.
