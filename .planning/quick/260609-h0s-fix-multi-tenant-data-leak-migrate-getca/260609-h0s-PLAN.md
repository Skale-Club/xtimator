<objective>
Fix a multi-tenant data leak: migrate the 11 remaining page/route data-loaders from the
legacy `getCachedCompany(claims.sub)` resolver to `getActiveCompany()` so they respect the
`active_company_id` cookie instead of resolving by `user_id`.

Purpose: Phase 79-04 migrated the app layout to `getActiveCompany()` but deliberately left
remaining callers on the legacy `getCachedCompany(userId)` resolver (STATE.md:457 — "a
follow-up v4.0 phase (TBD) will migrate remaining callers"). That resolver does
`SELECT ... FROM companies WHERE user_id = userId` via service role, ignoring the
active-company cookie. For a user who owns 2+ companies, these loaders load the WRONG
company's data while the switcher UI shows a different active company — a cross-tenant leak.

`getActiveCompany()` (lib/queries/active-company.ts) reads the cookie, validates membership,
and returns the SAME `AppCompany` shape ({ id, name, logo_url, owner_name, theme_preference,
industry, currency_code }) with zero arguments — making it a drop-in replacement everywhere.

Output: 11 migrated files; zero `getCachedCompany(` callers under app/; passing typecheck/build.
</objective>
