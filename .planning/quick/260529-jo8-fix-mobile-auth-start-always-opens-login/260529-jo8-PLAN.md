<objective>
Fix mobile auth routing so the Start/CTA buttons always open the login dialog even when a persisted Supabase session exists, and force Google's account picker during OAuth so re-authentication is meaningful.

Purpose: On mobile, a persisted session makes server-rendered `isAuthenticated` true, so Start/CTA short-circuit to `/dashboard`, which then bounces half-onboarded users (no `companies` row) to `/onboarding`. The user never sees the Google login dialog. Removing the short-circuits restores the dialog; forcing `prompt=select_account` prevents Google from silently looping the same account back into the broken state.

Output: Landing page always opens the auth dialog; OAuth forces account selection; no unused-var/prop lint errors.
</objective>
