# Summary: Hero landing polish — desktop 20% bigger, image reposition, gutter alignment

## What changed

Desktop-only (`lg:` ≥1024px) 20% scale-up of the hero title, subheadline, and both CTA
buttons in components/landing/hero-section.tsx. Every edit is on an `lg:`-prefixed
utility layered over the existing mobile/tablet clamps, so 0-1023px is byte-identical
to before.

- h1 (title): `lg:w-[580px] lg:text-[clamp(42px,4.5vw,56px)]` → `lg:w-[696px] lg:text-[clamp(50px,5.4vw,67px)]`
- p (subheadline): `lg:text-[18px]` → `lg:text-[22px]`
- Start button: `lg:min-w-[184px] lg:h-[46px] lg:px-[18px] lg:text-base` → `lg:min-w-[221px] lg:h-[55px] lg:px-[22px] lg:text-[19px]`; arrow icon `lg:size-[18px]` → `lg:size-[22px]`
- See Demo button: `lg:min-w-[166px] lg:h-[46px] lg:text-base lg:px-[18px]` → `lg:min-w-[199px] lg:h-[55px] lg:text-[19px] lg:px-[22px]`

Math: ×1.2 from the original baseline. Requested initially at 30% (×1.3); after the user
reviewed the live 30% render they asked for "10 percent smaller, so it is only 20 percent
bigger" — final target read as 20% bigger than original, so all values recomputed ×1.2
from baseline (not 1.3×0.9). Several ×1.2 desktop pins land on the existing tablet-clamp
ceilings (67px title / 55px height / 221px+199px min-w / 19px font / 22px icon), so
desktop now reads as a smooth continuation of the tablet maximum.

## Environment note — stale service-worker cache (root cause of a long debugging loop)

Mid-session, edits stopped appearing in the user's browser even across dev-server
restarts and hard refreshes. Root cause: this is a **PWA with a service worker** that was
serving the last cached CSS/JS build. Clearing site data / unregistering the service
worker (DevTools → Application) resolved it — all edits then rendered. Worth remembering
for future local landing/CSS work on this app.
