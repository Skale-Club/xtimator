<objective>
Fix homepage sections being clipped/hidden by their container bounds.

Root cause (already traced by orchestrator, confirmed): `components/landing/landing-page.tsx`
wraps each of the four landing sections in a div hard-locked to `h-[100dvh]` (fixed dynamic
viewport height) plus `overflow-hidden`. Whenever a section's intrinsic content is taller than
the available dynamic viewport — short laptop heights at desktop widths (where `lg:py-24`,
`lg:gap-10`, `lg:text-2xl` cards inflate height), landscape phones, or browser chrome eating
height — the overflow is CLIPPED and unreachable. Worst on Page 3 and Page 2 (`justify-center`
clips top AND bottom) and Page 4 (footer bottom cut).

Fix: On each of the FOUR wrapper divs, replace `h-[100dvh]` with `min-h-[100dvh]` and remove the
content-clipping `overflow-hidden` from the WRAPPER. This preserves the "each section fills at
least one screen" intent while letting tall content grow and be reachable via the existing outer
scroll container.

Purpose: Make every homepage section fully reachable across viewport heights without breaking the
intended full-screen feel, the no-horizontal-scroll behavior, or the hero image clip.
Output: A single edited file (`components/landing/landing-page.tsx`).

Verification note: After execution, the ORCHESTRATOR visually verifies the result via browser
preview at multiple viewport heights (short laptop, normal desktop, landscape phone). The executor
does NOT need to open a browser — only `npm run build` + `npm run lint` must pass.
</objective>
