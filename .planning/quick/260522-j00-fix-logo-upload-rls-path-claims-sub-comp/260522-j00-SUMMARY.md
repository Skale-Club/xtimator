# Quick Task 260522-j00: Fix Logo Upload RLS Path + Surface Catch Error — Summary

## One-Liner

Replaced `claims.sub` with `company.id` in the `updateCompanySettings` logo `storagePath` so the upload satisfies the `logos` bucket RLS policy `company_logos_insert`, and stopped silently swallowing the storage error in the `catch` block.

## Problem

Uploading a logo from `/settings` always failed with the generic toast `Failed to upload logo. Please try again.` with nothing in the server logs.

Root cause: the logos bucket RLS policy (migration `20260409000001_initial_schema.sql:349-355`) requires:

```sql
(storage.foldername(name))[1] IN (
  SELECT id::text FROM companies WHERE user_id = (SELECT auth.uid())
)
```

i.e. the first folder of the object name must be a `companies.id` whose `user_id = auth.uid()`. The code in `lib/actions/settings.ts` was building the path as `${claims.sub}/logo.${ext}`. `claims.sub` is the auth user UUID (`auth.users.id`), **not** the company UUID (`companies.id`). Every authenticated upload hit an RLS violation, the bare `catch {}` swallowed the underlying StorageError, and the UI surfaced the generic toast with no breadcrumb in the server log.

## What Landed

Two-line surgical edit inside `updateCompanySettings` in `lib/actions/settings.ts`:

## Out-of-Scope Observation (Flag for Follow-Up)

The `logos` storage bucket is `public:false` (migration `20260409000001_initial_schema.sql:273`) but the code calls `storage.getPublicUrl('logos', storagePath)` on line 65 (now line 65 after the edit). For a private bucket, the resulting "public" URL is non-resolvable for unauthenticated viewers — meaning a logo set via `/settings` will not render outside an authenticated Supabase session (e.g. in shared estimate links opened by an unauthenticated client).

**Not fixed here** — out of scope for a 2-line path fix. Recommended follow-up:

- Quick task: flip `getPublicUrl` to `getSignedUrl` (Phase 66 abstraction provides this) with a long-ish TTL for shared estimate views, OR
- Phase 66 storage-abstraction signed-URL pass once logo rendering is exercised on a public surface (client-facing PDF, share link)
