<objective>
Fix the recorder-UI flash that appears when a user records audio inside the estimate-creation popup, and replace the four-step CaptureStepper progress list with a calmer three-blue-dots loading overlay during processing.

**Root cause (already traced):**

1. In `components/capture/capture-recorder.tsx` line ~534:
   ```tsx
   const isIdle = stage === 'idle'
   const showRecorderUI = isIdle || stage === 'done'
   ```
   When the user taps the mic to stop, `stopRecording()` runs synchronously and clears `isRecording`, but `setStage('saving')` only fires later inside the async `recorder.onstop` → `runPipeline(blob)` handler. In that gap React paints once with `stage === 'idle'`, so `showRecorderUI === true` and the user briefly sees "Tap to start recording" again (this matches the screenshot the user reported, 00:16 timer with the idle helper text).

   The `|| stage === 'done'` half of the OR also causes a second flash: when the pipeline finishes, `setStage('done')` runs before `onComplete()` closes the dialog, so the recorder UI re-renders momentarily.

2. The current CaptureStepper renders a four-row stepper with check / spin / pending markers. The user finds this "tiring" and asked for a simpler indicator: three pulsing blue dots inside a semi-transparent overlay (with optional small label).

**Fix:**

- Eliminate BOTH flash sources in capture-recorder.tsx with surgical edits to two lines + one inserted setState (no logic changes to runPipeline, polling, or the stage state machine itself).
- Add a new tiny component `components/capture/capture-processing-overlay.tsx` (the three-dots overlay) and use it for `variant === 'popup'` only. Keep `<CaptureStepper />` for the legacy fullscreen route (preserves prior tests and behavior).

Purpose: Pure UX fix. No pipeline / actions / schema / API / lib changes. The recorder pipeline, the Inngest dispatch+poll logic, the language cascade, and the failure-path are all untouched.

Output: A single PR-shaped commit creating one new file and modifying one existing file.
</objective>
