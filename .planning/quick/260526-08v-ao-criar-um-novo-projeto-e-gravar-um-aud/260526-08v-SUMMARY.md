## Root-cause walkthrough

Two distinct flash sources lived in one component:

1. **Stop-tap flash.** Render sequence used to be: user tap → `stopRecording()` → `setIsRecording(false)` → React paints with `stage='idle'` (so `showRecorderUI = isIdle || stage === 'done'` is true) → `recorder.onstop` fires async → `runPipeline()` → `setStage('saving')` → React paints again. The middle paint briefly showed the idle helper text "Tap to start recording" with the timer at 00:0X — matching the screenshot the user reported. After the fix, `setStage('saving')` runs synchronously in the same event handler as `setIsRecording(false)`, so React batches both updates into a single paint and skips the interim frame.

2. **Done flash.** Previously `showRecorderUI === true` when `stage === 'done'`, so React would paint the recorder UI for one frame before `onComplete()` closed the dialog. After the fix, `stage === 'done'` falls into the processing branch (overlay still shown), so the recorder UI never re-renders. The text-only and photos-only popup paths in `handleGenerate` already set `stage` synchronously before any `await`, so they never had the audio race — but they also benefit from the done-flash fix and now see the calmer overlay.
