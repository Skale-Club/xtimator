# Quick Task 260610-fq2: Liberar canal de WhatsApp para o plano free

## Goal

Allow companies on the `free` tier to use the WhatsApp channel (send + receive),
removing the "WhatsApp channel is not available on your current plan" gate.

## Background

WhatsApp access is gated by a single entitlement flag, `whatsappEnabled`, defined
per tier in `lib/entitlements.ts`. Three call sites consult it via
`getEntitlements(tier).whatsappEnabled`:

1. `lib/whatsapp/handler.ts` — inbound message processor (rejects free tier with
   the upgrade message before creating any draft).
2. `app/api/estimates/[id]/send-whatsapp/route.ts` — outbound send route (403).
3. `app/(app)/projects/[id]/page.tsx` — gates the WhatsApp send button in the UI.

All three read the same flag, so flipping it once for the `free` tier unblocks
every path. No other tier-based WhatsApp gate exists (the Settings → Integrations
connect flow is not tier-gated).

## Tasks

### Task 1: Enable WhatsApp for free tier

- **files:** `lib/entitlements.ts`
- **action:** In the `free` tier object, change `whatsappEnabled: false` to
  `whatsappEnabled: true`.
- **verify:** `getEntitlements('free').whatsappEnabled === true`; grep confirms no
  other hardcoded free-tier WhatsApp block remains.
- **done:** Free-tier companies pass all three `whatsappEnabled` gates.

## must_haves

- **truths:** Free tier returns `whatsappEnabled: true` from `getEntitlements`.
- **artifacts:** `lib/entitlements.ts` updated.
- **key_links:** `lib/whatsapp/handler.ts:345`, `app/api/estimates/[id]/send-whatsapp/route.ts:87`, `app/(app)/projects/[id]/page.tsx:115`.

## Notes / Caveats

- Sending WhatsApp still requires the company to connect & verify a number in
  Settings → Integrations (`company_whatsapp.status === 'active'`) — that gate is
  unchanged and independent of plan.
- Operational cost note: Meta charges for WhatsApp conversations; enabling free
  tier removes the monetization gate on a paid-cost channel. This is the explicit
  intent of the task.
