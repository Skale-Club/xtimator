<objective>
Treat OpenRouter's spurious `401 {"message":"User not found","code":401}` transcription response as a transient error inside `transcribeAudioOR` (lib/ai/openrouter-client.ts), routing it into the existing in-process retry + OpenAI direct fallback path instead of throwing immediately.

Purpose: The Inngest transcribe-audio job intermittently fails with `OpenRouter transcription failed (401): {"error":{"message":"User not found.","code":401}}` then succeeds on Inngest's slow outer retry. This 401 is a known spurious error on OpenRouter's auth/credit-lookup side (the same valid key works on retry). The current 4xx branch throws all 4xx immediately, bypassing the retry + OpenAI fallback that already exist in this function, forcing reliance on Inngest's ~25-30s outer backoff and polluting logs with errors.

Output: A surgical edit to one file. No new dependencies, no new tests, no signature changes.
