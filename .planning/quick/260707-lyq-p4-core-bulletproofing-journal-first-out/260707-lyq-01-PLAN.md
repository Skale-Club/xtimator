<interfaces>
Journal outcome rules (validated against production data 2026-07-07):
- completed: a generate_estimate/succeeded event exists AND its estimate_id row still exists in
  estimates (is_current=true). (Vague path: succeeded event's estimate_id was deleted → NOT completed.)
- needs_details: generate_estimate/succeeded event exists AND its estimate_id is null OR the row
  no longer exists. (Optionally corroborate projects.status='awaiting_details' — fresh by
  construction since we only check after this attempt's terminal event.)
- failed: any event with status='failed' AND error_code NOT IN ('client_reported') →
  { step, reason: error_message }. (watchdog_timeout counts as failed.)
- pending: otherwise → include lastStep/lastStatus so the client can render stage progression.
Precedence: completed/needs_details (terminal success shapes) are evaluated BEFORE failed —
an attempt that eventually succeeded may carry stale failed rows (e.g. the 18:40 false
client-report); a genuine terminal success wins.
</interfaces>
