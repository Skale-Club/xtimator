# Quick Task 260801-hh4 — resolveClientIp() shared helper

## Why

`app/api/estimates/[id]/sign/route.ts` (lines ~120-141) resolves the client IP
correctly: last `x-forwarded-for` hop + `isIP()` validation, `x-real-ip` dropped
entirely. That logic landed with the digital-signature hardening merge.

`lib/admin/audit-log.ts:67` did NOT get the same treatment — it still does
`h.get('x-forwarded-for')?.split(',')[0]?.trim()`, i.e. the FIRST entry, which is
fully attacker-supplied. Every admin action's audit row can therefore record an
IP the caller chose.

Two problems: an admin audit log with forgeable IPs, and the same security
decision expressed twice (once correctly, once not).

## Deployment context (read before changing behavior)

The app sits behind exactly ONE trusted edge proxy (Traefik/Coolify), which
APPENDS the real client IP as the last `x-forwarded-for` entry. Verified for this
deployment: `xtimator.com` resolves to `188.245.112.3` (Hetzner) — there is no
CDN/Cloudflare hop in front that would append its own edge IP after Traefik's.
If a CDN is ever put in front, this helper's "last hop" rule must be revisited.

## Tasks

### Task 1 — create the helper + its tests

**files:** `lib/http/client-ip.ts` (new), `tests/unit/http/client-ip.test.ts` (new)

**action:**

Create `lib/http/client-ip.ts` exporting:

```ts
export function resolveClientIp(headers: Headers): string | null
```

Behavior (must match the sign route's current inline logic EXACTLY — that
behavior is already pinned by `tests/unit/api/sign-route-contract.test.ts`):

1. Read `x-forwarded-for`. If absent/null → return `null`.
2. Split on `,`, trim each part, drop empty parts, take the LAST remaining part.
   If nothing remains → return `null`.
3. Validate with `isIP()` from `node:net`. If it returns `0` → return `null`.
4. Otherwise return that part.

`x-real-ip` must never be read. Do not add a fallback to it, and do not add a
`request.ip` / socket fallback.

Carry the rationale into the module doc comment (single trusted appending proxy;
earlier XFF entries are attacker-supplied; `x-real-ip` is equally forgeable
unless the edge strips it and nothing in this repo proves it does; `isIP()`
prevents garbage reaching Postgres `inet` casts). Keep it proportionate — this
repo's comment density is high, so a real explanatory header is in keeping, but
do not simply copy the whole 20-line block verbatim.

Create `tests/unit/http/client-ip.test.ts` covering at minimum:
- single-entry XFF → that IP
- multi-entry XFF → the LAST entry, not the first
- `x-real-ip` present and XFF absent → `null`
- `x-real-ip` present and XFF present → the XFF last entry (x-real-ip ignored)
- garbage / non-IP value → `null`
- IPv6 literal → returned
- header absent → `null`
- whitespace-heavy and trailing-comma values → correct last entry
- empty string header → `null`

**verify:** `npx vitest run tests/unit/http/client-ip.test.ts`

**done:** helper exists, all new tests pass.
