<objective>
Fix the runtime error "there is no unique or exclusion constraint matching the ON CONFLICT specification" that breaks the entire WhatsApp connect/verification flow.

Purpose: `lib/actions/whatsapp-settings.ts` upserts on `{ onConflict: 'company_id' }` (lines 80 and ~205), but the `company_whatsapp` table only has UNIQUE constraints on `id` (PK) and `phone_number`. Postgres rejects `ON CONFLICT (company_id)` because no matching unique index exists. The design intent is one WhatsApp config per company, so a UNIQUE constraint on `company_id` is correct.

Context: The `company_whatsapp` table is currently EMPTY (0 rows, verified against live DB), so adding the constraint is safe — there is no duplicate-row risk and no backfill/dedup needed.
