The ONLY function changing in lib/platform-config.ts is getIntegrationKey. Its current env
fallback block (the `if (!data) { ... }` branch) reads:

```typescript
if (!data) {
  // Fallback to env var for local dev (D-16). Warn so the fallback path is visible.
  const envKey = process.env[`${provider.toUpperCase()}_API_KEY`]
  if (envKey) {
    console.warn(
      `[platform-config] Falling back to env var ${provider.toUpperCase()}_API_KEY for provider ${provider}. Configure via /admin/integrations to remove this warning.`
    )
    integrationCache.set(provider, { value: envKey, fetchedAt: now })
    return envKey
  }
  return null
}
```

Two consumers call getIntegrationKey('stripe') and MUST keep working unchanged:
- lib/billing/stripe-client.ts (getStripeClient → const key = await getIntegrationKey('stripe'))
- lib/billing/connect-oauth.ts (const secretKey = await getIntegrationKey('stripe'))

The existing test (tests/unit/platform-config.test.ts) mocks @/lib/supabase/service and asserts,
for the anthropic case, that console.warn is called exactly once and the message
`.toContain('Falling back')`. The new code MUST keep emitting a single warn whose message starts
with the same "[platform-config] Falling back to env var " prefix — only the var NAME inside it
changes to the actual one used. The test's afterEach deletes ANTHROPIC/OPENAI/RESEND_API_KEY; the
new stripe tests must clean up STRIPE_SECRET_KEY and STRIPE_API_KEY themselves.

Reconciled canonical names (DO NOT rename these in code — they are already correct):
- Secret key (env fallback): STRIPE_SECRET_KEY (preferred), STRIPE_API_KEY (back-compat)
- Price IDs: STRIPE_PRICE_PRO, STRIPE_PRICE_BUSINESS   (read in create-checkout-session/route.ts)
