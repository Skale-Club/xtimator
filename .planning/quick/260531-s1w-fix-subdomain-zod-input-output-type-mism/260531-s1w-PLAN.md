# Quick Task 260531-s1w: Fix subdomain zod input/output type mismatch

## Objective

Resolve the TypeScript error that breaks `next build` (and therefore all
production image builds in CI -> GHCR). The error stems from the `subdomain`
field in `companySchema` using `.optional().default('')`, which makes the zod
**input** type (`subdomain?: string`) differ from the **output** type
(`subdomain: string`). `useForm<CompanyValues>` is typed on the output of
`z.infer`, so the `zodResolver` (which validates against the input) no longer
matches, producing a resolver type error plus cascading `companyName`/subdomain
property errors in the three affected files.

## Approach

Align the input/output type by dropping `.optional().default('')` from the
`subdomain` field in `companySchema` (keep the same regex + message). Then add
the now-required `subdomain: ''` key to the two `OnboardingValues` object
literals that previously relied on the schema default.

`lib/schemas/onboarding.ts` is intentionally left untouched.

## Exact Edits

1. **components/landing/auth-dialog.tsx** — in `companySchema`, change
   `subdomain` from
   `z.string().regex(/^[a-z0-9-]*$/, '...').optional().default('')`
   to `z.string().regex(/^[a-z0-9-]*$/, '...')` (drop `.optional().default('')`
   only). Leave `defaultValues` and `values.subdomain ?? ''` untouched.
2. **components/onboarding/onboarding-survey.tsx** — add `subdomain: '',` to the
   `INITIAL: OnboardingValues` object (right after `companyName: ''`).
3. **tests/unit/components/onboarding-survey.test.tsx** — add `subdomain: '',`
   to the fixture `INITIAL: OnboardingValues` object (~line 8).

Do NOT modify `lib/schemas/onboarding.ts`.

## Verification

  must be gone (note, do not fix, any unrelated pre-existing errors).
- `npx vitest run tests/unit/components/onboarding-survey.test.tsx` — green.
