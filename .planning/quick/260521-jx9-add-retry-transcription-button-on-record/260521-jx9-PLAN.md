<objective>
Add a "Retry transcription" icon button to each `RecordingItem` so a user can re-run Whisper transcription on any saved recording that has an audio file. Re-uses the existing Inngest dispatch + poll pattern already proven in `audio-recorder.tsx` — no new server actions, no new API routes.

Purpose: When a transcription fails mid-flight (Whisper transient error, network blip, etc.), the recording row currently has no recovery affordance — the user is forced to delete and re-record. This adds a one-click retry that surfaces the same "Transcribing..." state on the row's TranscriptEditor and, on success, repaints the transcript in place.

Output: Updated `recording-item.tsx`, `recording-list.tsx`, and `audio-tab.tsx`. No DB, schema, server action, or API route changes.
</objective>

Existing reference implementation in components/workspace/audio/audio-recorder.tsx (lines 265-288):
```typescript
const transcribeResult = await transcribeRecording(result.data.id)
if ('error' in transcribeResult) {
  setIsTranscribing(false)
  onTranscribing?.(null)
  toast.error(t('Transcription failed. You can retry from the recording.'))
} else {
  toast.info(t('Transcription queued...'))
  try {
    const controller = new AbortController()
    await pollJob(transcribeResult.data.jobId, controller.signal)
    toast.success(t('Recording transcribed successfully!'))
  } catch (err) {
    if ((err as Error).name !== 'AbortError') {
      toast.error(t('Transcription failed. You can retry from the recording.'))
    }
  } finally {
    setIsTranscribing(false)
    onTranscribing?.(null)
  }
}
```
