# Hero title → two rows + title/text full width across all breakpoints

## User intent (as clarified mid-task)

- Title on **exactly two rows** ("Professional estimates" / "in seconds.").
- **NO font shrinking** — keep current sizes (user reversed the shrink option
  explicitly: "no shrinking", "jus make it two rows").
- Title **and** subheadline text boxes must be **full width** at every mobile
  phone and tablet/iPad breakpoint. Desktop (lg) unchanged.

## Root cause of the current 3-row title

The 3 rows are produced by two *forced* `<br>` elements in the H1, not natural
wrapping:
- `<br className="hidden sm:block lg:hidden" />` between word0 and word1 →
  splits "Professional" | "estimates" in the 640–1023 range.
- `<br className="hidden sm:block" />` after word1 → puts "in seconds." on its
  own row.

## Changes (no font size changes anywhere)

### components/landing/hero-section.tsx
1. H1: **remove** the forced break between word0/word1; make the break after
   word1 **unconditional** (`<br />`) so the 2-row split holds on phones too.
   Result: row1 = word0+word1, row2 = rest, at every breakpoint. Desktop lg is
   byte-identical in effect (inner break was already `lg:hidden`, after-word1
   break was already shown at lg).
2. Subheadline `<p>`: `sm:max-w-2xl` → `lg:max-w-2xl` so the paragraph is
   full-width below lg (phone + tablet) and keeps its desktop cap.

### app/globals.css — 3 real-tablet (`pointer: coarse`) blocks
3. `.hero-h1 { … width: auto !important }` → `width: 100% !important` (×3) so
   the title box is genuinely full width on real iPads (was shrink-wrapped).
4. `.hero-left p { … }` → add `width: 100%` (×3) for explicit full-width text.
