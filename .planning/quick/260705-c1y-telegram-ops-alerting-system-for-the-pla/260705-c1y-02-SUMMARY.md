# Phase quick-260705-c1y Plan 02: notifyOps fan-out + reportSilentFallback refactor Summary

Never-throw `notifyOps` ops-alert choke point (Redis SETNX dedupe → Sentry `captureMessage` → Telegram `sendTelegramMessage`), plus the first wired source: the AI silent-fallback signal now routes through it instead of calling Sentry directly.

## What Was Built

**Task 1 — `lib/observability/ops-alert.ts` (`notifyOps` + `formatOpsMessage`)**
- `notifyOps({ kind, title, message, severity?, dedupeKey?, suppressWindowSec? })` fans a system-health alert out to BOTH Sentry (`captureMessage`, level = `severity ?? 'warning'`, tag `ops_alert: kind`) AND Telegram (`sendTelegramMessage(formatOpsMessage(alert))`).
- **Dedupe (fail-open):** with a `dedupeKey` and Redis available, `redis.set('ops:<key>', ts, { nx: true, ex: window })`; a `null` return (key exists) suppresses the send; `'OK'` proceeds. Redis absent (`getRedis()→null`) OR a throwing `redis.set` → fail open (still send). Default window 900s.
- **Never-throw:** outer belt-and-suspenders try/catch, plus an independent swallow-try/catch around Redis, Sentry, and the Telegram send — a throwing/dormant Telegram, a throwing Sentry, or a Redis hiccup can never throw out of `notifyOps` and never blocks the other channels.
- `formatOpsMessage` renders a severity emoji (🔴 error / ⚠️ warning default) + `<b>title</b>` + message, minimally HTML-escaping `& < >` so error strings can't break Telegram's `parse_mode: 'HTML'`.
- Built TDD (RED test committed first, then GREEN implementation). 12 tests.

**Task 2 — `lib/ai/with-fallback.ts` `reportSilentFallback` refactor**
- Replaced the direct `Sentry.captureMessage` with `void notifyOps({ kind: 'ai_fallback', title: "AI primary down for '<op>' — serving fallback", message: <primaryError>, severity, dedupeKey, suppressWindowSec: 900 })`.
- Kept the `billingOrAuth` regex (`/402|insufficient credits|401|user not found|not configured/i`) → `severity: 'error'` and a `':billing'` dedupeKey suffix; otherwise `severity: 'warning'` and dedupeKey `ai_fallback:<op>`.
- `reportSilentFallback` stays a synchronous `void` function, fired-and-forgotten from the successful-fallback branch only, wrapped in its own try/catch.
- Removed the now-unused `import * as Sentry from '@sentry/nextjs'` (verified via grep it was only used by `reportSilentFallback`). tsc confirms no dangling import.
- `callWithFallback` control flow and return shape are **unchanged**.
