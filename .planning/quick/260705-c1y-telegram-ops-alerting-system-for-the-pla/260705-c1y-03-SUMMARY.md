## Decisions Made
- **Fire notifyOps before early-returns/500s:** In transcribe-audio the alert is placed before `if (!companyId) return`; in both cron routes it's placed before each `NextResponse.json(..., { status: 500 })` — ensuring the ops alert is never skipped by a downstream early exit.
- **Suppress windows:** 600s for AI jobs (retry-exhaustion is bursty), 3600s for crons (low-frequency scheduled, one alert/hour is enough). Kept consistent between the two cron routes.
- **Test scope:** Only the generate-estimate onFailure path is unit-tested; the transcribe/analyze wirings are identical in shape and covered by tsc + the shared notifyOps contract (Plan 02 owns notifyOps internals). Extending the existing test file was practical — the standalone-file fallback was not needed.
