**The genuine gap:** tests/unit/billing/billing-config.test.ts maintains a hand-curated ALLOWLIST of every file permitted to reference the getBillingConfig symbol (a "SYMBOL-scoped" static contract test, extended once per phase across v4.7 through v4.15 as each new legitimate consumer was added -- e.g. Phase 152's app/admin/companies/[id]/page.tsx, Phase 153's lib/billing/auto-topup.ts). **Phase 158 added a new, intended, legitimate consumer -- app/admin/billing/page.tsx calls getBillingConfig() directly (confirmed: line 16, destructured into markup/creditUnitUsd, used exactly as Phase 158's own CONTEXT.md specified) -- but never added this file to the allowlist.** This is not a functional bug (the admin Billing page works correctly and the reuse is exactly as designed -- Phase 158's CONTEXT.md explicitly names getBillingConfig as one of the "already-built credit-model functions to REUSE"), but it is a real, deterministic test failure that will fail CI. It escaped detection during Phase 158's own goal-verification because: (a) Phase 158's declared file scope was only app/admin/billing/page.tsx and billing-table.tsx, so its own targeted tsc grep and scoped vitest runs never touched tests/unit/billing/billing-config.test.ts, and (b) this test lives in a directory Phase 158's own verifier had no reason to check, since it is a cross-cutting contract test owned conceptually by Phase 111/112, not Phase 158.

**Fix required (small, mechanical, non-functional):** add app/admin/billing/page.tsx to the ALLOWLIST in tests/unit/billing/billing-config.test.ts (mirroring the existing pattern for e.g. ADMIN_COMPANY_PAGE_PATH), with a comment documenting Phase 158 as the reason, consistent with every prior entry's documentation style. This is the one open item blocking a clean "passed" status for this milestone.

No other similar "SYMBOL-scoped allowlist" contract test was found to have a matching gap -- tests/unit/settings/tenant-whatsapp-surface.test.ts (the only other such test in the repo) passes cleanly (5/5).
