## Milestone Summary

**Key Decisions:**

- User-facing rename only ("Inbox") — internal data layer (`lib/queries/admin-whatsapp.ts`, `lib/actions/admin-whatsapp*.ts`) and DB tables (`whatsapp_*`) keep WhatsApp naming, since the data is channel-specific and "Inbox" is a forward-looking, potentially multi-channel container (Rationale: contains blast radius; avoids a data-layer rewrite for a UI-only consolidation)
- Inbox = operations, Integrations = credentials — Accounts + Templates folded into an Inbox Settings sub-page; raw Meta credentials stay in `/admin/integrations/whatsapp` (Rationale: keeps secrets colocated with other integration credentials like Stripe/Twilio)
- Two-pane master-detail (not three-pane, not a modal) — mirrors the Xphere inbox's list+thread layout but omits the contact-info panel and reply composer (Rationale: read-only scope; contact-info panel deferred to INBOXX-02)
- Sequenced route consolidation (154) before the visual refactor (155) — the structural/rename layer had to be green before rewriting the viewer's UI, minimizing risk of compounding changes

**Issues Resolved:**

- STATE.md's frontmatter `milestone`/`milestone_name` fields intermittently reverted to a stale `v3.1.1` value after `gsd-tools.cjs state`/`roadmap` commands throughout this milestone (a known recurring tool bug) — manually re-asserted after every occurrence, each time confirmed correct before the next step proceeded
- A stale static-contract e2e assertion (`loadAdminConversationThread(row.id, row.company_id)`) that would have broken silently under the Phase 155 refactor was identified during Phase 155 research and fixed in 155-02, rather than surfacing as a post-ship regression

**Issues Deferred:**

- INBOXX-01 (two-way replies from the Inbox), INBOXX-02 (multi-channel Inbox + contact-info panel), INBOXX-03 (realtime updates) — all explicitly out of scope for v4.16, tracked as v2 requirements
- Live-nav e2e tests (row-click URL update, direct-link SSR selection, mobile viewport collapse) require seeded `TEST_ADMIN_EMAIL`/`TEST_ADMIN_PASSWORD` credentials unavailable in this environment — written and correctly creds-gated, but not executed; manual verification pending

**Technical Debt Incurred:**

- None identified — both phases' goal verifications and the milestone integration audit found zero gaps beyond the pre-existing, unrelated issues logged in each phase's `deferred-items.md` (a JSDoc-comment regex false-positive predating the milestone, plus a handful of unrelated Windows/RLS test flakes)
