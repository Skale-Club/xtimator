## Rescoping decision

Mid-execution discovery: **Vercel Free (Hobby) plan is not viable for Xtimator.** Two hard blockers:

1. **ToS violation** — Hobby is "personal, non-commercial only". Xtimator is a paid SaaS.
2. **10s function timeout** — `/api/generate-estimate` (Claude) and `/api/transcribe` (Whisper) routinely exceed this.

The user opted to defer all hosting-dependent phases (62-65) until budget allows commercial hosting (~$20/mo Vercel Pro) OR first paying customer signal. Captured in **SEED-018: Production Hosting + Deployment** which will resurface during the next `/gsd:new-milestone`.

## Lessons Learned

- **Worktree-based parallel execution drifts schemas.** When phases were executed in worktrees (v2.0 onwards), migration SQL files got committed but `supabase db push` was not always run against the shared DB. Future phases should add a pre-merge check that runs `compare-migrations.mjs`.
- **"It works in dev" can mean "the test you ran doesn't touch the new schema."** The v3.0 monetization features looked working because they were tested in isolated worktrees — but the columns/tables never made it to the shared dev DB.
- **Free-tier hosting is not always free.** Vercel Hobby's commercial-use restriction is the kind of constraint easy to miss until the audit forces it. Better to surface it in the planning phase next time.
- **Single-environment dev/prod is a pragmatic choice for solo pre-revenue.** Industry default is dev/prod separation, but it carries real costs (two projects, sync overhead, doubled migration work). Defer separation until the first paying customer.
