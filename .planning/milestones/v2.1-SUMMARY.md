# v2.1 WhatsApp Launch-Readiness — Milestone Summary

**Shipped:** 2026-05-11

## Why this milestone existed

v2.0 shipped a functional MVP of the WhatsApp channel, but a post-milestone audit revealed several launch-blocking gaps for real production use. The user's directive: "I want Xtimator to be born with WhatsApp working."

This milestone closed those gaps in one focused push.

## What was shipped

### Phase 46 — Typed Error Handling Foundation (SEED-014)
`lib/errors/` with `XtimatorError` class, `asResponse()` HTTP wrapper, `handleWhatsAppError()` adapter that translates errors into contextual WhatsApp messages, and assertion helpers (`throwIfNotFound`, etc.). Replaces ad-hoc try/catch + "Something went wrong" responses with structured codes carrying status, user message, and metadata.

### Phase 47 — Redis + Rate Limiting Infrastructure (SEED-012)
Upstash Redis client (`lib/redis.ts`) + sliding-window `rateLimit()` applied to the four most-expensive endpoints (generate-estimate, translate, analyze-photos, webhooks/whatsapp). Fails open when Redis is unavailable so production never breaks from a Redis hiccup. Foundation for future tier enforcement.

### Phase 48 — WhatsApp Multi-Message Debounce (SEED-010)
Per-phone Redis buffer that aggregates messages within a 5-second silence window. Fixes the fundamental UX gap where a contractor sending audio + photos + clarifying text used to get an estimate from only the first message. Now: all messages collapse into ONE estimate. "Latest claims it" pattern ensures only the worker for the final message processes the batch.

### Phase 49 — WhatsApp Typing + Read Receipts (SEED-011)
`markMessageAsRead()` + `sendTypingIndicator()` called immediately on inbound. Blue checks appear <1s, "typing..." shows during the 20-40s AI work. Re-sent before the 25s timeout to maintain continuous feedback. Fire-and-forget — failures swallowed. Zero cost (metadata only, doesn't count against Meta quota).

### Phase 50 — WhatsApp OTP Number Verification (SEED-015 Gap 2)
Two-step verification: credentials submitted → status='pending' → 6-digit code sent via WhatsApp → user enters code → status='active'. 10-minute TTL, max 3 attempts, row wiped on exhaustion. Closes the security gap where anyone with publicly-visible `phoneNumberId`+`wabaId` could claim a number. Existing connected numbers were not migrated (preserves access).

### Phase 51 — WhatsApp Pre-Send Edit Commands (SEED-015 Gap 1, MVP subset)
Structured parser for `edit total/timeline/payment/summary`, `client "Name" phone`, and `regenerate` commands. Owner no longer has to cancel and re-record everything when they spot a mistake. After every edit, the updated summary is re-sent. Section/item-level commands (`edit item 2.3 price`) deferred because they require numbered references in the confirmation message.

### Phase 52 — Per-Estimate Language Selection (SEED-016, backend complete)
End-to-end backend infrastructure for generating estimates in EN/PT-BR/ES independently of the user's app language. English-first cascade resolver: explicit override → client preference → company default → user app language (if non-EN) → 'en'. AI prompt is language-aware with locale-specific formatting instructions. WhatsApp formatter is fully localized (greeting, "Subtotal", "Total", etc.) with locale-aware currency. Auto-learns the client's preferred language after first successful send. Web UI dropdown + EstimatePDF i18n deferred.
