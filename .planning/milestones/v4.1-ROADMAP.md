# v4.1 MCP Server — Milestone Archive

**Status:** ✅ Shipped 2026-05-26
**Scope:** OAuth 2.0 authorization server + MCP Streamable HTTP transport + 6 tools (4 read + 2 write) + Claude Code/Claude.ai/ChatGPT connect UX.

---

## Goal

Implement the seed SEED-030: ship a working MCP server inside the existing Next.js app so a Xtimator user can connect Claude / Claude Code / Claude.ai / ChatGPT as a custom connector and invoke `list_estimates`, `get_estimate`, `list_clients`, `list_projects`, `create_estimate`, `check_job_status` from inside the chat — with OAuth 2.0 auth, PKCE, refresh-token rotation, and Claude.ai's auto-grouped permission UI ("Read-only tools (4)" + "Write tools (2)").

## Locked decisions

- **Auth: OAuth 2.0** (Claude is the OAuth client, Xtimator is authorization server + resource server). RFC 8414 metadata + RFC 9728 protected-resource metadata + RFC 7591 dynamic client registration + PKCE S256.
- **Hosting: Next.js route in same deploy** — `app/oauth/*` + `app/.well-known/*` + `app/api/mcp/route.ts`.
- **Tool grouping via annotations** — `readOnlyHint: true` / `destructiveHint: false` / `idempotentHint` per tool. Claude.ai auto-groups by these flags in the permissions UI.
- **Active-company scoping** — every token is bound to `(user_id, company_id)` at the consent screen. All tool queries explicit `.eq('company_id', auth.company_id)` even though OAuth already authorized that exact tuple (defense in depth).
- **Async pattern for create_estimate** — returns `{ job_id, status: 'queued' }` immediately; LLM polls `check_job_status(job_id)` until `status: 'complete'`. Job pipeline is the existing Inngest `EVENT_ESTIMATE_GENERATE`.

## Phases

### Phase 86: OAuth 2.0 server (foundation) — ✅ Shipped 2026-05-26

Created 4 tables (`oauth_clients`, `oauth_authorization_codes`, `oauth_access_tokens`, `oauth_refresh_tokens`) with deny-all RLS and sha256-hashed token storage. Shipped 5 endpoints:

- `GET /.well-known/oauth-authorization-server` — RFC 8414 metadata
- `GET /.well-known/oauth-protected-resource` — RFC 9728 metadata
- `POST /oauth/register` — RFC 7591 dynamic client registration (public clients, no secret)
- `GET /oauth/authorize` — consent UI server component + POST action that issues authorization code (10 min TTL, PKCE-bound, scope-bound, redirect-uri-bound)
- `POST /oauth/token` — both `authorization_code` and `refresh_token` grants; rotates refresh_token on each refresh; access_token TTL = 1h

Helpers in `lib/oauth/{types,pkce,tokens,codes,clients,issuer}.ts`. Token storage is hash-only (sha256) — DB leak doesn't compromise active sessions. Tests: 34/34 green.

**Migration:** `supabase/migrations/20260526000003_phase86_oauth_tables.sql` applied to prod.

**Commits:** 6.

### Phase 87: MCP route + Streamable HTTP transport — ✅ Shipped 2026-05-26

`app/api/mcp/route.ts` with POST (JSON-RPC handler) + GET (405) + OPTIONS (CORS preflight allowing `https://claude.ai`, `https://*.claude.ai`, `null` for local). Bearer auth via `verifyMcpRequest` calling `resolveAccessToken` from Phase 86. WWW-Authenticate header on 401 lets clients re-discover the auth server.

`lib/mcp/{auth,scope,server}.ts` primitives. Uses `WebStandardStreamableHTTPServerTransport` from `@modelcontextprotocol/sdk@1.29` (Fetch Request/Response — matches Next.js App Router native primitives).

`createMcpServer(authContext)` factory exposes the server instance Phase 88+ plug tools into.

Tests: 21/21 green.

**Commits:** 5.

### Phase 88: Read-only MCP tools — ✅ Shipped 2026-05-26

4 tools registered with `readOnlyHint: true, destructiveHint: false, idempotentHint: true`:

- `list_estimates(status?, project_id?, client_id?, limit?, cursor?)` — paginated, ORDER BY created_at DESC
- `get_estimate(id)` — full estimate with sections + items (double-checks tenant)
- `list_clients(search?, limit?, cursor?)` — case-insensitive substring search on name/email
- `list_projects(client_id?, status?, limit?, cursor?)` — paginated

Cursor pagination helpers in `lib/mcp/pagination.ts` (opaque base64-encoded `(created_at, id)` tuple, validates shape on decode). Typed errors via `lib/mcp/errors.ts` with `data.kind` discriminator.

Scope-gate via `requireScope(auth, 'mcp:read')` — missing scope throws `insufficient_scope`.

Tests: 45/45 green.

**Commits:** 4.

### Phase 89: Write MCP tools + async pattern — ✅ Shipped 2026-05-26

Refactored handler registration into shared `lib/mcp/tools/registry.ts` — `buildAllTools(auth)` concatenates read + write definitions; `registerAllTools(server, auth)` registers `tools/list` and `tools/call` exactly once per Server instance.

2 new tools:

- `create_estimate(project_id, prompt, language?)` — `readOnlyHint: false, destructiveHint: false, idempotentHint: false`. Scope-gates `mcp:write`. Verifies project belongs to active company. Sends `EVENT_ESTIMATE_GENERATE` to Inngest. Returns `{ job_id: <inngest_event_id>, status: 'queued' }`.
- `check_job_status(job_id)` — `readOnlyHint: true, destructiveHint: false, idempotentHint: true`. Scope-gates `mcp:read`. Reads `/v1/events/{id}/runs` (same path `/api/jobs/[jobId]` uses). Maps statuses to `queued | running | complete | failed`. On complete, includes `result.estimate_id`.

Read tools refactored from `registerReadTools` → `buildReadTools(auth): ToolDefinition[]`. Phase 88's 45 tests still pass after refactor.

Tests: 37 new + 67 pre-existing MCP = 104/104 green.

## Key accomplishments

1. **OAuth 2.0 server live in production** — RFC 8414, 9728, 7591 compliant. PKCE S256 mandatory. Token storage sha256-hashed. Refresh-token rotation. Phase 86 alone is ~600 LOC of security-sensitive code shipped with 34 unit tests covering the cryptographic invariants.
2. **`/api/mcp` Streamable HTTP endpoint live** — Bearer-auth gated, CORS configured for Claude.ai's origins, WWW-Authenticate enables automatic re-discovery on token expiry.
3. **6 tools across two permission tiers** — annotations drive Claude.ai's auto-grouped permission UI ("Read-only (4) — Always allow" / "Write (2) — Ask each time") with zero custom UI code on the Xtimator side.
4. **Async pattern end-to-end** — `create_estimate` returns immediately with `job_id`; `check_job_status` polls Inngest; on complete, LLM gets `estimate_id` to invoke `get_estimate` and read the generated output. This is what makes "long-running AI generation inside a chat connector" work without timeouts.
5. **Self-service connect UX** — `/settings/integrations/mcp` page gives the user a copy-pastable `claude mcp add ...` command + Claude.ai dialog steps + ChatGPT instructions. Active-company surfaced so the user sees which tenant they're binding to before authorizing.
