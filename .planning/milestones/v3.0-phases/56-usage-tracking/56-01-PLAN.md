```sql
CREATE UNIQUE INDEX usage_events_idempotency
```

Use a partial index (`WHERE idempotency_key IS NOT NULL`) so rows without an idempotency key (NULL) never collide with each other — multiple NULLs must be allowed. This is the correct Postgres pattern for nullable unique fields.

```typescript
import type { SupabaseClient } from '@supabase/supabase-js'
import { getEntitlements } from '@/lib/entitlements'

export type QuotaType = 'estimate' | 'photo_batch' | 'audio_minutes'
export type EventType = 'estimate_generated' | 'photo_analyzed' | 'audio_transcribed'

// Maps quota type to event_type string in usage_events
const QUOTA_TO_EVENT: Record<QuotaType, EventType> = {
  estimate: 'estimate_generated',
  photo_batch: 'photo_analyzed',
  audio_minutes: 'audio_transcribed',
}

// Maps quota type to the entitlements fields it checks
// { monthly: keyof Entitlements, daily: keyof Entitlements }
// estimate → maxEstimatesPerMonth / maxEstimatesPerDay
// photo_batch → maxPhotosPerEstimate (no monthly; check per-estimate limit — see note)
// audio_minutes → maxAudioMinutesPerEstimate (no monthly; per-estimate)
// NOTE: For Phase 56, only 'estimate' has monthly+daily limits.
// photo_batch and audio_minutes are per-estimate (not per-month) — checkQuota for those
// compares `units` arg against the per-estimate limit (pass units as parameter if needed).
// For simplicity in Phase 56: implement the monthly+daily pattern for 'estimate'; for
// 'photo_batch' and 'audio_minutes', return { allowed: true, remaining: null } (not enforced
// per-month — enforcement handled by Phase 57 via per-call unit check).

export async function checkQuota(
  supabase: SupabaseClient,
  companyId: string,
  quotaType: QuotaType
): Promise<{ allowed: boolean; remaining: number | null }>
```

**checkQuota implementation logic:**

1. Query companies table directly by `id = companyId` to get `tier` (NOT via `getCompanyTier` which takes userId — query companies directly):
   ```typescript
   const { data: company } = await supabase
     .from('companies')
     .select('tier')
     .eq('id', companyId)
     .single()
   ```

2. Call `getEntitlements(company.tier)` to get limits.

3. For `quotaType === 'estimate'`:
   - If `maxEstimatesPerMonth === null` AND `maxEstimatesPerDay === null`: return `{ allowed: true, remaining: null }`
   - Calculate start of current calendar month (UTC): `new Date(UTC year, UTC month, 1)`
   - Calculate start of current calendar day (UTC): `new Date(UTC year, UTC month, UTC day)`
   - Query `usage_events` for `company_id = companyId AND event_type = 'estimate_generated' AND created_at >= startOfMonth`
   - Count total this month. Count today (filter `created_at >= startOfDay`).
   - Check monthly limit first: if `maxEstimatesPerMonth !== null && monthCount >= maxEstimatesPerMonth`: return `{ allowed: false, remaining: 0 }`
   - Check daily limit: if `maxEstimatesPerDay !== null && dayCount >= maxEstimatesPerDay`: return `{ allowed: false, remaining: 0 }`
   - Return `{ allowed: true, remaining: maxEstimatesPerMonth !== null ? maxEstimatesPerMonth - monthCount : null }`

4. For `photo_batch` and `audio_minutes`: return `{ allowed: true, remaining: null }` (per-estimate limits enforced at call site in Phase 57)

**IMPORTANT: Use the Phase 12 pattern for ON CONFLICT DO NOTHING:**
```typescript
await supabase
  .from('usage_events')
  .upsert(
    { company_id: companyId, event_type: eventType, units, idempotency_key: idempotencyKey },
    { onConflict: 'company_id,idempotency_key', ignoreDuplicates: true }
  )
```
This is the established codebase pattern (STATE.md Phase 12: `upsert(rows, { onConflict, ignoreDuplicates: true })`). Do NOT use raw `.insert()` — supabase-js TypeScript types only support `onConflict` on `upsert()`.

If `error` is non-null after upsert, throw: `throw new Error(\`recordUsage failed: \${error.message}\`)`.
