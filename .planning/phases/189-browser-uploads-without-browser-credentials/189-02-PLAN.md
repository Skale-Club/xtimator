  <files>app/api/storage/upload-ticket/route.ts, tests/unit/storage/upload-ticket-route.test.ts</files>

  <behavior>
Gate order — each cheaper and stricter than the next, every refusal before any storage call, mirroring the Phase 187 proxy route's documented ordering:

1. **Body parse + shape.** Missing/non-JSON body, `bucket` outside `UPLOAD_TICKET_BUCKETS`, non-UUID `projectId`, missing `contentType` -> `400`. No auth work done yet.
2. **Auth.** No claims -> `401 { error: 'Not authenticated' }`. No active company -> `401`.
3. **Demo guard.** `demoGuardResponse()` -> its `403` verbatim. Must run **before** any DB read and before minting.
4. **Project ownership.** `select id from projects where id = :projectId and company_id = :companyId` under the RLS-bound client -> no row means `404` (not 403 — the response must not confirm the project exists, same reasoning as `proxy-auth.ts`'s 404-not-403).
5. **Mint.** `mintUploadTicket({ bucket, projectId, contentType, companyId, supabase, key })`. A throw -> `500 { error: 'Could not issue upload ticket' }` with the real error `console.error`'d server-side and **not** echoed to the caller.

Tests (mock `@/lib/queries/auth` / `@/lib/queries/active-company` / `@/lib/demo/guard` / `@/lib/supabase/server` / `@/lib/storage/upload-ticket`):
- unauthenticated -> 401, and `mintUploadTicket` was **not called**
- authenticated, no active company -> 401, mint not called
- demo principal -> 403 `demo_readonly`, mint not called, **and the project lookup was not performed** (assert call order, not just the status)
- `projectId` belonging to another company -> 404, mint not called
- `bucket: 'photos'` -> 400, mint not called
- `contentType: 'text/html'` -> 400 or mint-throw surfaced as 400 (pick one and assert it), mint never reaching a backend
- body `{ companyId: '<other-tenant-uuid>' }` present -> **ignored**; assert `mintUploadTicket` received the auth-derived company, not the body's
- happy path -> 200 with the exact ticket object `mintUploadTicket` returned, and `Cache-Control: private, no-store` on the response
- retry path: body carries a prior `key` -> it is passed through to `mintUploadTicket` unchanged (Plan 01 owns validating it; the route must not pre-sanitize it)
  </behavior>
