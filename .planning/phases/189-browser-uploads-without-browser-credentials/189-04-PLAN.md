<why_this_gate_and_not_a_bundle_scan>
The obvious check is "grep the built client chunks for the secret". It is the wrong check here, for three reasons: it needs a full `next build` (slow, and this repo's production build has OOM history on constrained hosts); it can only find a credential that is *currently set*, so it is green on any machine where `S3_*` is unset — which is every machine, deliberately, because CONTEXT.md keeps those vars out of `.env.local` and Coolify; and it proves nothing about the module graph, only about one build's output.

A static transitive-closure walk asks the load-bearing question instead: *can* a client entry point reach the module that touches credentials. That answer does not depend on whether a secret happens to be configured, runs in under a second, and lives in `tests/unit` where CI already runs it.
</why_this_gate_and_not_a_bundle_scan>
</context>
