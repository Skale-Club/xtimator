**`structuralEditEpoch` — the exact classification** (`use-estimate-reducer.ts`, mirroring the EXISTING `dirty()` helper pattern for `editEpoch`/SAVE-04 verbatim):

```ts
// Add to EstimateEditorState:
/** Phase 185 Plan 04 (PGMODE-03) — bumped ONLY by actions that change WHICH
 *  pagination blocks exist or their order (never by pure text edits) —
 *  read by usePaginatedPreview to trigger an IMMEDIATE repagination,
 *  bypassing the 400ms text-debounce. Documented exhaustively below; a new
 *  action type defaults to NOT bumping this (opt-in, not opt-out) — if a
 *  future action changes block presence/order, it must be added here. */
structuralEditEpoch: number

// Add alongside dirty():
function structuralDirty(state: EstimateEditorState): Pick<EstimateEditorState, 'isDirty' | 'editEpoch' | 'structuralEditEpoch'> {
  return { ...dirty(state), structuralEditEpoch: state.structuralEditEpoch + 1 }
}
```

**Exact classification (every `EstimateAction` case, exhaustive):**

| Action | Bump `structuralEditEpoch`? | Why |
|---|---|---|
| `INIT` | Set to `0` in `initState()` (both branches) | Fresh document load |
| `ADD_ITEM`, `REMOVE_ITEM`, `ADD_SECTION`, `REMOVE_SECTION`, `REORDER_ITEMS`, `REORDER_SECTIONS` | YES (`...structuralDirty(state)` replacing `...dirty(state)`) | Changes WHICH item-row/section-header blocks exist or their order |
| `UPDATE_DISCOUNT`, `UPDATE_DEPOSIT`, `UPDATE_TAX_RATE` | YES | Can flip a totals-row's PRESENCE (`discount_amount > 0` / `tax_amount > 0` / `deposit_type !== 'none'` gates in `blocksFromModel()`) — a block appearing/disappearing, not just a text measurement |
| `UPDATE_PRESENTATION_SETTINGS` | YES | Visibility toggles gate whole sections/blocks in or out |
| `APPLY_REFINEMENT` | YES | Wholesale content replacement — treat conservatively as structural |
| `APPLY_PRICE_BOOK_ITEM` | YES | A discrete, infrequent, deliberate click (not per-keystroke typing) — immediate recompute carries no thrash risk |
| `ATTACH_PHOTO`, `DETACH_PHOTO` | YES, but ONLY bump `structuralEditEpoch` directly (`state.structuralEditEpoch + 1`) — do NOT also call `dirty()`/`structuralDirty()` here, since these two cases intentionally do NOT set `isDirty`/bump `editEpoch` today (an existing, deliberate design choice this plan must not disturb) | Changes photo-row block/chunk count |
| `UPDATE_FIELD`, `UPDATE_SECTION_TITLE`, `UPDATE_ITEM` | NO (leave using plain `dirty(state)`, unchanged) | Per-keystroke-ish text/numeric edits on an EXISTING block — block presence/order unaffected |
| `MARK_SAVED` | NO | Server round-trip re-baseline; doesn't change which blocks exist beyond what was already locally true |
