<objective>
Extract the ONE shared `PageConstraints` derivation both the PDF renderer and the future web preview must use verbatim, and build a browser-safe twin of the server's fontkit measurement provider — proven byte-identical via a deep-equal parity test. This is the mirror-critical foundation every later Phase 185 plan depends on: without it, the web paginated preview could silently diverge from the PDF near page-capacity boundaries (185-RESEARCH.md's "constraints-parity finding").

Purpose: PGBRK-01/04 require the web paginated preview to consume the SAME pagination module as the PDF renderer, with the SAME constraints — not a second, independently-derived margin. This plan closes that gap at the engine level before any UI is built on top of it.
Output: `lib/estimate/pagination/page-constraints.ts` (shared constraints function), `lib/estimate/pagination/measure/line-packer.ts` (isomorphic core), `lib/estimate/pagination/measure/browser-estimator.ts` (browser-safe measurement provider), `render-estimate-pdf.ts` wired to the shared function, and a passing parity test proving the browser and server providers produce identical `PageAssignment[]`.
