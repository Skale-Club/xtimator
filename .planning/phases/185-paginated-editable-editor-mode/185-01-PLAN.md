```json
"exports": {
  "node": { "import": "./dist/module.mjs", "require": "./dist/main.cjs" },
  "import": "./dist/browser-module.mjs",
```

There is NO subpath entry (e.g. no `"./dist/browser.cjs": "..."` key) — `fontkit/dist/browser.cjs` cannot be imported as a package-relative specifier; Node throws `ERR_PACKAGE_PATH_NOT_EXPORTED`. The `"node"` condition matches ONLY a genuine Node.js resolver (plain Node, or Vitest running under Node) — any OTHER resolution target (webpack's client bundle, any web/browser-targeted bundler) does not set `"node"`, so it falls through to the plain `"import"`/`"require"` keys, i.e. the BROWSER build, automatically. Production code therefore uses the bare specifier; only this plan's OWN Node-based parity test needs to force past the `"node"` condition, via a mock resolving an absolute filesystem path (which sidesteps the exports map entirely — that restriction governs specifier resolution, not direct absolute-path file loads).
