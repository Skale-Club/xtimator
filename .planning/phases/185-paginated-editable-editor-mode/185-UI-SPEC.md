## 1. Toggle UI — two icon buttons LEFT of "Edit with AI"

### Location & mount point

`components/workspace/project-header.tsx`, inside the existing right-hand flex row:

```tsx
<div className="flex items-center gap-2 shrink-0 pt-0.5 sm:pt-0">
  {/* existing autosave status span, unchanged */}
  <ViewModeToggle mode={slot?.viewMode} onModeChange={slot?.onViewModeChange} />  {/* NEW */}
  <EditEstimateHeaderButton projectId={project.id} />  {/* existing, untouched */}
</div>
```

New component: `components/workspace/view-mode-toggle.tsx`. State comes from `VersionSlot.viewMode` / `VersionSlot.onViewModeChange` (extend the interface in `estimate-version-context.tsx` per ARCHITECTURE.md Q4 — not zustand, not URL param). Render nothing (`return null`) when `slot` is absent, matching the existing optional-chaining pattern already used for `saveStatus`.

### Structure — segmented pill, not two isolated buttons

Render the two buttons as ONE visually-grouped segmented control (not two independent `gap-2` buttons like unrelated header controls — a BLOCK-level visuals rule, see §6). Reuses the `Button` primitive's `ghost`/`icon-sm` variants already in the system:

```tsx
<TooltipProvider delayDuration={300}>
  <div
    role="group"
    aria-label="Document view mode"
    className="inline-flex items-center gap-0.5 rounded-full border border-border bg-muted/40 p-0.5"
  >
    <Tooltip>
      <TooltipTrigger asChild>
        <Button
          variant="ghost"
          size="icon-sm"
          aria-pressed={mode === 'width'}
          aria-label="Full width view"
          onClick={() => onModeChange?.('width')}
          className={cn(
            'rounded-full',
            mode === 'width'
              ? 'bg-background text-primary shadow-sm'
              : 'text-muted-foreground hover:text-foreground hover:bg-background/50',
          )}
        >
          <StretchHorizontal className="h-4 w-4" />
        </Button>
      </TooltipTrigger>
      <TooltipContent>Full width</TooltipContent>
    </Tooltip>

    <Tooltip>
      <TooltipTrigger asChild>
        <Button
          variant="ghost"
          size="icon-sm"
          aria-pressed={mode === 'page'}
          aria-label="Paginated view"
          onClick={() => onModeChange?.('page')}
          className={cn(
            'rounded-full',
            mode === 'page'
              ? 'bg-background text-primary shadow-sm'
              : 'text-muted-foreground hover:text-foreground hover:bg-background/50',
          )}
        >
          <FileStack className="h-4 w-4" />
        </Button>
      </TooltipTrigger>
      <TooltipContent>Paginated (PDF preview)</TooltipContent>
    </Tooltip>
  </div>
</TooltipProvider>
```

| Property | Value | Rationale |
|---|---|---|
| Icon — full width | `StretchHorizontal` (lucide, confirmed available) | Carries over the exact icon already used for this meaning on the retiring floating-pill toggle — zero relearning cost |
| Icon — paginated | `FileStack` (lucide, confirmed available) `[ADJUSTABLE]` | Distinct page-stack glyph, standard "PDF preview" convention; swap for owner's reference icon on arrival — isolated to one import line |
| Icon size | `h-4 w-4` (16px) | Matches the `Sparkles` icon size in the adjacent "Edit with AI" button (visual weight parity) |
| Button size | `icon-sm` (`size-9` = 36px) | Matches "Edit with AI"'s `size="sm"` height (`h-9`) so the group sits flush in the header row |
| Container | `rounded-full border border-border bg-muted/40 p-0.5` | "Track" of a segmented control — muted 30%-surface token, not a new color |
| Active state | `bg-background text-primary shadow-sm` | The active segment "pops" as a raised chip in the app's true background color against the muted track — standard segmented-control affordance. `text-primary` is one of this phase's ONLY two accent uses (see §Color) |
| Inactive state | `text-muted-foreground hover:text-foreground hover:bg-background/50` | Matches existing ghost-button hover conventions used throughout the app |
| Default on mount | `width` (full-width) — CONTEXT.md locked default | — |
| Gap between icons | `gap-0.5` (2px) inside the pill `[ADJUSTABLE]` — this is the one spacing value in this phase that is intentionally NOT on the 8-pt scale (see Spacing exceptions) | Segmented-control convention (icons nearly touching inside one track); mirrors shadcn's own `ToggleGroup` spacing |

### Tooltips, aria-labels, keyboard access

- Both buttons wrapped in a single local `TooltipProvider` (`delayDuration={300}`) — the app has **no** ancestor `TooltipProvider` (confirmed via repo-wide search), so this must be self-contained inside `ViewModeToggle`.
- `aria-label` names the MODE, not the action (`"Full width view"` / `"Paginated view"`) — `aria-pressed` communicates current state; do not phrase labels as `"Switch to…"` (that duplicates what `aria-pressed` already conveys and reads awkwardly with screen readers on the pressed one).
- Tooltip copy: `"Full width"` / `"Paginated (PDF preview)"` — short, matches the pill-button label conventions already in `estimate-floating-actions.tsx` (e.g. "Full page", "Full width").
- Keyboard: standard toggle-button-group pattern — each button is independently `Tab`-reachable (2 stops), `Enter`/`Space` activates. No roving-tabindex/arrow-key requirement (matches this codebase's existing convention — no precedent for `radiogroup`/arrow-key toggles anywhere in the app). Focus ring: inherited automatically from `Button`'s base classes (`focus-visible:shadow-[var(--focus-shadow)]`) — no new CSS needed.
- `role="group" aria-label="Document view mode"` on the wrapping pill gives assistive tech a landmark without imposing radio semantics that don't match the interaction model.

### Consolidation (PGMODE-04)

Remove the `viewMode`/`onViewModeChange` props and the "Full page"/"Full width" button block from `components/workspace/estimate/estimate-floating-actions.tsx` (lines ~22-26, ~112-131) and the `File`/`StretchHorizontal` import pair there. Retire `estimate-editor.tsx`'s CSS-`zoom` single-sheet mechanism (`pageZoom`/`pageWrapRef`/`LETTER_PAGE_HEIGHT`/`PAGE_FIT_CLEARANCE`) as a standalone feature — its **fit-to-viewport math is reused**, not deleted outright (see §4 Responsive).

## 2. Paginated canvas

### Geometry — reuse, do not re-declare

Letter page = **816 × 1056px @96dpi**. This exact pair is already hardcoded in two places (`estimate-editor.tsx` `LETTER_PAGE_HEIGHT = 1056` / `max-w-[816px]`; `estimate-document.tsx` `min-h-[1056px]`). If Phase 184's shared geometry module (`lib/estimate/document/` or `lib/estimate/pagination/`) lands first, import the constants from there. Otherwise, define ONE new shared constant (e.g. `lib/estimate/pagination/geometry.ts` exporting `PAGE_WIDTH_PX = 816`, `PAGE_HEIGHT_PX = 1056`) and repoint both existing hardcodes at it — do not add a third literal copy.

### Canvas treatment (neutral background on the dark workspace)

| Element | Value | Notes |
|---|---|---|
| Canvas wrapper | `bg-muted rounded-xl` (full, not overlay opacity) | Reuses the EXISTING `--muted` token (the system's own 30%-secondary-surface color) as a "PDF-viewer tray" — matches Chrome/Adobe/Google Docs' gray backdrop convention, introduces zero new color |
| Canvas padding | `py-8 px-4` (32px vertical / 16px horizontal, both on the 8-pt scale) | — |
| Page sheet background | `#ffffff` (forced light, `colorScheme: 'light'`) | Reuses the EXACT existing inline-style block from `estimate-document.tsx:1671-1689` (the "paper" override — `--foreground`, `--muted`, `--border`, `--glass-*` all re-pinned to light values). Do not re-derive this — import/reuse the same style object for the new paginated wrapper. |
| Page sheet corners | `rounded-none` (square) | Matches the existing `pageView` convention (real paper has no radius) — see `estimate-document.tsx:1667-1669` comment |
| Page sheet border | `1px solid rgba(255,255,255,0.14)` on the dark tray `[ADJUSTABLE]` | A light hairline reads crisply against the dark `--muted` tray; the existing `shadow-2xl` alone is a black shadow and is nearly invisible on a dark background, so the border carries the primary separation cue here (shadow is kept as a secondary depth cue, see next row) |
| Page sheet shadow | `box-shadow: 0 20px 40px -12px rgba(0,0,0,0.55)` | Elevation cue once the page is composited over the muted tray (subtler than pure `shadow-2xl`, tuned for a dark surrounding instead of a white one) |
| Page gap (between sheets) | `32px` (`space-y-8`, 8-pt scale) `[ADJUSTABLE]` | Matches Google Docs Pageless / Adobe Reader's ~24-32px inter-page gap convention |
| Page-number chrome | `"Page {n} of {m}"`, centered in the 32px gap below each sheet | `text-xs` (12px/400, `var(--font-size-xs)`/`var(--line-height-xs)`), color `text-white/70` (NOT lower — see Accessibility §5 contrast requirement), `select-none` |
| Continuation table header | Byte-identical reuse of the existing desktop item-table header row classes: `bg-muted/50 text-sm text-muted-foreground border-b border-border/50 select-none` (from `estimate-document.tsx:850`) | Only rendered when the pagination engine reports a section's rows actually span the boundary (per ARCHITECTURE.md Q2/Q3) — never a document-wide repeat |
| Page-1-only chrome | Company header + Bill To render ONCE, on page 1, never repeated | Table-stakes rule from FEATURES.md — encode as a non-repeating block in the page-break module, not a UI concern per se, but the visual result must NOT show a second letterhead on page 2+ |

### Transition when toggling modes

Because the underlying DOM tree is never re-parented (ARCHITECTURE.md Q5, strategy "b" — spacer/chrome-overlay over the SAME continuous tree), the transition is a **decoration fade**, not a content remount:

- The page-sheet decoration layer (background/shadow/border/page-number chrome) fades in/out: `transition-opacity duration-200 ease-out`.
- The inserted page-gap spacer elements animate their height from `0` to `32px` (or reverse) over the same `200ms`, so content reflows smoothly rather than jump-cutting.
- Gate the whole transition behind `@media (prefers-reduced-motion: no-preference)` — same pattern already used throughout `app/globals.css` (`.cta-glow`, `.hero-mesh`, `button-shimmer-sweep`, etc.). Under `reduce`, snap instantly (`transition: none`).
- **Do not** use `framer-motion` for this (it IS a dependency in this repo, but a CSS-only opacity/height transition is sufficient here and keeps the change low-risk — reserve `framer-motion` for cases that need spring physics or gesture tracking, neither of which apply).
- Never re-measure/recompute page breaks as *part of* the toggle transition — breaks should already be computed (or computed once, silently, on first switch to paginated mode) before the fade-in starts, so the fade never shows content "settling" into place.

## 3. Editing affordances inside pages

Because paginated mode reuses the exact same editable DOM tree (`dispatch`, `EditorItem`, `DocumentSectionBlock`, `SortableDocumentItemRow` — ARCHITECTURE.md Q5, unchanged, zero forking), every existing hover/focus/drag CSS state applies **unmodified** inside paginated mode. Only the decoration layer is new, and it must never intercept interaction:

| Rule | Value | Why |
|---|---|---|
| Page decoration boxes MUST use `overflow: visible` | Never `overflow: hidden` | The legacy single-sheet `pageView` used `overflow-hidden` (fine for a non-editable single "sheet"); paginated mode is a DECORATION layered behind live, editable, draggable content — clipping would cut off hover rings, focus outlines, and dnd-kit's drag-transform near a page boundary |
| Decoration z-index | Page sheet background/shadow/border render `pointer-events-none`, stacked BEHIND the content layer (`z-index: 0` decoration, content layer default stacking, drag overlays above both) | Clicks/hovers/drags must always reach the real interactive row, never the decorative sheet |
| dnd-kit `DragOverlay` | Must portal to `document.body` (or another top-level, non-clipped container) — never inside a page-decoration wrapper | A drag crossing a page-gap boundary must render its ghost continuously, not disappear/clip at the boundary |
| Repagination — "no flicker" rule | Debounce free-text-triggered repagination at **400ms** after the last keystroke (mid-point of CONTEXT.md's 300-500ms suggested range); structural changes (add/remove/reorder item or section) repaginate immediately, no debounce | Matches FEATURES.md's anti-feature warning against per-keystroke repagination |
| Repagination — atomic update | All page-break offsets update in a SINGLE state write, applied on the next animation frame, never partially | Prevents a visible half-updated page layout mid-recalculation |
| Focus/cursor preservation | Rows are keyed by stable `item.id`/`section.id`, never by page index — since the DOM never remounts, native browser focus/cursor position survive repagination automatically | Required by PGMODE-03; this is a consequence of the "no forking" architecture, not extra code |
| Empty space at page bottoms | No special treatment — the white page sheet simply continues to the computed page-height boundary; trailing whitespace before a break is expected/correct (mirrors a real printed page) | Do not stretch/justify content to fill the page — that would break "same content, same page" parity with the PDF |
| First-paint-after-toggle (before offsets are computed) | Render content in normal (non-decorated) flow with ZERO page chrome until the first `computePageBreaks()` result resolves, then fade the decoration in per §2 transition rule | Avoids a flash of misplaced/overlapping page-sheet decoration on the very first paint |

## 4. Responsive behavior

**Recommendation: scale-to-fit, not disable.** Paginated mode stays available at every breakpoint (mobile through desktop) — it must not be a desktop-only feature with no explanation, and CONTEXT.md sets no such platform restriction.

Extend the EXISTING `pageZoom` CSS-`zoom` fit calculation (`estimate-editor.tsx:297-315`, currently height-only) to also account for available WIDTH, not just height:

```ts
// was: Math.min(1, Math.max(avail / LETTER_PAGE_HEIGHT, 0.45))
const zoom = Math.min(
  1,
  Math.max(
    Math.min(availHeight / PAGE_HEIGHT_PX, availWidth / PAGE_WIDTH_PX),
    0.45, // existing floor — never unreadably small
  ),
)
```

| Breakpoint | Behavior |
|---|---|
| Desktop (≥1024px, viewport ≥ 816px + padding) | `zoom = 1`, page renders at true 816×1056px |
| Tablet / narrow desktop (viewport < 816px + padding) | `zoom` shrinks proportionally so the FULL page width is always visible (no horizontal scroll/clipping) — reuses the proven, already-shipped zoom mechanism, just widened to also gate on width |
| Mobile | Same formula, floored at `0.45` (existing floor) — below that floor, content becomes unreadable, so full-width mode remains the better choice; do not force paginated mode below the floor, just let the toggle stay available (user's choice) |
| Toggle buttons themselves | Remain visible at all breakpoints (unlike the autosave-status text, which is already `hidden sm:inline`) — the toggle is higher-value real estate than the save-status label the mobile header already hides |

This is a `[Claude's Discretion — flagged, not blocking]` recommendation per CONTEXT.md; revisit once the owner's reference image arrives in case it specifies a different mobile treatment (e.g. disabling paginated mode entirely below a breakpoint).

## 5. Accessibility

| Requirement | Value |
|---|---|
| Page sheet vs. dark tray contrast | Trivial — pure white (`#ffffff`) sheet against the `--muted` dark tray is a very high-contrast boundary by construction; no additional work needed |
| Page-number chrome contrast | **MUST** meet WCAG AA 4.5:1 (normal-size 12px text) against the `--muted` dark tray background. Use `text-white/70` — NOT a lower opacity (e.g. `/45` or `/50`, which risk falling below AA at this text size). Executor must verify with a contrast checker at implementation time; this is a BLOCK-level rule, not a suggestion (see §6). |
| Toggle button focus rings | Inherited automatically from the shared `Button` component's `focus-visible:shadow-[var(--focus-shadow)]` (already dark-mode-tuned: `0 0 0 3px hsl(var(--ring)/0.45)` in `.dark`). No new focus styling needed. |
| Toggle button `aria-pressed` | Required on both buttons (see §1) — screen readers must announce which mode is currently active. |
| `prefers-reduced-motion: reduce` | All mode-toggle transitions (decoration fade, page-gap height animation) become instant (`transition: none`), gated via `@media (prefers-reduced-motion: no-preference)` exactly like the rest of `app/globals.css`. Do not gate on JS `matchMedia` only — use the CSS media query as the primary mechanism, consistent with existing code. |
| Touch targets | `icon-sm` = 36×36px. Below the 44px touch-target guideline, but matches the EXISTING adjacent "Edit with AI" button height (`size="sm"` = `h-9` = 36px) — consistency with the immediately-adjacent control outweighs the generic 44px guideline here (documented spacing exception, see Spacing table). |

## 6. BLOCK / FLAG rules for gsd-ui-checker

### Copywriting
- **BLOCK:** either toggle button ships without an `aria-label`, or with generic/non-contract text (e.g. "Toggle view", "Switch mode") instead of the exact labels in the Copywriting Contract table.
- **BLOCK:** either toggle button ships without a tooltip.
- **FLAG:** page-number chrome uses different phrasing than `"Page {n} of {m}"`.

### Visuals
- **BLOCK:** the two toggle buttons render as visually isolated/ungrouped elements (e.g. default `gap-2` spacing identical to unrelated header controls) instead of one cohesive segmented pill per §1.
- **BLOCK:** paginated mode renders a forked/duplicate read-only copy of any editable component (violates PGMODE-03 and this spec's reuse requirement in §3).
- **BLOCK:** any page-decoration element uses `overflow: hidden` (clips hover/focus/drag states — see §3).
- **FLAG:** page gap deviates from 32px without a documented reason.
- **FLAG:** shadow/border treatment doesn't visibly separate page sheets from the dark tray (i.e., only `shadow-2xl` with no border, per the §2 rationale).

### Color
- **BLOCK:** any new arbitrary hex/rgb color introduced for the canvas tray, sheet border, or chrome that isn't sourced from an existing token (`--muted`, `--background`, `--border`, `--primary`, etc.) — inventing a new gray not in the palette is a violation.
- **BLOCK:** accent color (`--primary`/brand) applied to any element beyond the three reserved uses listed in the Color table.
- **BLOCK:** destructive color (`--destructive`) used anywhere in this phase's new UI.
- **FLAG:** page-number chrome contrast measured below 4.5:1 against its background.

### Typography
- **BLOCK:** a new font size or weight introduced for tooltip text, page-number chrome, or continuation-table-header text that isn't one of the two declared roles (12px/400 Label, or the reused 14px/400 Body).
- **FLAG:** line-height on new text doesn't match the declared ratios.

### Spacing
- **BLOCK:** any new spacing value introduced for the toggle group, canvas padding, or page gap that isn't a multiple of 4 AND isn't one of the two documented exceptions (`gap-0.5` inside the segmented pill, 816×1056 page geometry).
- **FLAG:** inconsistent gap conventions between this toggle and other header/pill controls elsewhere in the app.

### Registry Safety
- **BLOCK:** any new third-party (non-shadcn-official) registry component pulled in for this phase without completing the registry vetting gate from the ui-researcher's own process.
- Not otherwise applicable — this phase uses only already-installed shadcn-official primitives.
