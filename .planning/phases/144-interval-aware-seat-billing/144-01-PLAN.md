# Phase 144 Plan 01: Interval-Aware Seat Billing

## Goal

`syncSubscriptionSeatItem` reads the retrieved subscription's recurring interval and sets the seat item's `recurring.interval` to match. For annual, `unitAmount` comes from `billing_config.seatPriceAnnualCents`. Monthly path is byte-identical to v4.12.

## Success Criteria

1. Hardcoded `recurring: { interval: 'month' }` replaced with dynamic interval from the subscription
2. Annual → `seatPriceAnnualCents` from `getBillingConfig()`; monthly → `seatPriceCents` (unchanged)
3. Monthly org seat sync byte-identical to v4.12
4. Single-owner within `includedSeats` → no Stripe write in either interval
5. Stays gated by `enforcementEnabled`; never-throw

## Current code (lib/billing/stripe-client.ts)

```ts
// line ~79
recurring: { interval: 'month' },
```

`syncSubscriptionSeatItem(stripe, subscriptionId, desired: { quantity, unitAmount })` — currently accepts `unitAmount` as a parameter, so the caller (`syncSeatBilling`) already decides the price. The `recurring.interval` hardcoding is inside `syncSubscriptionSeatItem`.

## Tasks

### Task 1: Make syncSubscriptionSeatItem interval-aware

**File**: `lib/billing/stripe-client.ts`

**Change**: Read interval from the already-retrieved subscription:
```ts
const subscriptionInterval = (subscription.items?.data?.[0]?.plan?.interval ?? 'month') as 'month' | 'year'
```

Replace the hardcoded `recurring: { interval: 'month' }` with:
```ts
recurring: { interval: subscriptionInterval },
```

This is the ONLY change to `syncSubscriptionSeatItem`. The `unitAmount` is still passed in by the caller.

### Task 2: Make syncSeatBilling pass interval-aware unitAmount

**File**: `lib/billing/seat-billing.ts`

`syncSeatBilling(companyId)` currently calls:
```ts
await syncSubscriptionSeatItem(stripe, sub.stripe_subscription_id, {
  quantity: billableSeats,
  unitAmount: cfg.seatPriceCents,
})
```

It needs to read the subscription's interval and choose the right per-seat price:
```ts
const subscription = await stripe.subscriptions.retrieve(sub.stripe_subscription_id)
const interval = (subscription.items?.data?.[0]?.plan?.interval ?? 'month') as 'month' | 'year'
const unitAmount = interval === 'year' ? (cfg.seatPriceAnnualCents ?? cfg.seatPriceCents) : cfg.seatPriceCents
await syncSubscriptionSeatItem(stripe, sub.stripe_subscription_id, {
  quantity: billableSeats,
  unitAmount,
})
```

Wait — `syncSubscriptionSeatItem` already retrieves the subscription internally. To avoid a double-retrieve, we can instead pass the interval to `syncSubscriptionSeatItem` as an optional override, OR extract the retrieve call from `syncSubscriptionSeatItem`. 

**Recommended approach**: Keep `syncSubscriptionSeatItem` as-is reading the subscription (it already does), but also expose the interval it reads. However, the simplest approach is:
- `syncSubscriptionSeatItem` reads the subscription (as before) and uses its interval for `recurring.interval`
- Add an optional `annualUnitAmount` to `desired`: `{ quantity: number; unitAmount: number; annualUnitAmount?: number }`
- Inside `syncSubscriptionSeatItem`, if the subscription interval is `'year'` and `annualUnitAmount` is provided, use `annualUnitAmount` instead of `unitAmount`

This keeps the signature backward-compatible and avoids double-retrieve.

**Updated signature**:
```ts
export async function syncSubscriptionSeatItem(
  stripe: Stripe,
  subscriptionId: string,
  desired: { quantity: number; unitAmount: number; annualUnitAmount?: number }
): Promise<void>
```

**Inside the function**:
```ts
const subscriptionInterval = (subscription.items?.data?.[0]?.plan?.interval ?? 'month') as 'month' | 'year'
const resolvedUnitAmount =
  subscriptionInterval === 'year' && desired.annualUnitAmount != null
    ? desired.annualUnitAmount
    : desired.unitAmount
// use resolvedUnitAmount in priceData
// use subscriptionInterval in recurring
```

**Caller update** (`lib/billing/seat-billing.ts`):
```ts
await syncSubscriptionSeatItem(stripe, sub.stripe_subscription_id, {
  quantity: billableSeats,
  unitAmount: cfg.seatPriceCents,
  annualUnitAmount: cfg.seatPriceAnnualCents ?? undefined,
})
```

### Task 3: Unit tests

**File**: `tests/unit/billing/seat-billing-interval.test.ts` (new)

Tests (mock stripe SDK and billing_config):
1. Annual subscription + `annualUnitAmount` set → priceData uses `annualUnitAmount` + `recurring.interval: 'year'`
2. Monthly subscription → priceData uses `unitAmount` + `recurring.interval: 'month'` (byte-identical to v4.12)
3. Annual subscription + `annualUnitAmount` null/undefined → falls back to `unitAmount` (graceful)
4. Single-owner org within includedSeats → no stripe write (billableSeats = 0)
5. enforcementEnabled: false → seat quantity recorded but no Stripe write

Also update `tests/unit/billing/seat-billing-wiring.test.ts` if it has hardcoded expectations on `recurring: { interval: 'month' }`.
