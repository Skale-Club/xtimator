<interfaces>
Typed error: follow the house XtimatorError pattern (lib/errors) — code 'estimate_locked', scope 'estimates', message 'Estimate has been delivered and is locked; create a new version to make changes'. Server action returns `{ error: 'estimate_locked' }` (string contract consistent with existing saveEstimate error returns); the route throws the XtimatorError → asResponse.

LOCK COVERAGE (Opus blocker #1 — the signed-but-unresponded window): the sign route inserts the signature BEFORE respondToEstimate and SWALLOWS a respond failure (sign/route.ts:104-107 → returns success anyway); respondToEstimate never error-checks its UPDATE; copy-link delivery never sets sent_at. So `sent_at OR client_response` alone leaves a SIGNED estimate unlocked. The callers (saveEstimate guard AND refine route guard) must therefore reject when `isEstimateLocked({sent_at, client_response}) OR an estimate_signatures row exists for the estimate`. Keep lock.ts's pure predicate as-is; the signature-existence check is a caller-side lookup (one indexed EXISTS query) OR'd in.

LOCK READ (Opus note #5): saveEstimate today has NO pre-UPDATE SELECT (the :130 UPDATE is the first estimates op). A NEW pre-UPDATE SELECT of sent_at + client_response + a signature EXISTS is REQUIRED — do not fold the lock into the UPDATE's filters (that would collide with the optimistic-concurrency zero-rows path and lose the distinct error). One extra round-trip is accepted.

PRESENTATION CARVE-OUT (Opus blocker #2 — the real architecture): the gear panel has NO dedicated save call today. PresentationSettingsPanel.onChange → dispatch UPDATE_PRESENTATION_SETTINGS (estimate-editor.tsx:483-488) → reducer sets isDirty (use-estimate-reducer.ts:473-474) → the SHARED autosave sends the FULL content payload (stateToSavePayload :125 → saveEstimate :154). presentation_settings rides EVERY content save — there is no isolated call to reroute, and the gear trigger/panel render are gated on !isReadOnly (:461, :478). Implementation requirements:
  (i) Introduce a separate content-vs-presentation gate: `isContentReadOnly` (drives document editing + autosave) vs the gear panel's own gate (stays enabled when locked, disabled only for non-current versions).
  (ii) New `savePresentationSettings(estimateId, settings, expectedUpdatedAt)` action updating ONLY that column, exempt from the lock. When the estimate is LOCKED, the gear panel calls it DIRECTLY (decoupled from isDirty/autosave — which early-returns on readOnly and would be rejected anyway) while still dispatching to the reducer for live preview. When the estimate is a DRAFT, today's payload path continues unchanged (dual-path: presentation_settings stays in the content payload — it is NOT the gear panel's sole writer).
  (iii) Live preview preserved in both modes (reducer dispatch always happens).
