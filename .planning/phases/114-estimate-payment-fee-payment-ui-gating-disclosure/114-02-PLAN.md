<objective>
Centralize "may payment UI render for this company?" into one server predicate
`paymentsEnabled(company)` keyed on `stripe_connect_status === 'active'` (PAYGATE-01), refactor
the existing inline check in `generateInvoice` to call it (no drift), and gate the forward-looking
"Generate invoice" affordance in the owner editor so a disconnected company sees NO orphan payment
element (PAYGATE-02). Per the locked decision: gate forward-looking AFFORDANCES; historical
read-only indicators (the "Paid" badge, already-issued invoice panels) are a RECORD and may remain
— a never-connected company naturally has none of them, and tests assert both states.

Purpose: one guard, zero orphans — the product works fully when Stripe is disconnected.
Output: the predicate, the editor gating wired through the project-page → overview-tab → editor
prop chain, the refactored action check, and two-state coverage (unit + e2e).
</objective>

// lib/billing/payments-enabled.ts — PURE (no 'server-only'; usable either side, data comes from server)
export function paymentsEnabled(company: {
  stripe_account_id: string | null
  stripe_connect_status: string | null
}): boolean {
  return Boolean(company.stripe_account_id) && company.stripe_connect_status === 'active'
}
