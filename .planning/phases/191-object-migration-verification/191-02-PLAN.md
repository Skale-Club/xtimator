Turn Plan 01's read-and-judge engine into the command MIG-01 asks for: one
invocation that copies every Supabase object into R2, preserving content type,
and then proves per object that it landed. Safe to run twice by construction —
the second run finds everything already matching and writes nothing.

*re-runnable*. And Success Criterion 3 — "a deliberately corrupted or deleted
destination object is caught rather than reported as success" — is only
demonstrable if verification can run WITHOUT the copy step silently healing the
damage first. That is why `--verify-only` exists and why it must be provably
write-free, not merely documented as such.

      reports a different size, the row is `[FAIL]` and `allPassed` is false. A
      write that appears to succeed but does not land must not be reported as a
      copy.

      (overwrite), then re-verified. R2/S3 PutObject is unconditional overwrite,
      which is what makes the re-run self-healing; state that in a comment.
    - `[EXTRA]` detection: a `ListObjectsV2Command` sweep of each destination
      bucket finds a key with no source counterpart → one `[EXTRA]` row,
      `allPassed` still true, and the destination count in the per-bucket line
      reflects it.

      scenario above — assert it.
