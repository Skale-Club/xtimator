# Phase 76.1 Plan 01: PWA Metadata + Install Prompt Gate Summary

**One-liner:** Next.js Viewport export + apple meta tags + iOS Safari install flow + hasProjects gate wired through project count query.

## What Was Built

1. **viewport export in app/layout.tsx** — `export const viewport: Viewport` with `themeColor` (dark: `#0a0a0f`, light: `#ffffff`), `width: 'device-width'`, `initialScale: 1`, `maximumScale: 1`. This gives Lighthouse a valid `theme-color` meta tag for the PWA installability check.

2. **Apple meta tags in app/layout.tsx** — `<head>` block with `apple-mobile-web-app-capable=yes` and `apple-mobile-web-app-status-bar-style=black-translucent`, enabling iOS Safari standalone mode.

3. **InstallPrompt rewrite** — Added `hasProjects?: boolean` prop (defaults `false` → returns `null`). Added iOS Safari detection via `navigator.userAgent` (`/iPhone|iPad/i`). iOS branch shows static instructions "Tap Share then 'Add to Home Screen' to install" with Share icon immediately (no `beforeinstallprompt` event needed). Android/Desktop branch unchanged. Dismiss flow works in both branches.

4. **app/(app)/layout.tsx** — Added 4th entry to `Promise.all`: project count query via `requireServiceClient().from('projects').select('id', { count: 'exact', head: true }).eq('company_id', company.id)`. Derives `hasProjects = (projectCountResult.count ?? 0) > 0`. Passes `hasProjects={hasProjects}` to `<InstallPrompt>`.

5. **Wave 0 test stubs** — Created `tests/unit/pwa/install-prompt.test.tsx` (5 tests) and `tests/unit/pwa/offline-indicator.test.tsx` (2 tests).

6. **app-icons.test.ts fix** — Added `statSync` import; `publicIconConflicts()` now filters `isDirectory()` entries so `public/icons/` no longer triggers a false positive.

## Deviations from Plan

This is a pre-existing mismatch, not caused by Plan 01. Documented in `deferred-items.md`.
