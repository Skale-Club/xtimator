## Human Verification Required

### 1. Lighthouse PWA Audit

**Test:** Start `npm run dev`, open Chrome, navigate to `http://localhost:3000`, open DevTools (F12), go to the Lighthouse tab, select "Mobile" device and "Progressive Web App" category, click "Analyze page load".

**Expected:** All PWA installability checks green — specifically: "Installable" section passes (manifest valid, service worker registered, HTTPS or localhost, icons present), "PWA Optimized" section passes (apple meta tags, viewport, theme-color, offline page).

**Why human:** Lighthouse requires a running browser with a real network stack. The service worker only activates in a browser context. Cannot simulate from the shell.

### 2. App Shell Offline — Service Worker Cache

**Test:** With `npm run dev` running: (a) visit `http://localhost:3000/dashboard` to warm the cache, (b) open DevTools → Network → change throttle to "Offline", (c) reload the page (Cmd+Shift+R / Ctrl+Shift+R).

**Expected:** The app shell renders — not a "This site can't be reached" browser error page. The OfflineIndicator yellow bar "You're offline — showing cached data" appears at the top. The New Project button in the sidebar is visually disabled/greyed with tooltip "Requires internet connection".

**Why human:** Service worker cache state is populated at runtime during actual visits. Cannot pre-populate from a test harness.

### 3. Read-Only Cache for Estimates

**Test:** With `npm run dev` running: (a) navigate to `/dashboard` and `/estimates` (if any exist) while online, (b) enable DevTools → Network → Offline, (c) navigate to `/dashboard` — confirm page loads from cache.

**Expected:** Previously visited routes render stale data from cache. Unvisited routes show the `/offline` fallback page. No mutations are possible (create/record CTAs are disabled).

**Why human:** Cache population requires prior online visits; service worker runtime behavior cannot be unit-tested.

### 4. iOS Safari Install Flow (if device available)

**Test:** On a physical iPhone or iPad running Safari: navigate to the app URL, wait until the install prompt banner appears (requires >=1 project in the account), tap Share → "Add to Home Screen", complete the install.

**Expected:** Banner shows "Tap Share then 'Add to Home Screen' to install" with Share icon. Installed app opens in standalone mode (no Safari chrome). App icon matches the maskable PNG.

**Why human:** `beforeinstallprompt` never fires on iOS; iOS Safari install flow can only be verified on a physical device or iOS Simulator.

### 5. Android Chrome Install Prompt (if device available)

**Test:** On Android Chrome or Chrome DevTools with mobile simulation (Application → Manifest → "Add to homescreen"): visit the app with >=1 project, confirm install banner appears at the bottom.

**Expected:** Bottom banner "Install Xtimator for quick access" with Install button and dismiss (X). Tapping Install shows native Chrome install sheet. After install, app opens in standalone mode.

**Why human:** `beforeinstallprompt` requires a real browser with installability criteria met (valid manifest + registered SW + HTTPS/localhost + not already installed).
