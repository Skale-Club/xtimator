## Decisions Made

- `useIsOffline` defined inline per component (not extracted to a shared `hooks/use-is-offline.ts`) — three isolated consumers with no cross-component sharing; inline keeps the change self-contained per the RESEARCH Pattern 4 recommendation.
- Sidebar offline gate wraps a `<button>` (not `<Link>`) inside a Tooltip — `<Link>` has no disabled prop; a `<button disabled>` with `pointer-events-none` achieves identical visual treatment without breaking router semantics.
- Dashboard empty state suppresses `actionHref` when offline — EmptyState already renders no action button when `actionHref` is undefined, making this the least invasive change.
- `ClientNewProjectButton` uses native HTML `title` attribute for the offline tooltip — no additional Tooltip component import required; fits the existing `disabled={isPending}` pattern.
- Lighthouse + device install testing deferred to manual user QA — Task 2 checkpoint was approved by the user; automated Lighthouse CI is out of scope for this phase.
