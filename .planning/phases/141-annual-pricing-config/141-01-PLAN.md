<objective>
ANN-01 — make the per-tier ANNUAL subscription price and the global ANNUAL per-seat
price FULLY CONFIGURABLE in the super-admin billing panel, with ZERO hardcoded billing
numbers. Extend `BillingConfig`/`DEFAULT_BILLING_CONFIG` with `seatPriceAnnualCents`
(global) and `tiers[tier].subscriptionPriceAnnualCents` (per-tier) as null-safe
calibration placeholders, mirror the shape in the admin zod schema, surface both as
editable fields in the billing form, and lock the no-hardcode invariant with a static test.

This phase is a NEAR-EXACT MIRROR of Phase 139-01 (which added `seatPriceCents` +
`tiers[tier].includedSeats`). Reuse that proven shape verbatim — same type idiom, same
DEFAULT placeholder discipline, same deep-merge (untouched), same zod `.int().min(0)`,
same admin-form field idiom, same two-test split (deep-merge in the existing test file +
a new static no-hardcode file).

Purpose: every annual-billing number lives in ONE place (billing_config), read at runtime
via getBillingConfig(), changeable in the panel without a deploy (30s TTL flush) — exactly
the discipline markup / estimateFeePct / seatPriceCents already follow. The displayed
discount % is DERIVED later (Phase 145, `1 − annual/(12×monthly)`) and is NEVER stored —
this phase adds ONLY the price fields.

Output: extended config type + defaults + schema + admin form fields + a no-hardcode static test.

SCOPE FENCE (do NOT cross): config + admin zod schema + admin form fields ONLY. NO checkout
interval (Phase 143), NO credit-grant cron (142), NO seat-interval/Stripe sync logic (144),
NO pricing-card UI toggle or discount derivation (145), NO Stripe Price IDs, NO env vars,
NO new getBillingConfig consumer (the BILLCFG-03 allowlist is UNTOUCHED — this plan adds
config FIELDS only, no module that reads them at runtime). Just the price fields in config + schema + form.
</objective>
