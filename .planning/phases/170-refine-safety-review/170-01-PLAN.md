```ts
// lib/estimate/refine-merge.ts — pure, deterministic (same util for the dialog preview AND the reducer apply)
export interface RefineDiff {
  changed: Array<{ description: string; oldPrice: number; newPrice: number; oldQty: number; newQty: number }>
  added: Array<{ description: string; unit_price: number }>
  removed: Array<{ description: string }>
  // Warning 2: narrative-only refines change ZERO line items — without these a
  // "make the summary more professional" refine would render an EMPTY diff and the
  // user would Discard a real change. Field-level flags so the review is never empty.
  fields: {
    summary?: { old: string; new: string }
    notes?: boolean; timeline?: boolean; payment_terms?: boolean; warranty_terms?: boolean
  }
}
export function mergeRefinement(
  current: { sections: EditorSection[]; summary: string; notes?: string; timeline?: string; payment_terms?: string; warranty_terms?: string },
  refined: RefinementPayload
): { mergedSections: EditorSection[]; diff: RefineDiff }
```
Matching (v1 — the refined payload has no ids; TWO-PASS to preserve identity for reworded lines, the Blocker-1 fix):
- Match refined section → current section by normalized title; unmatched refined section = all-new (temp- section id).
- Within a matched section, TWO passes (a refine's whole purpose is often to reword/re-scope a line — a description-only match would classify that exact row as remove+add and LOSE its id/created_at, the opposite of the requirement):
  - **Pass 1 — exact normalized-description match** (case/space-insensitive): covers verbatim-untouched rows, reorders, and price/qty-only changes. Reuse the current id.
  - **Pass 2 — positional pairing of the LEFTOVERS**: pair each still-unclaimed current item with the still-unclaimed refined item at the same section-relative leftover index. A pair = a MODIFICATION (description changed) → REUSE the current id (preserve created_at), emit as `changed`. Guard each pass-2 pair with a light similarity threshold (token-overlap or a short Levenshtein ratio) so a genuine replace isn't force-matched onto an unrelated id — below threshold, treat as removed+added instead.
  - Remaining unmatched refined items = added (temp- id); remaining unmatched current items = removed (dropped).
- Preserve the 165-02 advanced-pricing carry-through (taxable/tax_category/discount/cost/markup ?? defaults). isManuallyEdited: PRESERVE it when the matched row's unit_price is unchanged (the AI echoed it verbatim — don't silently un-pin a manual price it didn't touch); reset to false only when the price actually changed (Info 6). DOCUMENT this.
- diff derived from the same matching: changed = matched (pass 1 or 2) with price OR qty OR description delta; added = unmatched-refined; removed = unmatched-current; fields = the summary/notes/timeline/terms deltas.

Reducer: APPLY_REFINEMENT calls mergeRefinement(state.sections, action.refined) and sets state.sections = mergedSections (then recalculate). No more blanket temp- regeneration. Keep the summary/notes/timeline/terms replacement.

Dialog (refine-estimate-dialog.tsx): 
- REFINE-01 flush: prop `onBeforeRefine: () => Promise<boolean>` (returns runSave's boolean). In submit, BEFORE the fetch: `if (isDirty) { const ok = await onBeforeRefine(); if (!ok) { setSubmitState('idle'); return } }` — runSave returns false on lock/conflict/generic error (estimate-editor.tsx:296/309/319); if the flush FAILS the dialog must NOT POST (else the refine runs on the stale persisted row and silently discards the user's edit — Warning 3). Surface the save error. Happy path has no flush↔POST race (runSave awaits the server action's commit; the POST is a fresh read-committed read).

Two buttons: Apply → onApply(refined) + close; Discard → close, no dispatch.
