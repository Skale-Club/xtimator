```ts
// lib/estimate/refine-merge.ts — pure, deterministic (same util for the dialog preview AND the reducer apply)
export interface RefineDiff {
  changed: Array<{ description: string; oldPrice: number; newPrice: number; oldQty: number; newQty: number }>
  added: Array<{ description: string; unit_price: number }>
  removed: Array<{ description: string }>
}
export function mergeRefinement(
  currentSections: EditorSection[],   // the editor's current rows, WITH ids
  refined: RefinementPayload
): { mergedSections: EditorSection[]; diff: RefineDiff }
```
Matching (v1 heuristic — the refined payload has no ids):
- Match refined section → current section by normalized title; unmatched refined section = all-new (temp- section id).
- Within a matched section, match each refined item → an unclaimed current item with the same normalized description (case/space-insensitive). A match REUSES the current item's id (preserve id + created_at) and takes the refined content (this is "unchanged" if price/qty equal, else "changed"). An unmatched refined item = new (temp- id). A current item with no refined match = removed (dropped).
- Preserve the 165-02 advanced-pricing carry-through already in APPLY_REFINEMENT (taxable/tax_category/discount/cost/markup ?? defaults), and isManuallyEdited handling (a merged/reused row: reset isManuallyEdited=false, same as today, since the AI re-priced it — DOCUMENT this choice).
- diff is derived from the same matching: changed = matched with price OR qty delta; added = unmatched-refined; removed = unmatched-current.

Reducer: APPLY_REFINEMENT calls mergeRefinement(state.sections, action.refined) and sets state.sections = mergedSections (then recalculate). No more blanket temp- regeneration. Keep the summary/notes/timeline/terms replacement.

Dialog (refine-estimate-dialog.tsx): 
- REFINE-01 flush: before POSTing the instruction, if the editor is dirty, flush a save (await the editor's save) so the route reads the latest persisted content. The dialog needs an `isDirty` + `flushSave` (or `onBeforeRefine: () => Promise<void>`) prop from the editor.
- REFINE-02 review: after the POST returns `{refined}`, do NOT immediately onApply. Compute `mergeRefinement(currentSections, refined)` (currentSections passed in as a prop/snapshot) and render the RefineDiff summary (changed/added/removed with old→new). Two buttons: Apply → onApply(refined) (reducer re-merges deterministically) + close; Discard → close, no dispatch.

Editor (estimate-editor.tsx): pass currentSections snapshot + isDirty + a flushSave callback (reuse runSave/handleSaveDraft) to the dialog; onApply stays dispatch(APPLY_REFINEMENT). Keep the existing lock/credit behavior (a locked estimate already hides/blocks refine per 164-02).
