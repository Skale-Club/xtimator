<objective>
Ship the SEAT-03 invite lifecycle server actions in `lib/actions/team.ts`:
`inviteMember(companyId, email, role)` and `revokeInvite(inviteId)`. Both gate
through the single `requireCompanyManager` authority (owner/admin only, never
client-trusted). `inviteMember` validates the input, generates a unique
cryptographically-random token, inserts a pending `company_invites` row, and
sends the invite email from Plan 01 — without ever returning the raw token to
the caller. `revokeInvite` flips a pending invite to 'revoked'.

Scope fence: create + email + revoke ONLY. NO accept route/flow (Phase 137),
NO member-management UI (Phase 138), NO seat billing (Phase 139). A pending
invite does NOT consume a billable seat — do nothing billing-related here.

Purpose: An owner/admin can invite a teammate and revoke a pending invite,
server-side authority enforced, token delivered only by email.
Output: `lib/actions/team.ts` + its behavioral test.
</objective>

    export `inviteMember(companyId: string, email: string, role: 'admin' | 'member')`:
    1. Gate: `try { await requireCompanyManager(companyId) } catch (e) { return { error: ... } }`
       — captures the resolved ctx (need `invited_by = ctx.userId` + inviterName context).
       Prefer: `let ctx; try { ctx = await requireCompanyManager(companyId) } catch { return { error: 'Not authorized' } }`.
    2. Validate: `const parsed = inviteSchema.safeParse({ email, role }); if (!parsed.success) return { error: 'Invalid email or role' }`.
       Use the parsed/normalized email from here on (lowercase-trim it: `const normEmail = parsed.data.email.trim().toLowerCase()`).
    3. const service = requireServiceClient().
    4. Already-active-member guard: query `company_members` for a row in this company
       whose email matches normEmail (the company_members table carries an `email` column
       per staff.ts). If found → `return { error: 'This email is already a member of the company.' }`.
       (Match by email case-insensitively; if company_members has no usable email for a row,
       this guard simply does not match — acceptable for this phase.)
    5. Duplicate-pending guard: query `company_invites` for a row with company_id = companyId,
       email = normEmail, status = 'pending'. If found → `return { error: 'A pending invite already exists for this email.' }`.
       [DOCUMENTED CHOICE: reject duplicates rather than replace — keeps the action side-effect-free on conflict.]
    6. Generate token: `const token = randomBytes(32).toString('base64url')` (unguessable; the
       column UNIQUE constraint is the single-use/uniqueness backstop).
    7. Compute `const expiresAt = new Date(Date.now() + INVITE_TTL_DAYS * 24 * 60 * 60 * 1000)`.
    8. Insert into `company_invites`: `{ company_id: companyId, email: normEmail, role,
       token, status: 'pending', invited_by: ctx.userId, expires_at: expiresAt.toISOString() }`.
       If insert errors → `return { error: 'Failed to create invite.' }` (do NOT send the email).
    9. Resolve the company name for the email: select `name` from `companies` where id = companyId

    10. Send the email (Plan 01): `await sendInviteEmail({ toEmail: normEmail, token, role,
        companyName, inviterName: null /* or ctx-derived if cheap */, expiresAt })`.
        sendInviteEmail never throws, so no try/catch needed around it.
    11. `revalidatePath('/settings/team')`.
    12. `return { success: true as const }` — CRITICAL: NEVER include `token` in the return.

    export `revokeInvite(inviteId: string)`:
    1. Look up the invite first (service client): select `company_id, status` from
       `company_invites` where id = inviteId. If not found → `return { error: 'Invite not found.' }`.
    2. Gate on the invite's company: `try { await requireCompanyManager(invite.company_id) }
       catch { return { error: 'Not authorized' } }` — this both authorizes AND scopes to the
       caller's company.
    3. If `invite.status !== 'pending'` → `return { error: 'Only pending invites can be revoked.' }`
       (no-op — do NOT update).
    4. Update `company_invites` set status='revoked' where id = inviteId AND status='pending'
       (the status guard in the WHERE makes the flip idempotent). If update errors →
       `return { error: 'Failed to revoke invite.' }`.
    5. `revalidatePath('/settings/team')`; `return { success: true as const }`.

    Do NOT do anything seat-billing-related (no seat count, no Stripe — that is Phase 139).
    Do NOT generate/return the token to the client. Do NOT build the accept route.
