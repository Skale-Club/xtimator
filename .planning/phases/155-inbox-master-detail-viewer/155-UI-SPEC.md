## Spacing Scale

Declared values (must be multiples of 4) — these are Xtimator's existing scale, confirmed from current admin surfaces (`admin-whatsapp-client.tsx`, `companies/page.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps (e.g. row unread dot, badge internals) |
| sm | 8px | Compact gaps (`gap-2`, row internal spacing), list row vertical padding |
| md | 16px | Row/cell horizontal padding (`px-4`), pane header/footer padding |
| lg | 24px | Not used inside the two-pane container (reserved for outer page sections) |
| xl | 32px | Not used inside the two-pane container |

Row vertical rhythm:
- List row: `px-3 py-2` (12px horizontal / 8px vertical). 8px vertical padding is a valid scale value (`sm`), and is intentionally denser than the existing table's `py-3` cells (12px) — a deliberate choice for a compact conversation-list aesthetic, not a reuse claim against any existing `py-2.5` class (no such class exists in the codebase; the existing table/Sheet padding is `px-4 py-3` throughout, confirmed via `admin-whatsapp-client.tsx`).
- Pane header/footer: `px-4 py-3` (matches existing `SheetHeader`/table thead padding, `border-b`/`border-t`).

Exceptions:
- Left pane fixed width: `w-[320px]` (Autonomous decision — see Layout section). Not a spacing-scale value; it's a container dimension, not internal spacing.
- Touch target minimum for the mobile "Back" affordance: 44px height (icon + label button), per standard touch-target practice — no existing project precedent to reuse, so this is a sensible default.

## Typography

Reusing exact classes already present in `admin-whatsapp-client.tsx` / `admin-whatsapp-filters.tsx` — no new sizes or weights introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (message text, row preview) | 14px (`text-sm`) | 400 (regular) | 1.5 (Tailwind default `leading-normal` on `text-sm`) |
| Label (row name, pane header title) | 14px (`text-sm`) with `font-medium` (500) | 500 (medium) | 1.2 (`leading-none`/`leading-tight` per existing `SheetTitle`) |
| Caption (timestamp, company secondary label, footer note) | 12px (`text-xs`) | 400 (regular) | 1.4 (Tailwind default on `text-xs`) |
| Micro (message bubble timestamp, per `MessageBubble`) | 10px (`text-[10px]`) | 400 (regular) | 1.2 |

Only 2 weights used across this phase: 400 (regular, body/caption/micro) and 500 (medium, names/titles — matches existing `font-medium` usage, NOT 600/semibold, since the current table/Sheet implementation uses `font-medium` throughout, not `font-semibold`). This is a pre-existing project convention, reused rather than invented.

**Exemption note:** The no-conversation-selected empty state reuses the existing `EmptyState` component (`components/dashboard/empty-state.tsx`) verbatim. That shared component's own internal typography (`text-lg font-semibold` — 18px/600) is inherited from that shared, unmodified component — not a new type choice authored by this phase — and is exempt from this phase's own 4-size/2-weight budget above, mirroring how phase 154 exempted the shared `tabs.tsx` primitive's font-weight. No phase-authored markup introduces 18px or weight 600; only the pre-existing `EmptyState` internals do.

## Layout Contract (phase-specific — supplements the template)

### Container

```
<div className="flex h-full min-h-0 gap-0 overflow-hidden">  {/* two-pane row, replaces the Card+table+Sheet */}
  <div className="flex w-[320px] shrink-0 min-h-0 flex-col border-r border-border ...">  {/* list pane */}
  <div className="flex flex-1 min-h-0 flex-col ...">  {/* thread pane */}
</div>
```

- **Height source**: `app/admin/layout.tsx`'s `<main>` is `flex-1 overflow-y-auto px-8 py-8` — the `<main>` itself is the scroll container for the whole admin page today. For this phase's two-pane viewer to scroll each pane independently (list scrolls, thread scrolls, outer page does NOT scroll as a whole — per CONTEXT.md lock), the Inbox page content must opt OUT of `<main>`'s scroll and instead fill it: the page root wrapper uses `h-full min-h-0 flex flex-col` so the two-pane container can compute its own bounded height from the `<main>` viewport, and each pane gets its own `overflow-y-auto` + `min-h-0`. **Autonomous decision**: do not modify `app/admin/layout.tsx` (out of blast radius for this phase); instead the Inbox page's own root div takes `h-full` (relying on `<main>` being a flex child that already constrains height) — concretely, wrap the two-pane row in a container with `flex-1 min-h-0` inside the page, so it fills whatever height `<main>` gives it, and give that wrapper its own `overflow-hidden` so only the two inner panes scroll, not `<main>`.
- **Left pane width**: fixed `w-[320px] shrink-0` (Autonomous decision, per CONTEXT.md's explicit menu of `w-[320px]` or `w-[360px]` — 320px chosen to match Xphere's stated default width and because the row content (name + timestamp + preview) fits comfortably at 320px given Xtimator's shorter row content — no company-branding avatar column like Xphere). Resizing is explicitly skipped (CONTEXT.md discretion — adds risk/time without being a locked requirement).
- **Right pane**: `flex-1 min-h-0 flex flex-col overflow-hidden` — header (fixed), message list (`flex-1 overflow-y-auto`), footer note (fixed).
- **Divider**: `border-r border-border` between panes (existing `--border` token, no new divider style).

### Primary visual anchors

The selected conversation row's accent-colored left border and the thread pane's message list are the primary visual anchors of this screen; the list pane's search/filter header is secondary. Everything else (dividers, captions, footer note) is deliberately low-contrast so the eye lands on "which conversation is active" and "what was said" first.

### Conversation list (left pane) row anatomy

Reusing exact fallback copy and formatting already in `admin-whatsapp-client.tsx`:

```
<div role="button" tabIndex={0} className="flex items-center gap-3 px-3 py-2 rounded-[var(--radius-md)] cursor-pointer hover:bg-muted/20 [selected: bg-muted/60 border-l-2 border-[hsl(var(--primary))]]">
  <div className="flex min-w-0 flex-1 flex-col gap-0.5">
    <div className="flex items-center justify-between gap-2">
      <span className="text-sm font-medium truncate">{contact_name || "(unknown)"}</span>
      <span className="text-xs text-muted-foreground whitespace-nowrap">{timestamp}</span>
    </div>
    <div className="flex items-center justify-between gap-2">
      <span className="text-xs text-muted-foreground truncate">{last_message_preview ?? "—"}</span>
      {unread_count > 0 && <Badge variant="outline">{unread_count}</Badge>}
    </div>
    <span className="text-xs text-muted-foreground truncate">{company_name || "(unknown company)"}</span>
  </div>
</div>
```

- Selected state: `bg-muted/60` + `border-l-2 border-[hsl(var(--primary))]` (uses the admin shell's existing `--primary` system-accent token set in `admin/layout.tsx` — NOT tenant branding — correct per that layout's own comment about elevated controls not inheriting tenant color).
- Hover state: `hover:bg-muted/20` (identical class already used on the current table `<tr>`).
- Unread indicator: **Autonomous decision** — keep the existing numeric `<Badge variant="outline">{unread_count}</Badge>` (not a plain dot). Rationale: CONTEXT.md marks this as either-acceptable discretion; the numeric badge is strictly more informative and is a zero-cost reuse of an already-correct component — changing it to a dot would be adding a new visual pattern for no requirement-driven reason.
- Keyboard pattern: `role="button"`, `tabIndex={0}`, `onKeyDown` handling Enter/Space — ported verbatim from the current `<tr>` handler.

### Thread (right pane) anatomy

- Header: `border-b px-4 py-3` containing contact name (`text-sm font-medium`, same fallback logic as current `SheetTitle`) and phone + company as `text-xs text-muted-foreground` (same content/format as current `SheetDescription`).
- Body: `flex-1 overflow-y-auto px-4 py-4 space-y-2`, rendering `MessageBubble` per message — unchanged.
- Loading state: centered `Loader2` spinner (`h-6 w-6 animate-spin text-muted-foreground`) — unchanged from current Sheet.
- Footer: `border-t px-4 py-2 text-xs text-muted-foreground` — "Read-only. Shows up to the last 30 days of messages." — unchanged copy.
- Empty-message state (thread loaded, zero messages in 30 days): "No messages in the last 30 days." — unchanged copy.
- No-conversation-selected state (new): reuse the existing `EmptyState` component (`components/dashboard/empty-state.tsx`) rather than a bespoke placeholder — see Copywriting Contract below and the Typography exemption note above for how its internal 18px/600 title is treated.

### Mobile behavior (below `md:`, i.e. < 768px)

Xtimator's admin surfaces do not currently collapse tables to cards on mobile (they rely on `overflow-x-auto` horizontal scroll instead) — there is no existing "list ↔ detail" mobile pattern to reuse in this codebase, so this phase establishes one, anchored to Tailwind's standard `md:` breakpoint (768px) already used elsewhere in the app (confirmed convention: `md:hidden` / `hidden md:` pairs appear in `app/(app)/projects/[id]/page.tsx` and sibling `loading.tsx` files).

- **Autonomous decision**: implement via conditional rendering (not pure CSS `hidden md:flex`), matching CONTEXT.md's suggestion that conditional-rendering-based-on-selection is acceptable and simpler than a CSS-only approach here, because the thread pane's data-fetch is already gated on `conversation` being set — no point mounting/rendering the thread markup at all on mobile until a conversation is chosen:
  - No `?conversation=` param + viewport `< md`: render list pane only, full width (`w-full`, no fixed `320px`, no right pane in the DOM).
  - `?conversation=<id>` set + viewport `< md`: render thread pane only, full width, with a "← Back" button in the thread header (in addition to / left of the contact name) that calls `router.replace` clearing the `conversation` param.
  - At `md:` and above: both panes always render side by side regardless of selection (per the two-pane locked requirement); no "Back" button shown (it's `md:hidden`).
  - Implementation detail: the list pane keeps its `w-[320px]` only at `md:` and above (`w-full md:w-[320px] md:shrink-0`); below `md:` it's conditionally not rendered rather than hidden-but-mounted, since it's a Server-Component-fed list — no meaningful cost either way, but this avoids double data-fetch/hydration ambiguity.
- Touch target for "← Back": minimum 44px height button (`h-11` or padding achieving that), per the Spacing exception above.

## Color

This phase introduces **zero new colors**. It is a strict reuse of Xtimator's existing `admin-dark` theme tokens (`app/globals.css`, applied via `data-theme="admin-dark"` in `app/admin/layout.tsx`). Xphere's literal color values are explicitly NOT ported (per CONTEXT.md lock) — only its structural weight (row density, selected/hover treatment) is emulated using Xtimator's own tokens below.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` → admin-dark: `240 6% 6%` | Page background behind both panes |
| Secondary (30%) | `hsl(var(--card))` / glass surface (`--glass-bg` dark: `rgba(20,24,33,0.60)`) | The two-pane `Card`-equivalent container surface, list-pane and thread-pane backgrounds, row backgrounds at rest |
| Accent (10%) | `hsl(var(--primary))` (admin shell system-accent, set explicitly in `admin/layout.tsx`, NOT tenant `--platform-primary`) | Reserved for: (1) selected row's left accent border, (2) any focus rings inherited from existing `Input`/`Select`/`Button` components, (3) links styled `text-[hsl(var(--primary))]` if any are added (none planned in this phase) |
| Destructive | `hsl(var(--destructive))` (admin-dark: `0 62.8% 45%`) | Already used only inside `MessageBubble` for `failed` outbound message status — unchanged, no new destructive actions in this phase (this phase is read-only, adds no delete/destructive UI) |

Accent reserved for: **selected conversation row's left border only**, plus standard component-level focus/hover states already baked into shadcn `Button`/`Input`/`Select` — never applied to body text, icons, or decorative elements beyond that.
