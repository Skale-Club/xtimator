  <action>
    Create lib/actions/invite-accept.ts ('use server'). Export
    `async function acceptInvite(token: string): Promise<{ success: true } | { error: string }>`.

    Implementation order (token authority — NOT requireCompanyRole; the accepting user is
    not yet a member):
    1. Read the accepting user: `const supabase = await createClient(); const { data } =
       await supabase.auth.getClaims(); const claims = data?.claims`. If no claims.sub →
       return { error: 'You must be signed in to accept this invite.' }.
    2. `const service = requireServiceClient()`. Look up the invite by token:
       `service.from('company_invites').select('id, company_id, email, role, status, expires_at')
       .eq('token', token).maybeSingle()`. Null → { error: 'This invite link is invalid.' }.
       (Never echo the token in the error; never console.log it.)
    3. Validate status === 'pending' → else { error: 'This invite is no longer valid (it may
       have been used or revoked).' }.
    4. Validate `new Date(invite.expires_at).getTime() > Date.now()` → else
       { error: 'This invite has expired.' }.
    5. Email match: compare `String(claims.email).trim().toLowerCase()` ===
       `String(invite.email).trim().toLowerCase()` → else { error: 'This invite was sent to a
       different email address. Sign in with the invited email to accept.' }.
    6. SINGLE-USE atomic flip FIRST (before the member insert so a lost race writes no
       membership): `service.from('company_invites').update({ status: 'accepted' })
       .eq('id', invite.id).eq('status', 'pending').select('id')`. If the returned data is
       empty/null (0 rows affected) → another accept won → return { error: 'This invite has
       already been accepted.' }.
    7. Insert membership idempotently: `service.from('company_members').upsert(
       { user_id: claims.sub, company_id: invite.company_id, role: invite.role,
         email: invite.email }, { onConflict: 'user_id,company_id', ignoreDuplicates: true })`.
       Role + company come ONLY from the invite row — never from a caller param. On a hard
       insert error (not a conflict) → return { error: 'Could not join the team. Please try
       again.' } (do NOT leave the invite flipped-but-unjoined in a way that bricks retry;
       acceptable for v1 — document this in a comment).
    8. Switch active company: `await switchActiveCompany(invite.company_id)`. Ignore its
       discriminated error for the return (the membership now exists; a cookie-write hiccup
       must not fail the join) — but DO call it so the user lands in the right org.
    9. Return { success: true as const }.

    NEVER log the token. NEVER accept a role/company argument. Mirror team.ts comment style.
  </action>
