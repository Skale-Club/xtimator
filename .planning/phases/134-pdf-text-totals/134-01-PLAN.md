<objective>
Add the shared READ seam for the v4.11 deposit/balance-due totals so all three output
surfaces (PDF, public share view, plain-text/WhatsApp/MCP) agree because they call one
helper that reads the PERSISTED server row — never recomputes (GUARD-03).

Two pieces:
1. Widen the `Estimate` type with the deposit columns that already exist in the DB
   (added by the phase-129 migration `20260627000001_phase129_advanced_pricing_schema.sql`:
   `deposit_type TEXT NOT NULL DEFAULT 'none'`, `deposit_value NUMERIC(12,2)` nullable,
   `balance_due NUMERIC(12,2)` nullable). The data layers already `select('*')`, so the
   values flow at runtime — this just makes them type-visible to the renderers.
2. A pure `deriveDepositDisplay()` helper that turns a persisted row into render-ready
   display values, with a hard retrocompat short-circuit when no deposit is set.

Purpose: one source of truth for "is there a deposit, and what is the deposit amount /
balance due" so the three surfaces in plans 02/03/04 can't drift.
Output: `lib/estimate/deposit-display.ts` + Estimate type fields + unit test.
</objective>
