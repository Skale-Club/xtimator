<objective>
Wire the Plan-01 validator to the enforcement decision (the CALIB-02 proof) and document the calibration transition.

The charge-on gate lives inside `saveBillingConfig` — the SINGLE write path for `enforcementEnabled`. After the existing `safeParse`, if the incoming config sets `enforcementEnabled: true`, run `validateMarginInvariant(parsed.data)` and REJECT the save (`return { ok: false, message }`, NO upsert) when it fails. A wiring test asserts no upsert fires on a failing flip — THIS is the proof the validator gates the enforcement decision, which is exactly what CALIB-02 requires. Saving with enforcement OFF is never gated (illustrative numbers are always saveable).

This plan also ships the operator's calibration tooling: a Node `.mjs` analysis script over `ai_cost_events`, and the CALIBRATION-RUNBOOK documenting collect→analyze→set→validate→flip.

CRITICAL: this phase ships the MECHANISM. It does NOT flip `enforcementEnabled` to true (no production data exists). The milestone completes SAFELY with enforcement OFF. The gate makes a future unsafe flip impossible; the runbook documents the real flip for later.

Purpose: tie the validator to the single chokepoint + document the numbers + give ops the aggregation tool. Output: the gate + its wiring test, the script, the runbook.
</objective>
