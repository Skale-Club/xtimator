<!-- declares module-scope mutable spies and wires the real consumer module to them: -->

```ts
// e.g. tests/unit/whatsapp/never-reply-regression.test.ts
const sendWhatsAppMessage = vi.fn().mockResolvedValue(undefined)   // module-scope mutable spy
vi.mock('@/lib/whatsapp/client', () => ({
  sendWhatsAppMessage: (...args) => sendWhatsAppMessage(...args),  // arrow indirection
}))
const generateEstimateForProject = vi.fn()                         // module-scope mutable spy
vi.mock('@/lib/services/generate-estimate', () => ({ generateEstimateForProject: (...a) => generateEstimateForProject(...a) }))
```

The REAL consumer (`lib/estimate/adapters/whatsapp.ts`) imports the mocked symbol ONCE and caches
the binding inside the reused worker (vitest 4 default `pool: 'forks'`). File B's
`vi.clearAllMocks()` clears file B's spy object — NOT the one the cached adapter actually calls —
so file A's spy call count bleeds forward. The FIX (the 2 already-correct files used it) is a
consistent `afterEach`:

```ts
afterEach(() => {
  vi.clearAllMocks()   // resets call counts on the module-scope spies
  vi.resetModules()    // LOAD-BEARING: evicts the cached real consumer so the next file rebinds
})
```

`tests/unit/whatsapp/batch-reporting.test.ts` and `tests/unit/whatsapp/replay-safe-ttl.test.ts`
ALREADY have this — use them as the reference template. Do NOT copy them; they are not the source
of their own leak.
