<objective>
Prove the concrete failure this whole phase exists to prevent: with R2 configured, an inbound WhatsApp image is written and read back on **one** backend.

Purpose: PROV-03. This is the case the field assessment named — `lib/estimate/adapters/whatsapp.ts` already honored `STORAGE_PROVIDER` (it used `getServerStorage()`), so flipping the flag made it write inbound audio and photos to R2 while every reader still read Supabase. Silent 404s on inbound media, with no error anywhere. Plans 01-03 fixed the seam; this plan turns "should be fixed now" into a test that fails if it ever isn't.

Output: one test file. No production code changes.

**No R2 activation.** The test supplies obviously-fake `S3_*` values through `vi.stubEnv` and an in-memory mock of the AWS SDK. Nothing enters `.env.local` or Coolify.
</objective>

6. The signed URL is generated for the **same key** that the write produced — assert equality between the captured `PutObjectCommand` `Key` and the key embedded in the presigned URL. "Both used R2" is not enough; the point is that the reader looks where the writer wrote.
