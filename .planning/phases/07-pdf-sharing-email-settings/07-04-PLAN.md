<task type="auto">
  <name>Task 1: Create settings data layer and server actions</name>
  <files>lib/queries/company.ts, lib/actions/settings.ts</files>
  <action>
    1. Create `lib/queries/company.ts` — query function to load all company settings.

    `getCompanySettings(supabase: SupabaseClient, userId: string)`:
    - Query: `supabase.from('companies').select('*').eq('user_id', userId).single()`.
    - Return the full company row or null.
    - Export the return type as `CompanySettings`.

    2. Create `lib/actions/settings.ts` — server actions for all settings mutations per D-18 through D-21.

    Use the standard getAuthContext pattern (getClaims + company fetch).

    **updateCompanySettings(formData: FormData)** (per D-18, SET-01, SET-02):
    - Extract fields: name, owner_name, phone, email, website, address, city, state, zip, license_number, insurance_info, industry, brand_primary_color.
    - Handle logo upload: if formData has a 'logo' File, upload to Supabase Storage at `{userId}/logo.{ext}` path in logos bucket (same pattern as onboarding — see Phase 2 decision). Get the public URL. If no new file but existing logo_url, keep it.
    - Update company row with all fields.
    - Revalidate `/settings` and `/dashboard`.
    - Return `{ success: true }` or `{ error: '...' }`.

    **updateDefaults(data: { defaultTaxRate: number, defaultPaymentTerms: string, defaultWarrantyTerms: string, defaultValidityDays: number })** (per D-19, SET-03):
    - Validate: tax rate 0-1 (decimal), validity days > 0.
    - Update company: default_tax_rate, default_payment_terms, default_warranty_terms, default_validity_days.
    - Revalidate `/settings`.

    **updateNotifications(data: { notifyOnView: boolean, notifyOnAccept: boolean, notifyOnDecline: boolean })** (per D-20, SET-04):
    - Update company: notify_on_view, notify_on_accept, notify_on_decline.
    - Revalidate `/settings`.

    **changePassword(data: { currentPassword: string, newPassword: string })** (per D-21, SET-05):
    - Use `supabase.auth.updateUser({ password: data.newPassword })`.
    - Note: Supabase `updateUser` doesn't verify current password. For v1 this is acceptable since user is already authenticated. If stricter verification needed, use `supabase.auth.signInWithPassword` first to verify current password, then update.
    - Return success or error.

    **changeEmail(data: { newEmail: string })** (per D-21, SET-05):
    - Use `supabase.auth.updateUser({ email: data.newEmail })`.
    - Supabase sends a confirmation email to the new address.
    - Return success message: "Confirmation email sent to your new address."

    **deleteAccount()** (per D-21, SET-06):
    - Use service role client: `createServiceClient().auth.admin.deleteUser(userId)`.
    - This cascades: company, projects, etc. are deleted via FK CASCADE.
    - Return `{ success: true, redirect: '/auth/login' }`.
  </action>
