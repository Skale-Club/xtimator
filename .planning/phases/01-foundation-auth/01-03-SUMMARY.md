## Decisions Made

- Used `bunx supabase db push --db-url` instead of `supabase link` because the Supabase CLI `link` command requires a Supabase access token, which is unavailable in a non-TTY environment (no `supabase login` possible). The DATABASE_URL from `.env.local` was used directly.
- `estimate_activity` has only SELECT, INSERT, and DELETE policies — no UPDATE policy — because activity logs are append-only by design.
- `(SELECT auth.uid())` wrapper used in all policies to prevent the function from being evaluated once per row, improving query performance.

## Deviations from Plan

None - plan executed exactly as written. The `bunx supabase init` step was added before `db push` because no `config.toml` existed, but this is an expected prerequisite step.

## Issues Encountered

- `bunx supabase link --project-ref prmqgcrnpuvpzruyzvuv` failed with "does not have necessary privileges" because Supabase CLI link requires an authenticated session token (not available in non-TTY). Resolved by using `--db-url` flag with the DATABASE_URL value from `.env.local` which includes the database password directly.
