# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui |
| Preset | New York style (locked — CONTEXT.md D-09) |
| Component library | Radix UI (via shadcn/ui) |
| Icon library | lucide-react (pulled in by shadcn/ui) |
| Font | Inter (Google Fonts, next/font/google) |

**Initialization command (to run during scaffold):**
```bash
bunx shadcn@latest init
bunx shadcn@latest add button input form card dialog badge select tabs avatar dropdown-menu label separator sheet skeleton textarea alert alert-dialog progress scroll-area tooltip popover calendar checkbox radio-group switch table command navigation-menu sonner
```

**Notes:**
- New York style is locked per CONTEXT.md D-09; do not use Default style.
- All components listed in D-09 must be installed in Phase 1 so later phases never need to install components.
- `next-themes` provider should be installed now for future dark mode groundwork (negligible bundle cost per CONTEXT.md Claude's Discretion).

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding between icon and label |
| sm | 8px | Compact element spacing, input field inner padding supplement |
| md | 16px | Default element spacing, form field vertical gap |
| lg | 24px | Card internal padding, section padding |
| xl | 32px | Card-to-card gap, layout column gaps |
| 2xl | 48px | Auth page vertical breathing room above/below card |
| 3xl | 64px | Page-level vertical centering offset |

Exceptions:
- Touch targets (buttons, nav items): minimum 44px height per UX-02. This falls between xl (32px) and 2xl (48px) — use `min-h-[44px]` on all interactive mobile elements; do not derive from the spacing scale.
- Auth card max-width: 400px (not a spacing token — a layout constraint).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` — white | Page background, auth page background, card background |
| Secondary (30%) | `hsl(240 4.8% 95.9%)` — neutral-100 | Input backgrounds, divider areas, muted surface behind card on large screens |
| Accent (10%) | `hsl(240 5.9% 10%)` — neutral-900 | Primary action buttons (Sign in, Sign up, Continue with Google), active form focus rings |
| Destructive | `hsl(0 84.2% 60.2%)` — red-500 | Form error messages, error toast backgrounds, field validation error borders |

**Source:** shadcn/ui New York style default tokens — neutral (slate/gray base), not a blue/brand accent. Company brand color is set per-company during onboarding (Phase 2); Phase 1 uses a neutral default throughout.

Accent reserved for:
1. Primary submit buttons on all auth forms ("Sign in", "Create account", "Send reset link", "Update password")
2. "Continue with Google" OAuth button (full-width, top of card)
3. Form field focus rings (`ring-offset-background`)
4. Keyboard focus indicators (`:focus-visible` outlines)

Destructive color is NOT used in Phase 1 for any user-triggered deletion — no destructive actions exist in auth. It is reserved exclusively for inline form validation error text and error toast messages.

## Layout Contract

### Auth Pages (`/auth/login`, `/auth/signup`, `/auth/reset-password`)

**Primary focal point: the "Continue with Google" button — it must be the most visually prominent element inside the card.**

```
┌─────────────────────────────────────────────────────────┐
│  Full-screen centered column (flex, items-center,        │
│  justify-center, min-h-screen, bg-muted/40)              │
│                                                          │
│         ┌──────────────────────────┐                     │
│         │  Logo + "EstimateBuilder  │   ← 48px mb below  │
│         │  Pro" wordmark           │     logo block      │
│         └──────────────────────────┘                     │
│                                                          │
│         ┌──────────────────────────┐                     │
│         │  Card (max-w-[400px],    │                     │
│         │  w-full, p-6)            │                     │
│         │                          │                     │
│         │  [Continue with Google]  │ ← full-width btn    │
│         │                          │                     │
│         │  ──── or ────            │ ← Separator         │
│         │                          │                     │
│         │  Email field             │                     │
│         │  Password field          │                     │
│         │                          │                     │
│         │  [Sign in]               │ ← full-width btn    │
│         │                          │                     │
│         │  Forgot password? link   │                     │
│         │  Don't have an account?  │                     │
│         └──────────────────────────┘                     │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

- Card padding: `p-6` (24px all sides)
- Card border-radius: New York default (`rounded-xl`)
- Card shadow: `shadow-sm`
- Background: `bg-muted/40` (subtle neutral wash behind card)
- Logo block: SVG logomark (placeholder compass/building icon in Phase 1) + `<span>` wordmark text at Display size (28px, weight 600)
- All form buttons: `w-full` (full card width)
- Google button: outlined with Google "G" icon from lucide-react or inline SVG; variant="outline"

### Mobile (< 640px)
- Card: `mx-4`, no max-width override — fills screen with 16px side margins
- Logo: scales down to Heading size (20px, semibold)
- No layout change otherwise — centered column still works

| Element | Copy |
|---------|------|

| Primary CTA — Reset password request | "Send reset link" |
| Primary CTA — Set new password | "Update password" |
| Google OAuth button | "Continue with Google" |
| "or" divider | "or" (lowercase, muted color) |
| Login → Signup link | "Don't have an account? Sign up" |
| Signup → Login link | "Already have an account? Sign in" |
| Login → Reset link | "Forgot your password?" |
| Empty state heading | Not applicable — no list views in Phase 1 |
| Empty state body | Not applicable — no list views in Phase 1 |

| Error — email not confirmed | "Please check your inbox to confirm your email before signing in." |

## Interaction States

All interactive elements must implement the following states:

| Element | States Required |
|---------|----------------|
| All `<Button>` components | default, hover, focus-visible, disabled, loading (spinner inside) |
| All `<Input>` components | default, focus, error (red border + FormMessage), disabled |
| Google OAuth button | default, hover, focus-visible, loading (after click, show spinner, disable button) |
| Auth card form | idle, submitting (disable all inputs + buttons, show loading state on CTA) |
| Password field | show/hide toggle via eye icon (lucide `Eye` / `EyeOff`); default hidden |

**Loading pattern:** When a form is submitting, the primary CTA button shows a `<Loader2>` icon (lucide-react, `animate-spin`) inline before the label text. All form fields and buttons are disabled during submission.

**Form validation trigger:** On submit only (not on change). On submit failure (Supabase error), show `<Alert>` above the form fields with the error message. Field-level errors (zod) show as `<FormMessage>` below each field.

## Accessibility Contract

- All `<Input>` elements have an associated `<Label>` via `htmlFor` / `id`.
- All `<Button>` elements have visible text (no icon-only buttons in Phase 1 auth).
- Error messages are associated with their fields via `aria-describedby` (handled by shadcn `<FormMessage>`).
- Color contrast: all text on backgrounds meets WCAG AA (4.5:1 for body, 3:1 for large text). shadcn New York default tokens satisfy this in light mode.
- Focus order follows DOM order (no tabindex manipulation).
- Google OAuth button has an explicit `aria-label="Sign in with Google"` if the button label is icon-only.
