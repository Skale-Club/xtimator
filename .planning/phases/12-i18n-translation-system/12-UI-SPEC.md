## Typography

Exactly 4 sizes, exactly 2 weights. Consistent with Phase 11 UI-SPEC constraint.
All sizes use Inter (`--font-inter`).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (1rem) | 400 (normal) | 1.5 | General UI text (not directly used in these 2 components) |
| Label | 14px (0.875rem) | 400 (normal) | 1.25 | LanguageToggle dropdown item labels ("English", "Português", "Español") |
| Badge | 12px (0.75rem) | 700 (bold) | 1 | 2-letter language code badge inside the toggle button (EN / PT / ES) |
| Overlay | 14px (0.875rem) | 400 (normal) | 1.5 | TranslationLoadingOverlay status text (if text label is shown) |

Notes:
- Only 2 weights in use: 400 (normal) and 700 (bold). No 500 or 600 weight classes.
- The 2-letter badge uses `font-bold` (700) to ensure legibility at 12px in an icon-sized button.
- Badge size maps to `--font-size-xs: 0.75rem` token from globals.css.

## Color

Token system: all colors consumed via `hsl(var(--token))` syntax per globals.css.
Default context: dark mode (`.dark` on `<html>`).

| Role | HSL Token | Hex Reference | Usage |
|------|-----------|---------------|-------|
| Dominant (60%) | `--background: 240 10% 3.9%` | #09090B | Topbar background, bottom-nav background, overlay backdrop |
| Secondary (30%) | `--card: 240 10% 3.9%` / `--border: 240 3.7% 15.9%` | #09090B / #27272A | DropdownMenuContent surface, border separators |
| Accent (10%) | `--primary: 224 86% 60%` | #406EF1 | See reserved-for list below |
| Destructive | `--destructive: 0 62.8% 30.6%` | — | Destructive actions only (not present in this phase) |

**Accent reserved for (explicit list):**
1. Focus ring on LanguageToggle button — `--ring: 224 86% 60%` (established global pattern)
2. Active/selected language indicator in dropdown — `aria-checked` state: `text-[hsl(var(--primary))]` on the currently-selected language item

Accent is NOT used on: the badge text itself (uses `--foreground`), the overlay spinner, dropdown item default text, or the overlay background.

### LanguageToggle badge color specifics
- Badge background: `hsl(var(--muted))` — same as ThemeToggle button ghost background
- Badge text: `hsl(var(--foreground))` — no accent; the badge is informational, not a CTA
- Ghost button variant matches ThemeToggle exactly: `variant="ghost" size="icon"`

### TranslationLoadingOverlay color specifics
- Overlay backdrop: none — overlay is NOT a full-page block (source: CONTEXT.md D-07, specifics note)
- Spinner color: `hsl(var(--muted-foreground))` — subtle, does not compete with content
- If text label shown: `hsl(var(--muted-foreground))` at 14px / 400

## Component Inventory

### LanguageToggle

**Location:** `components/app-shell/language-toggle.tsx` (new file)
**Rendered in:** `components/app-shell/topbar.tsx` (alongside ThemeToggle) + `components/app-shell/bottom-nav.tsx` (mobile parity)
**Source decisions:** CONTEXT.md D-11, D-12

**Visual spec:**
- Button: `<Button variant="ghost" size="icon" aria-label="Switch language">` — identical variant and size as ThemeToggle
- Inside button: a 2-letter uppercase badge — `<span className="text-xs font-bold">EN</span>` (or PT / ES per current language)
- No Lucide icon — the 2-letter code IS the visual affordance (source: additional_context)
- Mounted guard: `const [mounted, setMounted] = useState(false)` + `useEffect(() => setMounted(true), [])` — renders `null` or a skeleton span until mounted to avoid SSR hydration mismatch with localStorage (mirrors ThemeToggle hydration pattern)

**Interaction behavior (cycle on click — Claude's discretion confirmed as cycle, not dropdown):**
- Click cycles: EN → PT → ES → EN
- On cycle: calls `setLanguage(next)` from `useLanguage()` context hook
- No dropdown. The 3-option cycle is deliberate: the toggle is a single-action button, not a menu. Rationale: only 3 languages, cycling is faster than opening a menu for a frequent toggle. If a dropdown is ever needed (4+ languages), this contract must be revisited.
- `aria-label` changes dynamically: `"Switch language: currently English"`, `"Switch language: currently Português"`, `"Switch language: currently Español"`

**Bottom-nav placement:**
- Appended after the last NAV_ITEM link in `BottomNav`
- Rendered as a button with the same `min-h-[44px] min-w-[44px]` wrapper already used by NAV_ITEM links
- Same ghost appearance — 2-letter badge centered, `text-muted-foreground` default, no active state highlight
- Does NOT have a label below the badge (unlike NAV_ITEMS which show a text label) — the 2-letter code is self-labeling

**States:**
| State | Visual |
|-------|--------|
| Default (EN) | Badge shows "EN", `text-foreground` |
| Default (PT) | Badge shows "PT", `text-foreground` |
| Default (ES) | Badge shows "ES", `text-foreground` |
| Hover | Ghost button hover background: `hsl(var(--accent))` (same as ThemeToggle) |
| Focus-visible | `ring-2 ring-[hsl(var(--ring))]` focus ring at 3px, color `#406EF1` |
| Pre-mount (SSR) | Renders empty button or `null` — no flash of wrong language code |

### TranslationLoadingOverlay

**Location:** `components/i18n/translation-loading-overlay.tsx` (new file)
**Rendered in:** A top-level wrapper inside the authenticated app layout — positioned near the LanguageToggle or as a fixed corner overlay
**Source decisions:** CONTEXT.md D-07, REQUIREMENTS.md I18N-07, specifics note ("subtle — spinner or shimmer text — NOT a full-page block")

**Visual spec:**
- Position: `fixed bottom-4 right-4 z-50` — bottom-right corner toast-style position. Does not block any content. Does not dim the page.
- Container: `flex items-center gap-2 px-3 py-2 rounded-[var(--radius-md)] bg-[hsl(var(--card))] border border-[hsl(var(--border))] shadow-md`
- Size: auto-width (fits content), max-width 200px
- Spinner: Lucide `Loader2` icon, `h-4 w-4 animate-spin text-[hsl(var(--muted-foreground))]`
- Text: `"Translating..."` — 14px / 400 / `text-[hsl(var(--muted-foreground))]`
- No backdrop, no overlay, no blur, no page block — this is a non-intrusive corner indicator

**Visibility logic:**
- Shown: when `isTranslating === true` (context flag set during first-session `/api/translate` fetch)
- Hidden: when `isTranslating === false` (default for EN users, and after first-session cache is populated)
- EN users: overlay never renders — `isTranslating` is always `false` for EN (source: CONTEXT.md D-02: EN returns text unchanged with zero overhead)
- Transition: `opacity-0 → opacity-100` fade-in over 150ms; `opacity-100 → opacity-0` fade-out over 150ms before unmount
- Implementation note: use CSS transition + conditional render with a small delay before unmount (150ms) for smooth exit

**Accessibility:**
- `role="status"` on the container
- `aria-live="polite"` — announces translation activity without interrupting the user
- `aria-label="Translating content"` on the container

**States:**
| State | Visual |
|-------|--------|
| Hidden (default, EN) | Not rendered |
| Fetching (first session, PT or ES) | Visible corner overlay: spinner + "Translating..." text |
| Complete (cache populated) | Fades out and unmounts |

## Interaction Flow

```
User clicks LanguageToggle (e.g. EN → PT)
  │
  ├─ setLanguage('pt') called
  ├─ localStorage.setItem('language', 'pt')
  ├─ LanguageContext re-renders consumers
  ├─ t() calls resolve via: session cache → static dict → /api/translate
  │
  ├─ If /api/translate needed:
  │   ├─ isTranslating = true → TranslationLoadingOverlay appears (150ms fade-in)
  │   ├─ Batched request fires after 50ms debounce
  │   ├─ Response populates session cache
  │   └─ isTranslating = false → overlay fades out (150ms) and unmounts
  │
  └─ If static dict covers all strings (expected for standard sessions):
      └─ No overlay shown — UI updates instantly
```

## Implementation Notes for Executor

1. **Match ThemeToggle exactly** — `LanguageToggle` must use `variant="ghost" size="icon"` and the same `cursor-pointer` className. Read `components/app-shell/theme-toggle.tsx` before implementing.
2. **Cycle, not dropdown** — Interaction is a single click to cycle EN → PT → ES → EN. No DropdownMenu is needed for LanguageToggle. The DropdownMenu component is available if the decision is revisited, but this contract specifies cycle-on-click.
3. **2-letter badge, not icon** — The button content is a text badge (`"EN"` / `"PT"` / `"ES"`), not a globe icon or flag. 12px / bold / foreground color.
4. **Mounted guard required** — `useState(false)` + `useEffect(() => setMounted(true), [])` before reading from `useLanguage()` context. Render `null` or a blank button until mounted to prevent SSR/hydration mismatch.
5. **Overlay is non-blocking** — `TranslationLoadingOverlay` must NEVER cover interactive content, dim the page, or prevent clicks. Position: `fixed` corner only. No backdrop.
6. **EN overhead is zero** — When `language === 'en'`, `t()` must return the input string unchanged with no cache lookup, no API call, and no overlay render. Test this explicitly.
7. **Bottom-nav placement** — In `components/app-shell/bottom-nav.tsx`, append LanguageToggle as the last item. It does not use the `NAV_ITEMS` array — it is a separate element rendered after the mapped items. Use the same `min-h-[44px] min-w-[44px]` touch target sizing.
8. **Tailwind arbitrary values** — Use `hsl(var(--token))` syntax, not hardcoded hex, per established project convention.
9. **Overlay mobile bottom offset** — On mobile, bottom-nav is 56px tall. Use `bottom-[calc(56px+1rem)]` or `bottom-20` to position the overlay above it.
10. **Font weight enforcement** — Only 400 (normal) and 700 (bold) used in this phase. The badge uses `font-bold` (700). Everything else uses default (400 / normal).
