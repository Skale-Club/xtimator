## Spacing Scale

Declared values (must be multiples of 4) — inherited from existing codebase tokens (`app/globals.css` `--radius-*` scale and Tailwind defaults already used by `tier-card.tsx`/`credit-balance-card.tsx`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. `AlertTriangle` + copy in low-balance banner) |
| sm | 8px | Compact spacing inside pack cards (badge offsets, inline gaps) |
| md | 16px | Default element spacing — form field stacks in the auto-top-up modal, card internal padding rhythm |
| lg | 24px | Section padding — grid gaps between the 3 pack cards (`gap-6` per `tier-cards-grid.tsx` precedent) |
| xl | 32px | Layout gaps — space between the manual top-up pack row and the auto-top-up settings card below it |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: none. Card padding uses the existing `Card` component default (`p-6` / `py-6` per `components/ui/card.tsx`) — do not override.

## Typography

Inherited from existing codebase type scale (`app/globals.css` `--font-size-*` tokens) — no new sizes introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--font-size-sm` / `text-sm`) | 400 (regular) | 1.25rem / 1.43 (`--line-height-sm`) |
| Label | 12px (`--font-size-xs` / `text-xs`) | 500 (`--font-weight-medium`) | 1rem (`--line-height-xs`) |
| Heading (card title) | 20px (`--font-size-xl` / `text-xl`) | 600 (`--font-weight-semibold`) | 1.75rem (`--line-height-xl`) |
| Display (price line) | 30px (`--font-size-3xl` / `text-3xl`, `font-mono`) | 600 (`--font-weight-semibold`) | 2.25rem (`--line-height-3xl`) |

Exactly 4 sizes, 2 weights (400 regular for body copy, 600 semibold for headings/price — matches `tier-card.tsx` exactly, where `CardTitle` and the price `<span>` both use `font-semibold`/`font-[var(--font-weight-semibold)]`). Price display uses `font-mono` + `tabular-nums` styling for dollar figures, consistent with `tier-card.tsx`'s price line and `money-input.tsx`'s `tabular-nums` convention.

## Color

Inherited from existing CSS variable theme (`app/globals.css`) — no new hex values introduced; all colors referenced via existing `hsl(var(--token))` CSS variables so tenant branding (`--platform-primary`) still cascades correctly.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(var(--background))` / glass surfaces (`--glass-bg`) | Page background, card surfaces (`Card variant="glass"`) |
| Secondary (30%) | `hsl(var(--muted))` / `hsl(var(--secondary))` | Card headers, feature-list text, non-selected pack cards, `--glass-border` outlines |
| Accent (10%) | `hsl(var(--primary))` (resolves to tenant `--platform-primary`) | Reserved for: (1) the selected/recommended pack's CTA button and top accent bar, (2) the "Auto top-up enabled" state indicator/badge, (3) the price figure emphasis color inherited from `tier-card.tsx`'s brand-gradient CTA, (4) focus rings on inputs inside the auto-top-up modal |
| Destructive | `hsl(var(--destructive))` | Reserved for: auto-top-up failure state text/icon ("Auto-top-up failed — update your payment method"), and the disable/turn-off confirmation affordance only. Never used for the pack cards themselves (no pack is "dangerous") |

Accent reserved for: the middle/recommended top-up pack's CTA button + its card's top accent edge (mirroring `tier-card.tsx`'s `pro` tier treatment — see Component Inventory below), the auto-top-up settings card's "enabled" badge/icon, and focus-visible rings on the threshold/amount/payment-method controls inside the auto-top-up modal. Accent is NOT used on the two non-recommended pack cards' CTAs (those use `outline` button variant, matching `tier-card.tsx`'s `free`/non-popular tier treatment) and NOT used anywhere in the auto-top-up card's default (collapsed, non-editing) resting state.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (manual top-up, per pack card) | `"Top up ${amount}"` — e.g. `"Top up $50"` (button label derived from `priceCents`, never a hardcoded literal — matches CONTEXT.md decision #3). Loading state: `"Redirecting…"` (matches existing `top-up-button.tsx` i18n string exactly). |
| Primary CTA (auto-top-up enable, first-time) | `"Enable auto-top-up"` |
| Primary CTA (auto-top-up manage, already enabled) | `"Manage"` (opens the settings modal — mirrors Anthropic Console's own "Manage" affordance per 153-CONTEXT.md §8) |
| Auto-top-up settings card heading | `"Auto top-up"` |
| Auto-top-up settings card body (enabled state) | `"Auto top-up is enabled. We'll add ${packAmount} when your balance drops below ${thresholdAmount}."` (both values interpolated from `company.auto_topup_pack_index` → `billing_config.topUpPacks[i].priceCents` and `company.auto_topup_threshold_credits`, never hardcoded) |
| Auto-top-up settings card body (disabled/off state) | `"Never run out mid-job. Turn on auto top-up to automatically add credits when your balance gets low."` |
| Auto-top-up settings card body (platform kill-switch off — `billing_config.autoTopupEnabled === false`) | Card does not render at all for the tenant (per CONTEXT.md decision #1 — the toggle only renders/functions when the platform switch is on). No copy needed; absence is the correct state. |
| Modal title | `"Manage auto top-up"` |
| Modal field: threshold | Label `"When balance drops below"`, helper text `"We'll check this every time credits are used."` |
| Modal field: purchase amount | Label `"Purchase this amount"`, rendered as the same 3-pack picker (radio-style, reusing the pack-card visual language at a smaller scale or a `Select` — see Component Inventory) |
| Modal field: payment method | Label `"Payment method"`; if none saved: `"No payment method on file. Add one to enable auto top-up."` + CTA `"Add payment method"` (routes to Stripe Customer Portal / setup flow per CONTEXT.md decision #3); if saved: `"Visa •••• 4242"`-style masked display (Stripe-provided `brand`/`last4`), non-editable inline — editing happens via the portal, not a custom form (CONTEXT.md: "never build a raw card-number input") |
| Modal footer CTA (save) | `"Save changes"` |
| Modal footer CTA (cancel) | `"Cancel"` |
| Modal footer CTA (turn off, only visible when currently enabled) | `"Turn off auto top-up"` (styled `variant="outline"`, text `text-destructive`, positioned separate from Save/Cancel — a settings change, not a data-loss action, so it does NOT open a second confirmation dialog; see Destructive confirmation row below for the reasoning) |
| Empty state (no payment method, manual top-up entry point) | Heading: n/a (inline, not a full empty state) — Body: `"You'll be redirected to a secure Stripe checkout to complete this purchase."` shown only if helpful; otherwise manual top-up needs no empty state since `TopUpButton` always redirects to Stripe Checkout regardless of saved payment method. |
| Error state — manual top-up checkout fails to start | `"Could not start top-up. Please try again."` (existing string, verbatim reused from `top-up-button.tsx` — do not diverge) |
| Error state — auto-top-up charge fails (surfaced on next low-balance view) | `"Auto-top-up failed — update your payment method to keep it active."` with CTA `"Update payment method"` (opens the same Manage modal, payment-method section focused) |
| Error state — auto-top-up save fails (validation, network) | `"Could not save auto top-up settings. Please try again."` |
| Destructive confirmation | **Turning off auto-top-up:** no separate confirmation dialog — it is a reversible settings toggle (re-enabling costs nothing), so the modal's own `"Turn off auto top-up"` button commits immediately on click, then closes the modal and toasts `"Auto top-up turned off."` This mirrors the codebase's existing precedent: `handoff-button.tsx`'s Dialog has no secondary "are you sure" step for its own action either — the Dialog itself IS the confirmation gate. There is no other destructive action in this phase (manual top-up is an additive purchase, not destructive). |

## Component Inventory

Explicit mapping from CONTEXT.md's required UI surfaces to concrete components — all reuse existing `components/ui/*` primitives, no new base components needed.

### 1. Manual top-up pack picker (CREDITUI-06)

Replaces the single `<TopUpButton packIndex={0}>` line inside `credit-balance-card.tsx`'s low-balance warning block, AND (new) lives as its own always-visible section on Settings > Plans (not gated behind the low-balance warning — a tenant should be able to top up proactively, not just when already low).

- **Container:** new component `components/billing/topup-packs-grid.tsx`, structurally mirroring `tier-cards-grid.tsx` (`<div className="mx-auto grid w-full max-w-5xl grid-cols-1 gap-6 sm:grid-cols-3">` — 3 columns since there are exactly 3 packs, no responsive 2-col step needed at this card count).
- **Card:** new component `components/billing/topup-pack-card.tsx`, structurally mirroring `tier-card.tsx` but simplified (no annual/monthly toggle, no "current plan" state, no features list — packs are not mutually exclusive with each other, any can be bought any time):
  - `Card variant="glass"` (not `stat` — no pack is inherently "the current plan", but see next bullet for the recommended-pack accent treatment)
  - The middle pack ($50) gets the `Badge variant="brand"` "Most popular"-style pill reused verbatim as `"Best value"` (positioned `absolute -top-3 left-1/2 -translate-x-1/2` exactly as `tier-card.tsx` does for `popular`), plus the same 3px `before:` gradient-brand top accent edge — this is the ONE accent-colored element among the three cards.
  - Price line: `<span className="font-mono text-3xl font-semibold tracking-tight">${amount}</span>` where `amount = priceCents / 100`, formatted with no decimals (`$20`, `$50`, `$100`) — matches `tier-card.tsx`'s price line styling exactly, reusing the same font-mono/text-3xl/font-semibold classes.
  - Sub-line under price: `"≈ {credits.toLocaleString()} credits"` in `text-sm text-muted-foreground` — credits shown as a secondary reference number only, never the primary label (CONTEXT.md decision #2: dollar amount is primary).
  - CTA: the existing `TopUpButton`, re-labeled. `top-up-button.tsx` needs its hardcoded `"Top up credits"` string parameterized to accept a `label` prop so each card can render `"Top up $20"` / `"Top up $50"` / `"Top up $100"` — button variant is `outline` for the two non-recommended packs, `primary` (gradient-brand) for the $50 recommended pack, matching `tier-card.tsx`'s `buttonVariant` ternary pattern.
- **Placement in `credit-balance-card.tsx`:** the low-balance warning block's existing `<Link href="/settings/billing?topup=1"><TopUpButton packIndex={0} /></Link>` line is removed; the warning's CTA becomes just `"Top up now"` (a plain anchor/button scrolling to or linking to the new pack grid section), since the full 3-card picker is too wide for the inline warning banner. The full `TopUpPacksGrid` renders as its own section on the Settings > Plans page, below the usage progress bar (Phase 152) and above (or beside) the new Auto Top-Up settings card.

### 2. Auto-top-up settings card (CREDITUI-07, collapsed/resting state)

New component `components/billing/auto-topup-card.tsx`, rendered on Settings > Plans, directly below the `TopUpPacksGrid`. Only rendered server-side when `billing_config.autoTopupEnabled === true` (platform kill switch) — otherwise this whole card is omitted from the tree, not rendered-disabled.

- `Card variant="glass" className="p-6"` — structurally identical container pattern to `credit-balance-card.tsx` (`CardHeader` with icon + `CardTitle`/`CardDescription`, then `CardContent`).
- Icon: `RefreshCw` or `Zap` (lucide-react) in the header, colored `text-[hsl(var(--primary))]` — matching `CreditCard` icon treatment in `credit-balance-card.tsx`.
- `CardTitle`: `"Auto top-up"`. `CardDescription`: dynamic per enabled/disabled copy (see Copywriting Contract).
- **Enabled state body:** shows the interpolated sentence + a small `Badge variant="brand"` reading `"On"` next to the title (in `CardAction` slot, top-right — reuses `CardAction` primitive already in `card.tsx`), plus the masked payment-method line, plus the `"Manage"` button (`variant="outline" size="sm"`).
- **Disabled state body:** shows the pitch copy + a single `"Enable auto-top-up"` button (`variant="primary" size="sm"`) that opens the same modal directly into "setting up" mode.

### 3. Auto-top-up management modal (CREDITUI-07, editing state)

New component `components/billing/auto-topup-dialog.tsx`, following the exact `Dialog`/`DialogContent`/`DialogHeader`/`DialogFooter` structural precedent of `app/admin/companies/handoff-button.tsx` (the explicitly named precedent in the task's `<primary_reference>`):

- `<Dialog open={open} onOpenChange={...}>` + `<DialogContent className="sm:max-w-md glass-strong border border-[var(--glass-border)]">` — one step wider than `handoff-button.tsx`'s `sm:max-w-sm` since this form has 3 fields instead of 1.
- `DialogHeader` > `DialogTitle` with icon prefix (`RefreshCw` or matching card icon) + `"Manage auto top-up"`, `DialogDescription` (visually hidden via `sr-only`, matching `handoff-button.tsx`'s pattern) stating the modal's purpose for screen readers.
- Form body (`space-y-4`, matching `handoff-button.tsx`'s form spacing):
  - **Threshold field:** `Label` + a dollar-denominated input. Use the existing `MoneyInput` component (`components/ui/money-input.tsx`) bound to a dollar value, NOT `auto_topup_threshold_credits` directly — the credits column is a derived/stored value, but the UI is dollar-first per CONTEXT.md's explicit "mirror Anthropic Console: threshold + amount, both in dollars" instruction. Convert dollars→credits at the server action boundary, not in the component.
  - **Purchase amount field:** `Label` "Purchase this amount" + a `Select` (`components/ui/select.tsx`) with exactly 3 options, one per configured pack, each rendered as `"$20 (≈1,300 credits)"` — reuses the same derived-label pattern as the pack cards, not a free `Select` of arbitrary values (CONTEXT.md: exactly 3 configured packs, no free entry).
  - **Payment method field:** read-only masked display row (`brand` + `last4` from Stripe) if a payment method exists, OR an `"Add payment method"` button if not — this button navigates to (or opens) the Stripe-hosted setup flow (Customer Portal or a `mode: 'setup'` Checkout Session per CONTEXT.md decision #3), it does NOT render any local card form fields.
  - Loading/pending states use the existing `Loader2` spin + disabled-button pattern from `handoff-button.tsx` verbatim (`<Loader2 className="h-4 w-4 animate-spin mr-2" />` inside the submit button while pending).
- `DialogFooter`: `"Cancel"` (`variant="outline"`) + `"Save changes"` (`variant="default"`, disabled while pending or while no payment method is on file) — and, only when editing an already-enabled config, a left-aligned or visually separated `"Turn off auto top-up"` (`variant="outline"` + `text-destructive` className override) per the Copywriting Contract's Destructive confirmation row.

### 4. Failure state surfacing

Reuses the existing `Alert`/`AlertTitle`/`AlertDescription` (`components/ui/alert.tsx`) with `variant="destructive"`, rendered inside `auto-topup-card.tsx` above the normal body content when the company's last auto-top-up attempt failed (server-supplied flag) — icon `AlertTriangle` (lucide-react, already imported elsewhere in `credit-balance-card.tsx`), matching that file's existing amber-warning visual weight but using the `destructive` token since this is a failed charge, not merely a heads-up.
