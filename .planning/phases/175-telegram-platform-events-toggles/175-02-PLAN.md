<objective>
Wire the 4 net-new platform events into `notifyOps()` as additive sibling calls: tenant signup, the TWO distinct payment flows (customer→tenant via Stripe Connect, and tenant→Xtimator via the platform subscription webhook), and quota exhaustion — the last of which requires reviving `notifyQuotaThresholds()`, which has had no production caller since Phase 77.

Purpose: Plan 01 built the typed 10-kind catalog and the toggle-respecting gate; nothing calls it yet for these business events. This is the "every cataloged platform event routes through notifyOps()" half of PLAT-01. Distinguishing `tenant_payment_received` (a customer paying a tenant) from `subscription_payment_received` (a tenant paying Xtimator) matters because they are different audiences' money moving through different Stripe webhook arms — collapsing them into one kind would make the admin toggle matrix and the Telegram feed both misleading.
Output: 4 new `notifyOps()` call sites (additive, fire-and-forget, mirroring the 260705-c1y precedent) + one dead-code revival (`notifyQuotaThresholds()` gains a real caller) + test-safety mocks so none of this risks a real Supabase/Telegram/Redis round-trip when running tests locally.
</objective>
