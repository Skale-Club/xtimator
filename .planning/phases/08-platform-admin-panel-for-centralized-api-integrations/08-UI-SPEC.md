# Phase 8 — UI Design Contract

> Visual and interaction contract for the Platform Admin Panel (`/admin/integrations`, `/admin/branding`, `/admin/admins`) and the scoped dark refresh of `/(auth)/*` routes. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | new-york, neutral base, CSS variables |
| Component library | Radix UI primitives |
| Icon library | Lucide |
| Font | Inter (variable `--font-inter`) |

**Scope note:** Two distinct surfaces ship in this phase.

1. **Platform Admin Shell** (`/admin/*`) — scoped DARK theme via `[data-theme="admin-dark"]` attribute on the `app/admin/layout.tsx` wrapper.
2. **Auth Dark Pass** (`/(auth)/*`) — scoped DARK theme via `[data-theme="dark-auth"]` attribute on the `app/(auth)/layout.tsx` wrapper.

Both scoped themes override the same CSS vars defined in `globals.css`. The main tenant app (`(app)`) remains LIGHT and untouched (global dark-mode toggle stays deferred to V2-06 per D-20).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, badge padding, helper-text gap |
| md | 16px | Default element spacing, form field gaps, card header → content gap |
| lg | 24px | Card padding, nav item vertical rhythm |
| xl | 32px | Section breaks between cards, admin page top padding |
| 2xl | 48px | Gap between logo/wordmark and auth card |
| 3xl | 64px | Not used in this phase |

**Exceptions:**
- Password-masked integration input: right padding is 80px (not a scale token) to accommodate the show/hide toggle + Test button icon stack.
- Admin left-nav width: 240px fixed (not a scale token, standard nav rail dimension).
- Auth card stays at existing `max-w-[400px]`; admin cards are `max-w-[560px]` to fit key inputs without overflow.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.15 |

Inherits from Phase 2 and Phase 7 settings patterns. Four roles total — within the 3-4 role cap.

**Usage:**
- **Display** — auth wordmark (the `{app_name}` loaded from `getBranding()`, replaces the hardcoded "EstimateBuilder Pro" string).
- **Heading** — page `<h1>` on each admin page ("Integrations", "Branding", "Admins"); auth page card title ("Sign in", "Create account", "Reset password").
- **Label** — form field labels, "Last updated" badge label, nav item label, status badge text. Differentiated from Body via `text-muted-foreground` color and (where appropriate) `tracking-wide uppercase` styling.
- **Body** — form input text, helper text, description paragraphs, provider name under integration card header.

**Monospace exception:** masked API key preview (bullet chars + last 4 chars when collapsed) uses `font-mono` at 14px — this is a CSS utility, not a separate type role. Primary color `#0D9488` hex label in branding form also uses `font-mono` — inherited from `company-info-form.tsx:332`.

## Color

Three color contracts apply in this phase. Each must be declared separately because the scoped themes override the same tokens.

### 1. Main App (LIGHT — unchanged, for reference only)

Inherits the existing `:root` palette from `app/globals.css` lines 4–25. No changes this phase.

### 2. Admin Shell (scoped `[data-theme="admin-dark"]`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(240 6% 6%)` (zinc-950) | Full admin viewport background |
| Secondary (30%) | `hsl(240 4% 11%)` (zinc-900) | Admin cards, left-nav surface, inputs |
| Accent (10%) | `hsl(var(--platform-primary, 220 91% 60%))` | Primary action buttons ("Save", "Test", "Add Admin"); active left-nav item background tint (12% alpha); focus rings |
| Destructive | `hsl(0 62.8% 45%)` (dark-adjusted `--destructive`) | "Remove admin" button; "Delete key" action; error toast border |

**Accent reserved for:** Save button on each admin form, Test button on each integration card, Add Admin button in `/admin/admins`, active nav-item background highlight (8–12% alpha of primary), input focus ring, and "Success" status of Test button result. Nothing else.

**`--platform-primary` is pulled from `getBranding().primary_color`** via CSS custom property set inline on the admin layout wrapper. Fallback `220 91% 60%` (blue-500) applies if branding row has `primary_color = null`.

### 3. Auth Dark Pass (scoped `[data-theme="dark-auth"]`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(240 6% 6%)` (zinc-950) | Full auth viewport background |
| Secondary (30%) | `hsl(240 4% 11%)` (zinc-900) | Auth card surface, input background |
| Accent (10%) | `hsl(var(--platform-primary, 220 91% 60%))` | "Sign in" / "Create account" / "Reset password" primary button; inline link colors (`Forgot your password?`, `Sign up`); input focus ring |
| Destructive | `hsl(0 62.8% 45%)` | `<Alert variant="destructive">` error border and text |

**Accent reserved for:** the single primary submit button on each auth page, the inline anchor links below the card, and input focus rings. The Google OAuth button does NOT use accent — see D-21 below.

**Google OAuth button variant for dark bg (D-21):**
- Background: transparent
- Border: 1px solid `hsl(240 4% 20%)` (zinc-800)
- Text: `hsl(0 0% 98%)` (zinc-50)
- Hover: background `hsl(240 4% 16%)` (zinc-900 lifted)
- Google "G" logo retains its full-color brand marks (no monochrome filter)

**Dark-surface card border:** 1px solid `hsl(240 4% 20%)` (zinc-800). Shadow omitted on dark surfaces — borders do the work.

**Contrast (WCAG AA verified):**
- Foreground `hsl(0 0% 98%)` on `hsl(240 6% 6%)` background → 18.7:1 (AAA)
- Foreground `hsl(0 0% 98%)` on `hsl(240 4% 11%)` card → 16.0:1 (AAA)
- Muted-foreground `hsl(240 5% 65%)` on `hsl(240 4% 11%)` card → 6.8:1 (AA+)
- Primary-foreground `hsl(0 0% 100%)` on `hsl(220 91% 60%)` button → 4.6:1 (AA) — meets threshold for UI components.

**Nav dimensions:**
- Rail width: 240px (fixed)
- Rail padding: 24px top, 16px sides, 24px bottom
- Logo block: 40×40 logomark + 14px wordmark, gap 8px, margin-bottom 32px
- Nav items: 44px tall each (matches UX-02 44px min touch target), 4px vertical gap
- Sign-out block: positioned at `mt-auto`, top border separator 1px

**Main content:**
- Max width 720px, centered horizontally (admin pages are narrow forms)
- Top padding 32px, bottom padding 48px, horizontal padding 32px
- Page h1 → description → 32px gap → Card stack (24px vertical gap between cards)

### Mobile Behavior (admin)

- Left-nav collapses to a `Sheet` drawer triggered by a hamburger icon in a 56px top bar

Deferred polish (not in v1 DoD): sticky top bar with scroll-aware hide, mobile-optimised list-view for `/admin/admins`.

## Interaction Contract

### `/admin/integrations`

| Action | Behavior |
|--------|----------|
| Page load | Server loads current `platform_integrations` rows. Ciphertext NEVER leaves server (ADMIN-14); UI shows `••••••••••••{last4}` placeholder + "Connected" badge if row exists, else empty input + "Not configured" badge. |
| Focus masked input | Eye toggle and clear (X) button fade in. Input clears placeholder dots on focus. |
| Click show/hide eye | Toggle `type="password"` ↔ `type="text"` on the input. Never toggles for the server-side value — only the locally-typed new value. |
| Click Save | Client form validates non-empty. Server action encrypts, upserts, calls `invalidatePlatformConfig()`. Success toast "Resend key saved." Status badge flips to "Connected", Last updated timestamp refreshes, input re-masks. |
| Click Test | Triggers provider-specific verification server action. Loading spinner on button. Resend: sends a real verification email to the current admin's email ("Check your inbox at `{admin.email}`"). Anthropic: 1-token completion call ("Responded in {n}ms"). OpenAI: `/models` list call ("Found {n} models available"). Result renders as inline Alert directly below the button. |
| Click Delete key | Opens `AlertDialog` "Delete {provider} key? Features that use this provider will stop working immediately." Confirm → server action DELETEs row + invalidates cache + toast "Key removed." Status badge flips to "Not configured", input returns to empty state. |

### `/admin/branding`

| Action | Behavior |
|--------|----------|
| Page load | Loads singleton `platform_branding` row. Form pre-filled with current values. Live preview card pre-rendered with current colors/logo. |
| Edit app_name | Preview wordmark updates on debounced input (200ms). Validation: required, min 1 char, max 64 chars. |
| Upload logo | Reuses `logo-uploader.tsx` verbatim (D-11). 2MB limit, PNG/JPG/WebP accepted. Preview card updates immediately via objectURL. |
| Change primary color | Color picker + hex input (reuses `company-info-form.tsx:320-335` pattern). Preview card updates instantly as user types. Invalid hex → form error "Enter a 6-digit hex like #0D9488" (matches Phase 2 copy). |
| Edit email_from_name | Simple text input with helper text "Sender name shown in platform emails (welcome, password reset). Client-facing estimate emails use your company name per tenant." |
| Click Save | Server action uploads new logo to `platform-brand/` bucket if File present, upserts row, invalidates loader cache. Success toast "Branding updated." Preview remains; cached server components (wordmark on auth, title tag) pick up change within 60s cold-start window or immediately on same-instance invalidation. |

### `/admin/admins`

| Action | Behavior |
|--------|----------|
| Page load | Lists all rows from `platform_admins` joined to `auth.users` for email/created_at. |
| Click "Add admin" | Opens `Dialog` with single email input + "Add" button. |
| Submit add form | Server action looks up user by email (service role). If no user: error inline "No user registered with that email. Ask them to sign up first." If user exists + is already admin: error "Already an admin." Otherwise insert + toast "{email} added as platform admin." |
| Click "Remove" on row | If row.user_id === currentUser AND admins.length === 1: button is disabled with tooltip "You are the only admin. Add another admin before removing yourself." Otherwise opens `AlertDialog` "Remove {email} as platform admin?" → confirm → server action DELETE. If DB trigger throws (last-admin guard), catch and toast "Cannot remove the last platform admin." |

### Auth Dark Pass (visual-only changes)

No new interactions. Every existing auth behavior (login, signup, reset-password, OAuth redirect) is preserved. Only visual tokens change.

Special handling for `/auth/callback` (R-10): inherits the `(auth)` dark layout so the brief "Signing you in…" render doesn't flash light.

### Key-Missing UX (tenant app, per D-15 / ADMIN-11)

| Feature | Tenant-side behavior when key is null |
|---------|---------------------------------------|
| "Generate Estimate" | Button rendered disabled. `<Tooltip>` on hover: "AI estimate generation isn't available right now. Contact your platform administrator." Already shipped for Resend in commit `3492264`; extend pattern to all 3 providers. |
| "Send via Email" | Button rendered disabled. Tooltip: "Email sending isn't available right now. Use 'Download PDF' and send manually, or contact your platform administrator." |
| Audio transcribe (OpenAI Whisper) | Recording UI still functions; after stop, inline `<Alert>` "Audio transcription isn't available right now. Contact your platform administrator. You can still save and manually transcribe this recording." |

**Never expose "admin email" in v1** — would leak PII. Copy says "Contact your platform administrator" generically.

## Accessibility

| Requirement | Implementation |
|-------------|----------------|
| Masked key input | Input `type="password"` by default; show/hide button `aria-label="Show API key"` / `"Hide API key"`; input `aria-describedby` points to Last-updated footer |
| Test button | `aria-busy="true"` during loading; `aria-live="polite"` region wraps the result Alert so SR announces success/error |
| Form validation (all admin forms) | `aria-invalid="true"` + `aria-describedby` linking error message (inherits FormMessage pattern) |
| Delete / Remove confirmations | `AlertDialog` from shadcn; destructive button gets `aria-label="Confirm delete"` |
| Admin nav | `<nav aria-label="Platform admin navigation">`; active item has `aria-current="page"` |
| Auth dark wrapper | `[data-theme="dark-auth"]` is attribute only — no `role` change; screen-reader semantics identical to light version |
| Focus rings on dark | `--ring` resolves to `--platform-primary` at full saturation — high-contrast on dark bg. Auto-applied by shadcn Input/Button. Verified visually against both a default blue-500 primary and a worst-case dark-primary (e.g., black) — if primary_color has < 3:1 contrast against card bg, fall back to ring `hsl(0 0% 80%)`. |
| Color picker | Native `<input type="color">` has OS-level accessibility; hex text input provides keyboard alternative |
| Logo fallback | When `branding.logoUrl` is null, inline SVG logomark renders with `aria-hidden="true"` (the wordmark provides the accessible name) |
| Keyboard navigation | All interactive elements reachable via Tab; Escape closes Dialog/AlertDialog |
| Reduced motion | No decorative animations in this phase. Skeleton shimmer uses Tailwind `animate-pulse` which respects `prefers-reduced-motion` via shadcn defaults |
