<objective>
Close the rebrand loop and the env-var coupling. After this plan:
- No code file (except `lib/platform-config.ts`) reads `process.env.RESEND_API_KEY` / `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` directly.
- No code file contains the literal "EstimateBuilder Pro" (tests in `tests/e2e/auth.spec.ts` are updated to read the expected app name from an env-driven fixture).
- Two grep-assertion unit tests enforce this going forward.

This plan is **Wave 4** and depends on:
- Plan 02 (`lib/platform-config.ts` loader + `getIntegrationKey`/`getBranding`).
- Plan 04 (Integrations admin page — means an admin can configure keys BEFORE this sweep makes the app depend on DB-stored keys in prod).
- Plan 07 (auth tree already branding-swept — reduces surface area here).

The plan is **not autonomous** because it ends with a `checkpoint:human-verify` that exercises the migrated call sites end-to-end (generate estimate, send email, transcribe audio) against real API keys configured via the admin UI.
