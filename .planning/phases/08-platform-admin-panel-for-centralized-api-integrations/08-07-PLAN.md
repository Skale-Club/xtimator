<objective>
Apply the scoped dark visual pass to all `/(auth)/*` routes and migrate `components/auth/auth-card.tsx` + `components/auth/google-oauth-button.tsx` to consume branding from the loader instead of hardcoded strings and SVGs — satisfies ADMIN-07 partial coverage (auth tree) and ADMIN-12 (dark pass).

**Known codebase state (grep-confirmed):** `app/(auth)/login/page.tsx`, `app/(auth)/signup/page.tsx`, and `app/(auth)/reset-password/page.tsx` all start with `'use client'` today. To call `await getBranding()` (server-only), we MUST split each into:
1. A server component `page.tsx` that fetches branding and renders `<AuthCard branding={...}><XxxForm /></AuthCard>`.
2. A new `xxx-form.tsx` client component that owns the interactive form state (moved from the current page).

This split is captured in `files_modified` (new `login-form.tsx`, `signup-form.tsx`, `reset-password-form.tsx`).

This plan runs parallel to Plans 04/05/06 in Wave 3. They do not touch the same files: Plans 04/05/06 write `/admin/*`, this plan writes `/(auth)/*` and its shared components. The branding-sweep of `app/layout.tsx`, `onboarding-card.tsx`, `share/estimate-view.tsx`, and the two email/PDF call sites is deferred to Plan 08 (the env+branding sweep).

Purpose: The rebrand from "EstimateBuilder Pro" → "Xtimator" begins visible here: once this plan ships, every auth page already shows the new name via the loader. Plan 08 finishes the sweep across the rest of the codebase.

Output:
- New `app/(auth)/layout.tsx` — server component that sets `[data-theme="dark-auth"]` + `--platform-primary` + wraps children in dark bg.
- Refactored `auth-card.tsx` — takes `branding` prop, logo fallback, wordmark from prop.
- Refactored `google-oauth-button.tsx` — dark-variant styling.
- Three page-form splits (`page.tsx` = server, `*-form.tsx` = client).
- Callback page inherits dark layout (R-10 fix).
- One e2e spec confirming the data-theme attribute is present.
</objective>
