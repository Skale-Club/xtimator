<objective>
Build the CUST-01 send primitive: a Resend-calling function for end-customer email whose sender identity is always the honest, non-deceptive `{{business_name}} via Xtimator` friendly-from — never a bare business name (which could impersonate the tenant with no indication a platform is involved) and never bare "Xtimator" (which would hide whose message it actually is).

Purpose: This is the email-side sibling to `lib/sms/client.ts`'s `sendSms()` — a small, isolated, never-throwing dispatch primitive with no template/audit logic inside it (that lives in 177-06's orchestrator). Keeping it isolated means the "honest sender identity" rule lives in exactly one function (`customerEmailFrom`) that both this primitive and any future caller must go through.
Output: `customerEmailFrom()` + `sendCustomerEmail()`, unit-tested against a mocked Resend client (mirrors `tests/unit/notifications/account-emails.test.ts`'s mocking convention).
</objective>

  html: string

  ok: boolean
  id?: string
  error?: string
}

Contract: empty `toEmail` -> `{ ok: false, error: 'no_recipient' }`, no Resend call. No Resend key configured (`getIntegrationKey('resend')` -> falsy) -> `{ ok: false, error: 'resend_unconfigured' }`, no Resend call, `console.warn`. Resend responds with an `error` -> `{ ok: false, error: <message> }`. Resend throws/rejects -> caught, `console.warn`, `{ ok: false, error: 'send_failed' }`. Success -> `{ ok: true, id: data.id }`.
