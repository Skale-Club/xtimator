New `lib/notifications/customer-send.ts` — the exact shape 177-07 and Phase 178 will import:
```ts
export type TriggerSource = 'manual' | 'agentic-whatsapp' | 'agentic-mcp'

export interface SendCustomerMessageParams {
  permit: SendPermit
  companyId: string
  clientId: string // MUST equal permit.clientId — checked, not assumed
  businessName: string
  triggerSource: TriggerSource
  // Exactly one of template | freeform must be provided.
  template?: { eventType: CustomerEventType; vars: CustomerCopyContext }
  freeform?: { subject?: string; body: string }
}

export interface SendCustomerMessageResult {
  ok: boolean
  channel: SendChannel
  providerMessageId?: string
  error?: string
}

export async function sendCustomerMessage(params: SendCustomerMessageParams): Promise<SendCustomerMessageResult>
```

Internal flow (LOAD-BEARING order):
1. `params.permit.clientId !== params.clientId` -> `{ ok: false, channel: params.permit.channel, error: 'permit_client_mismatch' }` (no dispatch, no DB fetch, no log — this is a caller bug, not a customer send attempt).
2. Neither `template` nor `freeform` provided -> `{ ok: false, channel, error: 'no_content' }`.
3. Fetch the client's `email, phone, name` from `clients`, scoped by `id = clientId AND company_id = companyId` (service client — mirror the tenant-scope defense-in-depth already established in `customer-send-gate.ts`).
4. `channel === 'email'` and no client email on file -> `{ ok: false, channel, error: 'no_recipient_email' }`. `channel === 'sms'` and no client phone -> `{ ok: false, channel, error: 'no_recipient_phone' }`. (Neither of these logs to `customer_messages` — no dispatch was attempted.)
5. Resolve `subject`/`body`: `template` -> `resolveCustomerCopy(eventType, channel, { ...vars, businessName: vars.businessName ?? params.businessName, clientName: vars.clientName ?? client.name })`; `freeform` -> use `params.freeform.subject`/`.body` as-is.
6. Dispatch: `channel === 'email'` -> `sendCustomerEmail({ toEmail: client.email, toName: client.name, businessName: params.businessName, subject: subject ?? \`A message from ${params.businessName}\`, html: body, text: stripHtmlTags(body) })` (write a tiny `stripHtmlTags` helper — regex-strip `<[^>]+>` + collapse whitespace — so Resend always gets a sane plain-text alternative even when `body` is the HTML fallback copy from 177-05). `channel === 'sms'` -> `sendCustomerSms(client.phone, body)`.
7. Call `logCustomerMessage(...)` with `provider: channel === 'email' ? 'resend' : 'twilio'`, `status: dispatchResult.ok ? 'sent' : 'failed'`, `isTemplate: Boolean(params.template)`, `templateEventType: params.template?.eventType ?? null` — THIS RUNS FOR EVERY STEP-6 DISPATCH ATTEMPT, success or failure (steps 1/2/4 short-circuit before this and do NOT log — they never reached a dispatch attempt).
8. Return `{ ok: dispatchResult.ok, channel, providerMessageId: dispatchResult.id ?? dispatchResult.sid, error: dispatchResult.error }`.

Whole function wrapped in try/catch — never throws; an unexpected exception resolves `{ ok: false, channel: params.permit.channel, error: 'unexpected_error' }`.
