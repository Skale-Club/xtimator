<objective>
Close the SINGLE explicitly-recorded Phase-177 prerequisite from 176-VERIFICATION.md: migrate `app/api/estimates/[id]/send-sms/route.ts` — the one and only end-customer-facing `sendSms()` call site in the codebase (confirmed by a repo-wide grep during planning: the only other `sendSms(` callers are the tenant-scoped notification dispatcher and the super-admin template test-send, neither of which target an end customer) — onto the gate and the new dedicated-Messaging-Service send path.

Purpose: This route sends an estimate share link via SMS directly to a project's linked client — i.e. it IS an end-customer send, and today it has zero consent/suppression/quiet-hours check and rides the shared owner number. Both of those are exactly what this milestone exists to fix. Per 176-VERIFICATION.md: "no legacy bypass may remain."
Output: The route now (1) resolves the estimate's linked client, (2) refuses to proceed if the request's destination number doesn't match that client's on-file number (closing an implicit bypass: an arbitrary `to` override could previously target ANY number regardless of whose consent was checked), (3) calls `assertSendAllowed()`, (4) dispatches via `sendCustomerMessage()` on the dedicated Messaging Service, (5) keeps the existing `estimate_deliveries` bookkeeping (estimate-specific, unrelated concern) sourced from the new result shape.
</objective>
