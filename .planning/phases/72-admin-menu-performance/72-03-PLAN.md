<objective>
Fix two database query anti-patterns that cause slow page loads:
1. `lib/admin/integrations-providers.ts` `loadCategoryInitials()` — replace N+1 `getUserById()` calls (one per integration row) with a batch lookup: collect unique `updated_by` user IDs, call `getUserById` once per unique ID (typically 1-2 across all integrations), build a Map, look up from the Map in the decrypt loop
2. `app/admin/admins/page.tsx` — replace `listUsers({ perPage: 1000 })` with `getUserById(row.user_id)` for each platform_admins row (typically 1-5 calls instead of fetching up to 1000 users)

Purpose: The integrations page makes N auth API calls inside Promise.all where N = number of configured integrations. Since updatedByEmail is typically the same 1-2 admins across all integrations, this is pure waste. The admins page fetches 1000 users to build an email lookup for 1-5 admin rows — equally wasteful. Research confirmed: platform_admins has 1-5 rows — paginating 5 rows adds complexity with zero perf benefit. getUserById per admin row (O(n) where n≤5) is the correct approach.

Output: 2 modified files with bounded, efficient auth API usage.
</objective>
