# 193-03 — Engagement dashboard + click heatmap

**Goal:** the owner opens an estimate in the workspace and immediately sees whether the
client is interested: opens, unique visitors, time spent, how far they read, what they
clicked — including a visual heatmap over the actual estimate document.

## Task 1 — Query layer `lib/queries/engagement.ts`

Authenticated (normal RLS path — the 193-01 SELECT policy makes company-scoped reads work
with the user client; no service role needed here):

- `getEstimateEngagementSummary(estimateId)` → one aggregate query:
  `opens` (count of `view`), `unique_visitors` (distinct `visitor_id`),
  `last_viewed_at`, `total_seconds` (sum of heartbeat metadata), `max_scroll_pct`,
  `sections_viewed` (distinct targets), `clicks`, `device_split`, `unlock_fails`.
- `getEstimateClickPoints(estimateId)` → `[{ x_pct, y_px, doc_h, target }]` for `click`
  events, capped at 2000 rows, newest first.
- `getEstimateViewTimeline(estimateId)` → per-session rollup (session_id, started_at,
  seconds, device, max scroll) for a "visits" list.

Prefer plain Supabase queries + TS aggregation over a SQL view unless row counts make it
slow (they won't at this stage; note it in deferred-items if revisited).

- "View click heatmap" entry opening the Task 3 dialog.

## Task 3 — Heatmap `components/workspace/estimate/engagement-heatmap.tsx`

Pragmatic overlay, no external heatmap lib:

- Dialog (full-height scroll area) rendering the estimate through the **same template
  renderer** used by the share page (via `lib/estimate/templates/registry.ts`), read-only,
  inside a container of known width `W`.
- Absolutely-positioned `<canvas>` over the document container. For each click point:
  `x = x_pct/100 * W`, `y = y_px * (renderedDocHeight / doc_h)` — the per-event `doc_h`
  makes the y-scale robust across template/viewport differences. Draw radial-gradient
  blobs (r≈28px, low alpha, `globalCompositeOperation:'lighter'`) → density emerges from
  overlap; recompute on container resize (ResizeObserver).
- Fallback aggregate: per-section click counts (bar list by `target`) shown beside the
  canvas — this stays meaningful even when coordinate scaling is imperfect for a visitor
  whose viewport differed wildly (mobile events: offer a mobile/desktop filter toggle,
  since coordinates from the two device classes shouldn't blend).
