# Phase 154 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase is a near-verbatim RELOCATION of already-shipped UI (`app/admin/whatsapp/page.tsx` → `/admin/inbox`, accounts + templates → `/admin/inbox/settings`). Every value below is pre-populated from the existing codebase (154-CONTEXT.md + direct reads of `app/admin/whatsapp/page.tsx`, `app/admin/legal/page.tsx`, `components/ui/tabs.tsx`, `components/ui/card.tsx`, `components/admin/admin-nav.tsx`, `app/globals.css`) — nothing here is a new design decision except where explicitly marked "New in this phase."

## Spacing Scale

Declared values (must be multiples of 4) — matches the existing admin page convention observed in `app/admin/whatsapp/page.tsx`, `app/admin/companies/page.tsx`, `app/admin/legal/page.tsx`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap in nav items (`gap-3` container, icon `size={16}`) |
| sm | 8px | Tab trigger internal gap, badge padding |
| md | 16px | `px-4 py-3` tab trigger padding, card internal padding subdivisions |
| lg | 24px | `p-6` / `md:p-8` Card content padding (settings page shell) |
| xl | 32px | `space-y-8` — page-level vertical rhythm between header / tabs / content (matches existing `<div className="space-y-8">` root wrapper on every admin page) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions: none. Nav item row height stays `h-[40px]` (existing `admin-nav.tsx` constant, unchanged) — not on the 8-point scale but it's pre-existing and out of this phase's diff.

## Typography

Matches the exact pattern already used on every admin page (`app/admin/whatsapp/page.tsx`, `app/admin/companies/page.tsx`, `app/admin/legal/page.tsx`) — reused verbatim, not redesigned:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 500 (`font-medium`, tab triggers / nav label) | 1.4 |
| Heading (page title) | `clamp(28px, 3.5vw, 40px)` | 600 (`font-semibold`) | 1.2, `tracking-tight` |
| Display | Not used in this phase | — | — |

Font weights used: 400 (body/description) and 600 (page `<h1>` + semibold tab-active state) — exactly 2 weights, matching the codebase's `--font-weight-semibold: 600` token. Tab trigger active/inactive both render at `font-medium` (500) per the existing `Tabs`/`legal/page.tsx` pattern — this is a pre-existing 3rd weight already in the shared `tabs.tsx` primitive, not introduced by this phase.

## Color

This codebase uses HSL CSS custom properties (`hsl(var(--primary))`), not static hex — documented here as the semantic roles, matching `app/globals.css`:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (0 0% 100% light / 240 10% 3.9% dark) | Page background |
| Secondary (30%) | `--glass-bg` / `--glass-border` (frosted card surface) | `Card variant="glass"` — the settings page shell, nav rail background |
| Accent (10%) | `--primary` (`--system-primary`, 224 86% 60%) | Reserved for: active nav item's left rail indicator (`before:bg-[image:var(--gradient-brand)]`), active tab underline (`after:opacity-100` / `data-[state=active]:border-primary`), pagination "Previous/Next" links, "edited" badge accent — NOT used as a background fill anywhere in this phase |
| Destructive | `--destructive` (0 84.2% 60.2%) | Not used in this phase — no destructive actions exist in the route-consolidation/settings scope (Accounts/Templates panels are reused unchanged; any destructive controls inside them are out of this phase's diff) |

Accent reserved for: the Inbox nav item's active-state left-edge indicator bar, the active Tab's bottom border/underline on the Settings page, and inline text links (Previous/Next pagination, "Configure →"-style links) — never a full-surface background fill.

## New Surface Detail — `/admin/inbox/settings/page.tsx`

Since this is the only genuinely new page shell in the phase, the exact composition (all derived from the `app/admin/legal/page.tsx` reference implementation, substituting content):

```
<div className="space-y-8">                                  {/* page-level rhythm, xl=32px gaps */}
  <Link href="/admin/inbox" className="inline-flex items-center gap-1.5 text-sm text-muted-foreground hover:text-foreground">
    <ChevronLeft size={16} /> <T>Back to Inbox</T>
  </Link>

  <div className="space-y-2">
    <h1 className="text-[clamp(28px,3.5vw,40px)] font-semibold tracking-tight">
      <T>Inbox Settings</T>
    </h1>
    <p className="text-muted-foreground">
      <T>Manage WhatsApp account provisioning and message templates.</T>
    </p>
  </div>

  <Tabs defaultValue={initialTab} className="w-full gap-5">     {/* initialTab from ?tab=accounts|templates, default 'accounts' */}
    <div className="border-b border-border">
      <TabsList variant="line" className="w-auto h-auto bg-transparent p-0 gap-0 rounded-none justify-start">
        <TabsTrigger value="accounts" className="{same classes as legal/page.tsx trigger}">
          <T>Accounts</T>
        </TabsTrigger>
        <TabsTrigger value="templates" className="{same classes as legal/page.tsx trigger}">
          <T>Templates</T>
        </TabsTrigger>
      </TabsList>
    </div>

    <TabsContent value="accounts" className="mt-0">
      <AdminWhatsAppAccounts configs={configResult} senders={senderResult} companyId={filters.companyId} />
    </TabsContent>

    <TabsContent value="templates" className="mt-0">
      <WhatsAppTemplatesPanel templates={templates} />
    </TabsContent>
  </Tabs>
</div>
```

Notes:
- The `Tabs` component here is client-side (radix `Tabs.Root` requires `'use client'` internally — already handled by `components/ui/tabs.tsx`), but tab selection should still sync to the URL (`?tab=accounts|templates`) via the existing `router.replace`/`Link`-driven pattern the old page used for its own `?tab=` param, OR via Radix's `value`/`onValueChange` + `useRouter().replace` in a thin client wrapper — implementation detail left to the planner/executor; the CONTRACT is: tab state must be shareable via URL on load (SSR-readable `searchParams.tab`) and `defaultValue` must reflect it, mirroring the old page's `?tab=accounts|conversations` behavior so bookmarks/back-button continue to work.
- Do NOT wrap each tab's content in its own `Card variant="glass"` unless the existing `AdminWhatsAppAccounts`/`WhatsAppTemplatesPanel` components don't already provide their own card chrome — check both components' existing root markup first (154-CONTEXT.md confirms these are reused unchanged; if they already self-wrap in a `Card`, do not double-wrap).
- `requireAdmin()` must be the first line of the async Server Component, before any data fetch — matches every existing admin page.
