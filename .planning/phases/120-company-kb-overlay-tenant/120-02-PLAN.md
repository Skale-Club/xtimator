<objective>
Build the tenant settings sub-route `app/(app)/settings/knowledge/` — the company owner's OWN overlay panel (KOVL-01), a DISTINCT surface from the super-admin `/admin/knowledge` (the locked two-panel rule). It is a 1:1 mirror of Phase 119's `app/admin/knowledge/` UI with three differences: (a) tenant auth (`getAuthClaims` + `getActiveCompany`, redirecting like other `/settings/*` pages) instead of `requireAdmin`; (b) the RLS-bound authed `createClient()` instead of the service client; (c) the form OMITS the industry `<Select>` (company rows have `industry_id = NULL`) and resolves `companyKnowledgeEntrySchema`. Wire it from `components/settings/settings-nav.tsx`.

This is a curation surface (add/edit/delete), NOT a navigable KB reader/browser (locked decision: no owner-facing KB browser). i18n every owner-facing string via `<T>` / `useTranslation()`.

Purpose: the owner-facing UI for the overlay; it calls the Plan 120-01 actions.
Output: 7 route/component files under `app/(app)/settings/knowledge/` + a settings-nav entry.
</objective>
