    # Stripe Connect — Owner Setup Runbook

    This is a one-time platform setup. After completing, any tenant company can connect their Stripe account from Settings → Payments and start accepting card payments on their shared estimates.

    **Time required:** ~15 minutes.
    **Prerequisites:** Stripe account in test mode + production access; admin login to Xtimator.

    ## 1. Enable Connect in Stripe Dashboard

    1. Log into [dashboard.stripe.com](https://dashboard.stripe.com).
    2. Top-left product menu → **Connect** → **Get Started**.
    3. Choose integration type: **Standard**.
    4. Confirm — Connect is now enabled for your platform.

    ## 2. Configure Platform Branding

    Stripe Dashboard → Connect → Settings → Branding:
    - Brand name: **Xtimator**
    - Brand color: `#406EF1`
    - Upload Xtimator logo
    - Support email: `support@xtimator.com` (or your owner email)

    ## 3. Configure OAuth Redirect URIs

    Stripe Dashboard → Connect → Settings → Integration:
    - Add: `https://xtimator.com/api/stripe/connect/callback`
    - Add (for dev): `http://localhost:3000/api/stripe/connect/callback`

    ## 4. Copy Client ID into Xtimator Admin

    1. Stripe Dashboard → Connect → Settings → top of page shows **Client ID** in the form `ca_...`.
    2. Copy that value.
    3. Log into Xtimator as super-admin → `/admin/integrations`.
    4. Find the **Stripe Connect Client ID** card → paste → Save.
    5. Confirm last4 displays correctly.

    ## 5. Configure Webhook Endpoint for Connected-Account Events (CRITICAL)

    The existing platform webhook endpoint (`/api/webhooks/stripe`) must be subscribed to BOTH platform AND connected-account event scopes. Same URL, same signing secret.

    Stripe Dashboard → Developers → Webhooks → click the existing endpoint:
    - Tab **Events from**: ensure both **Your account** AND **Connected accounts** are toggled on.
    - Under "Connected accounts" events, add:
      - `checkout.session.completed`
      - `account.application.deauthorized`
      - `account.updated`
    - Save.

    The `STRIPE_WEBHOOK_SECRET` env var does NOT change.

    **Warning sign of misconfiguration:** Customer pays → estimate stays `unpaid` in DB → no webhook log entry. First debug: Stripe Dashboard → Workbench → Events for the connected account.

    ## 6. Smoke Test (Test Mode)

    1. Sign up a fresh non-admin company in Xtimator.
    2. Navigate to Settings → Payments.
    3. Click **Connect Stripe Account** → complete OAuth in Stripe test mode (use a Stripe test account or create one).
    4. Return to `/settings/payments?connected=1` → verify "Connected ✓" displays.
    5. Create + share an estimate.
    6. Open the share link → click **Pay $X** → use test card `4242 4242 4242 4242` (any future date, any CVC).
    7. Verify:
       - Return to `/estimate/<token>?stripe=success` with green banner
       - Dashboard shows "Paid" badge on that estimate
       - `SELECT payment_status, paid_at, payment_amount_cents FROM estimates WHERE id='<id>'` returns `paid` + populated fields
       - Resend dashboard shows 2 emails sent (business + customer)
    8. Click **Disconnect** in Settings → Payments → confirm DB column cleared.

    ## Troubleshooting

    | Symptom | Likely cause |
    |---------|--------------|
    | OAuth redirects to "platform_not_configured" | Step 4 not done (Client ID missing) |
    | Pay Now button never appears on share page | Test company didn't complete Connect; `stripe_account_id` is null |
    | Customer pays but estimate stays `unpaid` | Step 5 not done (webhook endpoint missing "Connected accounts" scope) |
    | OAuth callback shows `invalid_state` | Cookie blocked (third-party cookie restrictions in incognito with strict mode) — retry in normal window |
    | "ca_xxx invalid" error from Stripe | Pasted secret key instead of Client ID; Client ID starts with `ca_` not `sk_` |
