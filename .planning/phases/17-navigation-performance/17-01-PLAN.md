# Phase 17 — Plan 01: loading.tsx for All Missing Authenticated Routes

**Goal:** Every authenticated route shows a skeleton UI within 50ms on navigation. Three routes currently have no `loading.tsx` file: `projects/new`, `settings`, and `settings/appearance`.

**Depends on:** Nothing — standalone file additions.
**Estimated complexity:** Low (3 small files, no logic changes)

---

## Context

**Existing loading.tsx files (do NOT modify):**
- `app/(app)/dashboard/loading.tsx` — stat cards + project list skeleton
- `app/(app)/clients/loading.tsx` — search bar + row skeletons
- `app/(app)/clients/[id]/loading.tsx` — profile card + projects list skeleton
- `app/(app)/projects/[id]/loading.tsx` — project header + tab skeleton

**Missing loading.tsx files (this plan creates):**
- `app/(app)/projects/new/loading.tsx`
- `app/(app)/settings/loading.tsx`
- `app/(app)/settings/appearance/loading.tsx`

**How loading.tsx works in Next.js 16:** A `loading.tsx` co-located with `page.tsx` automatically wraps the page in a `<Suspense>` boundary. For dynamic routes, Next.js partially prefetches the skeleton + layout so the skeleton appears on click within ~50ms on a warm connection, before the page's server data resolves.
