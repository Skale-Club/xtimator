# Phase 17 — Plan 03: Parallel Queries + Suspense Boundaries + Hover Prefetch

**Goal:** Progressive streaming for dashboard and project workspace — the layout shell renders instantly while data sections stream in. Add hover-triggered prefetch to sidebar links so clicks feel instant even before viewport-triggered prefetch runs.

**Depends on:** Plan 01 (loading.tsx) and Plan 02 (cached auth/company)
**Estimated complexity:** Medium (Suspense refactor + sidebar client component update)

---

## Context

After Plans 01 and 02:
- Every route shows a skeleton immediately (loading.tsx)
- The layout resolves from cache (~0ms on warm hits)
- Auth claims are deduplicated per request

The remaining gap: individual pages still `await` all their data before returning ANY content. With Suspense streaming, the page can return a shell immediately and stream data sections as they resolve. This benefits most on slow connections and for pages with multiple independent data queries.

**Audit of page query patterns:**

| Page | Queries | Pattern | Suspense opportunity |
|------|---------|---------|---------------------|
| `dashboard/page.tsx` | `getDashboardStats` + `getProjects` via `Promise.all` | Already parallel | Yes — stream stat cards + project list independently |
| `clients/page.tsx` | `getClients(supabase, company.id)` | Single query | Minimal — single query already fast |
| `projects/[id]/page.tsx` | 7 queries via `Promise.all` | Already parallel | Yes — stream tabs (activity, recordings, photos, estimate) independently |
| `projects/new/page.tsx` | `getClients` only | Single query | Minimal |
| `settings/page.tsx` | `getCompanySettings` | Single query | Minimal |

**Priority order:** Dashboard and project workspace have the most to gain from granular Suspense.

## Wave 1 — Dashboard Suspense Streaming

### Task 1-1: Refactor `app/(app)/dashboard/page.tsx` for streaming

**File:** `app/(app)/dashboard/page.tsx` (read before modifying)

**Current pattern:**
```ts
const [stats, projects] = await Promise.all([
  getDashboardStats(supabase, company.id),
  getProjects(supabase, company.id),
])
return (
  <div>
    <StatCards stats={stats} />
    <ProjectList projects={projects} />
  </div>
)
```

**New pattern — kick off fetches without awaiting, pass promises to components via Suspense:**

The goal is to start both fetches during render but let React stream each section as its promise resolves. The `<Suspense>` boundaries provide independent skeleton fallbacks for stat cards and project list.

```tsx
import { Suspense } from 'react'
import { Skeleton } from '@/components/ui/skeleton'

// Async sub-components that own their own data fetching
async function DashboardStats({ companyId }: { companyId: string }) {
  const supabase = await createClient()
  const stats = await getDashboardStats(supabase, companyId)
  return <StatCards stats={stats} />
}

async function DashboardProjects({ companyId }: { companyId: string }) {
  const supabase = await createClient()
  const projects = await getProjects(supabase, companyId)
  return <ProjectList projects={projects} />
}

// Skeleton fallbacks matching existing loading.tsx shapes
function StatCardsSkeleton() {
  return (
    <div className="grid grid-cols-1 sm:grid-cols-2 gap-4">
      {Array.from({ length: 4 }).map((_, i) => (
        <Skeleton key={i} className="h-24 rounded-lg" />
      ))}
    </div>
  )
}

function ProjectListSkeleton() {
  return <Skeleton className="h-64 rounded-lg" />
}

export default async function DashboardPage() {
  const claims = await getAuthClaims()
  if (!claims) { redirect('/login') }
  const company = await getCachedCompany(claims.sub)
  if (!company) { redirect('/onboarding') }

  return (
    <div className="space-y-6">
      <div className="flex items-center justify-between">
        <h1 className="text-2xl font-bold">Dashboard</h1>
        <Button asChild>
          <Link href="/projects/new">
            <Plus className="h-4 w-4 mr-2" />
            New Project
          </Link>
        </Button>
      </div>

      <Suspense fallback={<StatCardsSkeleton />}>
        <DashboardStats companyId={company.id} />
      </Suspense>

      <Suspense fallback={<ProjectListSkeleton />}>
        <DashboardProjects companyId={company.id} />
      </Suspense>
    </div>
  )
}
```

**What this achieves:** The heading + "New Project" button render immediately (static shell). Stats and project list stream independently. If stats resolve in 150ms and projects in 300ms, the user sees stats populate before projects.

**Note on colocating sub-components:** Place `DashboardStats` and `DashboardProjects` as exported functions at the bottom of `dashboard/page.tsx` (they are page-internal components, not reusable). This keeps the file self-contained.

**Verification:** `npx vitest run tests/unit/dashboard/` passes. Dev server: dashboard streams content progressively.

## Wave 2 — Project Workspace Suspense Streaming

### Task 2-1: Audit `app/(app)/projects/[id]/page.tsx` for streaming split

**File:** `app/(app)/projects/[id]/page.tsx` (read before modifying)

**Current pattern:**
```ts
const [project, activity, stats, recordings, photos, currentEstimate, allVersions] =
  await Promise.all([...7 queries...])

if (!project) { notFound() }
```

**Key constraint:** `project` existence check must happen BEFORE any Suspense boundary (to get a real 404 HTTP status, not a streamed notFound). The `notFound()` call must fire before streaming begins.

**Streaming strategy:**
1. Fetch `project` first (fast — single row by PK)
2. After confirming project exists, kick off remaining queries in parallel
3. Wrap slower sections in Suspense

```tsx
import { Suspense } from 'react'
import { notFound } from 'next/navigation'

async function ProjectTabs({
  project,
  activityPromise,
  statsPromise,
  recordingsPromise,
  photosPromise,
  currentEstimatePromise,
  allVersionsPromise,
  companyName,
}: ProjectTabsProps) {
  const [activity, stats, recordings, photos, currentEstimate, allVersions] =
    await Promise.all([
      activityPromise,
      statsPromise,
      recordingsPromise,
      photosPromise,
      currentEstimatePromise,
      allVersionsPromise,
    ])

  return (
    <ProjectWorkspace
      project={project}
      activity={activity}
      stats={stats}
      recordings={recordings}
      photos={photos}
      currentEstimate={currentEstimate}
      allVersions={allVersions}
      companyName={companyName}
    />
  )
}

export default async function ProjectPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params
  const supabase = await createClient()

  // Step 1: Fast existence check — must be before any Suspense
  const project = await getProjectById(supabase, id)
  if (!project) { notFound() }

  // Step 2: Kick off remaining queries in parallel (do NOT await yet)
  const activityPromise = getProjectActivity(supabase, id)
  const statsPromise = getProjectQuickStats(supabase, id)
  const recordingsPromise = getProjectRecordings(supabase, id)
  const photosPromise = getProjectPhotos(supabase, id)
  const currentEstimatePromise = getCurrentEstimate(supabase, id)
  const allVersionsPromise = getProjectEstimates(supabase, id)

  // Step 3: Fetch company name (can also be kicked off in parallel with step 2)
  const { data: company } = await supabase
    .from('companies')
    .select('name')
    .eq('id', project.company_id)
    .single()

  const companyName = (company?.name as string) ?? ''

  return (
    <div className="space-y-6">
      {/* Project header renders immediately — no Suspense needed */}
      <div>
        <h1 className="text-2xl font-bold tracking-tight">{project.name}</h1>
        {project.client && (
          <p className="text-muted-foreground">{project.client.name}</p>
        )}
      </div>

      {/* Workspace tabs stream in when all 6 parallel queries resolve */}
      <Suspense fallback={<ProjectWorkspaceSkeleton />}>
        <ProjectTabs
          project={project}
          activityPromise={activityPromise}
          statsPromise={statsPromise}
          recordingsPromise={recordingsPromise}
          photosPromise={photosPromise}
          currentEstimatePromise={currentEstimatePromise}
          allVersionsPromise={allVersionsPromise}
          companyName={companyName}
        />
      </Suspense>
    </div>
  )
}

function ProjectWorkspaceSkeleton() {
  return (
    <div className="space-y-4">
      <Skeleton className="h-10 w-full" /> {/* Tab bar */}
      <Skeleton className="h-64 w-full" /> {/* Tab content */}
    </div>
  )
}
```

**What this achieves:**
- Project header (name + client) renders immediately as part of the static shell
- The 6 parallel queries fire simultaneously while the project header is being sent to the client
- `ProjectWorkspace` streams in when all 6 resolve (typically the slowest of the 6)
- The `notFound()` fires before streaming begins, so 404 responses work correctly

**Verification:** `npx vitest run` — full suite passes. Navigate to a project in dev — header appears before workspace tabs.

## Wave 3 — Hover Prefetch for Sidebar Links

### Task 3-1: Create `HoverPrefetchLink` component

**File:** `components/app-shell/hover-prefetch-link.tsx` (NEW)

**Purpose:** Sidebar nav links currently use plain Next.js `<Link>` which prefetches on viewport entry. For the sidebar (always in the viewport), all routes are prefetched simultaneously on page load — this can cause unnecessary server load. Hover-only prefetch limits prefetching to routes the user is about to visit.

```tsx
'use client'

import Link from 'next/link'
import { useState } from 'react'
import type { ComponentPropsWithoutRef } from 'react'

type HoverPrefetchLinkProps = ComponentPropsWithoutRef<typeof Link>

/**
 * A Link that prefetches only on hover, not on viewport entry.
 * Use for sidebar nav items where all links are visible simultaneously.
 *
 * Source: https://nextjs.org/docs/app/getting-started/linking-and-navigating
 */
export function HoverPrefetchLink({ children, ...props }: HoverPrefetchLinkProps) {
  const [shouldPrefetch, setShouldPrefetch] = useState(false)

  return (
    <Link
      {...props}
      prefetch={shouldPrefetch ? null : false}
      onMouseEnter={() => setShouldPrefetch(true)}
    >
      {children}
    </Link>
  )
}
```

**Notes:**
- `prefetch={null}` is Next.js default behavior (prefetch the loading skeleton for dynamic routes)
- `prefetch={false}` disables all prefetching
- Toggle from `false` to `null` on first hover — subsequent hovers use the cached prefetch
- This is a client component (`'use client'`) because it uses `useState`
