**dispatch.ts:**
- Extend `NotifyParams.channels` to `{ inApp?; email?; whatsapp?; sms? }` and the resolved `channels` object to 4 keys (mirror the existing `inApp/email` defaulting from `resolved`).
- After the in-app insert + the existing email branch, add a `whatsapp` branch and an `sms` branch. Each:
  - Runs ONLY if its resolved channel is true AND `params.userId` is set.
  - Resolves the phone once: `const phone = await resolveOwnerPhone(params.companyId, params.userId)`. If `null` → skip both new channels.
  - WhatsApp: `const tpl = getTemplateForEvent(params.eventType)`; if `null` → skip.   - SMS: requires opt-in. Read the user's `sms_opt_in_at` (fetch via getUserPreferences or pass through resolved gate). If not opted-in → skip. Else `inngest.send({ name:'notification/channel.send', data:{ channel:'sms', to: phone, eventType, body: `${title}: ${body}` } })`.
  - Each branch wrapped in its OWN try/catch that logs + swallows (mirror the existing email-branch try/catch). A throw here must NOT affect the in-app insert (which already ran) or the other channel.
- Keep the existing `skipped: 'channel_disabled'` early-return logic but broaden the "all channels off" check to include whatsapp/sms.

**preferences.ts:** finalize `resolveChannels` to return `{ inApp, email, whatsapp, sms }` reading `userCat.whatsapp ?? defaults.whatsapp` and `userCat.sms ?? defaults.sms` (defaults false). The phone/opt-in gate is NOT applied here (dispatch owns it) — document that. Thread the new opt-in columns through `UserPrefs` + `upsertUserPreferences` (if not already done in Task 1).
