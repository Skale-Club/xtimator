<objective>
Thread an `attemptId` (minted once per capture session, reused on Retry) through the capture flow and the Inngest event payloads, and close the double-charge gap: make the user-initiated Retry reuse the original idempotency keys (stable `requestId` for generate, stable `recordingId` for transcribe) so an already-successful step is never re-dispatched, while a genuinely-failed step may still re-run. Also rewire `capture-recorder.tsx` to consume Plan 01's discriminated `JobResult` and map the failure state to an i18n reason, and verify "Edit manually" preserves project context.

Purpose: REC-03 (traceable attempt lineage on Retry; Edit-manually preserves context — the seam Phase 92's event store reads) and REC-04 (idempotent jobs, no double-charge — carry-forward INNGEST-06). The Inngest functions are already idempotent per key; this plan makes the user-facing Retry path produce stable keys.

Output: A capture session with a stable attempt lineage; Retry that does not re-charge already-successful AI/transcription; a repaired idempotency test.
</objective>
