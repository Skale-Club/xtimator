<objective>
Thread an `attemptId` (minted once per capture session, reused on Retry) through the capture flow and the Inngest event payloads, and close the double-charge gap: make the user-initiated Retry reuse the original idempotency keys (stable `requestId` for generate, stable `recordingId` for transcribe) so an already-successful step is never re-dispatched, while a genuinely-failed step may still re-run. Rewire `capture-recorder.tsx` to consume Plan 01's discriminated `JobResult` and map the failure state to an i18n reason. **Then rewire EVERY remaining production `pollJob` consumer** (`text-describe.tsx`, `photos-input.tsx`, `use-ai-input-submit.ts`) to read the new discriminant — Plan 01 changed `pollJob` from "throws on failure / resolves run output on success" to "always resolves a `JobResult` discriminant, never throws"; any caller left on the old assumption silently swallows failures (Pitfall 4). Finally verify "Edit manually" preserves project context.

Purpose: REC-03 (traceable attempt lineage on Retry; Edit-manually preserves context — the seam Phase 92's event store reads), REC-04 (idempotent jobs, no double-charge — carry-forward INNGEST-06), and the consumer half of REC-05 (ALL pollJob callers honor the no-throw discriminant contract so no flow regresses to silent success/failure-swallowing). The Inngest functions are already idempotent per key; this plan makes the user-facing Retry path produce stable keys and makes every caller correct against the new contract.

Output: A capture session with a stable attempt lineage; Retry that does not re-charge already-successful AI/transcription; a repaired idempotency test; and every pollJob consumer reading the JobResult discriminant (no silent regressions).
</objective>
