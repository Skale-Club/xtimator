<objective>
Eliminate the opaque 503 from `GET /api/jobs/[jobId]` and replace it with a single discriminated-`state` contract that always returns HTTP 200 for every known condition. Rewrite the polling layer (`pollJob` + `useJobStatus`) to interpret that contract without throwing on non-200, and give `CaptureFailure` a human-readable, i18n-wrapped reason mapped from the failure state.

Purpose: REC-01 (no opaque 503 / graceful degradation), REC-05 (hook distinguishes processing / failed-with-reason / config-unavailable without throwing), and the rendering half of REC-02 (friendly reason + Retry + Edit-manually, never a raw status code). This is the foundation Plan 02 builds the attempt-lineage on.

Output: One response shape the client parses everywhere; a polling layer that carries the config-vs-failure discriminant; a failure UI that shows plain language.
</objective>
