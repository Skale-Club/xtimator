Exports:

```typescript
/** Buckets whose object URL may be PERSISTED as a bare same-origin path.
 *  Every entry needs a written justification below — this set is the
 *  executable form of Phase 187's second deferred exclusion. */
export const PERSISTABLE_PROXY_BUCKETS = ['logos', 'platform-brand', 'photos'] as const
export type PersistableProxyBucket = (typeof PERSISTABLE_PROXY_BUCKETS)[number]

export function storageProxyPath(bucket: PersistableProxyBucket, key: string): string
export function isStorageProxyPath(value: string): boolean
export function parseStorageProxyPath(value: string): { bucket: ProxyBucket; segments: string[] } | null
export function absoluteAssetUrl<T extends string | null | undefined>(url: T, baseUrl: string): T
```

W7 — `absoluteAssetUrl`'s generic needs an explicit cast. TypeScript cannot prove a
value produced inside the body satisfies the caller-chosen `T`, so the joined-string
branch MUST end `return joined as T` (the passthrough branches can `return url`
directly). Without it `tsc -p tsconfig.ci.json` fails with "Type 'string' is not
assignable to type 'T'". Do NOT "fix" that by widening the signature to
`string | null` — the generic is what removes a cast at all four call sites in
Plans 03 and 04.

Also export a tiny shared predicate that Plan 03 reuses (so there is exactly one
definition of "an absolute URL we will accept"):

```typescript
/** True for a URL whose protocol is http:, https: or data:. `new URL()` alone is
 *  NOT sufficient — `javascript:alert(1)` parses successfully. */
export function isAcceptableAbsoluteAssetUrl(value: string): boolean
```

File-header docblock MUST record, per bucket, WHY it is safe to persist as a bare path — this is the answer to Phase 187 Plan 03's "no share-token path" exclusion and it must be written down, not assumed:

- `logos` — publicly readable through the proxy (`isPubliclyReadableBucket` true), so an ANONYMOUS share-page viewer and any email client resolves it with no session and no token. This is exactly why a share token is NOT needed.
- `platform-brand` — same: publicly readable, and the landing page / emails / OG tags are all anonymous surfaces.
- `photos` — NOT publicly readable, and deliberately narrow: the ONLY persisted `photos` URL is `company_price_book.image_url`, which is rendered exclusively on authenticated app surfaces (`components/price-book/price-book-list.tsx`, `components/price-book/price-book-item-dialog.tsx`, `components/trash/trash-list.tsx`). It is NEVER rendered on a share page or in a PDF. Tenant job-site photos on share pages and in PDFs keep resolving through short-lived signed URLs generated server-side (`lib/queries/share.ts`, `lib/pdf/render-estimate-pdf.ts`) — those are NOT persisted and are NOT touched by this phase.
- `audio` / `pdfs` — EXCLUDED. Nothing persists a URL for them; they are always delivered as a signed URL at send time (`lib/whatsapp/pdf-delivery.ts`). Adding them here would create a persisted private-bucket URL with no defined viewer, which is precisely the hole `canReadPrivateKey` exists to prevent.

The docblock must ALSO carry this media caveat, because membership in
`PERSISTABLE_PROXY_BUCKETS` is about ACCESS, not about playability:

> **Not every object in a persistable bucket may actually be repointed.** The Phase
> 187 proxy is whole-object pass-through with **no Range/206 and no `Accept-Ranges`**.
> Safari (desktop and iOS) refuses to play a `<video>` served from an origin that does
> not honour byte-range requests. `platform-brand` therefore holds one asset class —
> the landing hero background video (`hero-bg-videos/…`, up to 20 MB, no transcoding)
> — that must keep its absolute Supabase URL until the proxy gains Range support.
> See Plan 02's documented exemption. Persistable != streamable.

Implementation notes:
- `storageProxyPath` validates FIRST (bucket membership, then `normalizeProxyKey(key.split('/'))` must be non-null and equal `key`), then encodes: `key.split('/').map(encodeURIComponent).join('/')`, prefixed `/storage/${bucket}/`. Throw `new Error('storageProxyPath: ...')` with the bucket and a REASON but never the raw key in the message.
- `isStorageProxyPath` must reject `//host/...` explicitly (a protocol-relative URL is cross-origin, not same-origin) before the `/storage/` prefix check.
- `parseStorageProxyPath` splits on `/`, drops the leading empty + `storage`, validates the bucket with `isProxyBucket`, requires >= 1 remaining segment, returns the segments STILL ENCODED (the caller decodes — this is what lets the round-trip test mirror what Next.js does).
