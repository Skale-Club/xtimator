The table is the URL-02 "reversible record". It must be concrete enough that a
restore is a data operation, not a reconstruction:

```sql
create table if not exists public.storage_url_rewrites (
  id           bigint generated always as identity primary key,
  batch_id     uuid        not null,
  target       text        not null,   -- 'companies.logo_url', 'auth.users.user_metadata'
  row_pk       text        not null,   -- pk rendered as text ('1' for the platform_branding singleton)
  value_kind   text        not null check (value_kind in ('text','jsonb','user_metadata')),
  old_value    jsonb       not null,   -- FULL previous value (whole doc for jsonb/user_metadata)
  new_value    jsonb       not null,   -- FULL new value, so revert can detect drift
  rewritten_at timestamptz not null default now(),
  reverted_at  timestamptz
);
```

Design points that are load-bearing — do not "simplify" them away:

- `old_value`/`new_value` are **jsonb**, not text, so a scalar TEXT column, a
  whole JSONB document (`platform_branding.landing_content`) and a whole
  `auth.users.user_metadata` object all record identically. A scalar stores as a
  JSON string.
- Storing the **whole** document for jsonb/user_metadata targets (not a per-field
  patch) is what makes restore exact and single-statement.
- `new_value` exists so the revert can refuse to clobber a row that changed after
  the rewrite. Plan 02 implements that check.

Add:
- `create index if not exists storage_url_rewrites_batch_idx on public.storage_url_rewrites (batch_id);`
- `create index if not exists storage_url_rewrites_open_idx on public.storage_url_rewrites (reverted_at) where reverted_at is null;` — Plan 02's crash-recovery reads "is there an open batch?" on every apply.
- `create unique index if not exists storage_url_rewrites_batch_row_uniq on public.storage_url_rewrites (batch_id, target, row_pk);` — one record per row per batch, so re-recording inside the same batch (the crash-resume path) cannot double-record.
- `alter table public.storage_url_rewrites enable row level security;` with **no policies**, matching the `platform_integrations` convention in `20260419000001_platform_admin.sql` (deny-all for anon/authenticated; service role bypasses).

  <action>
Create `lib/storage/url-rewrite.ts`. It must be **pure**: no `import 'server-only'`,
no env reads, no I/O — the same discipline `proxy-policy.ts` and `asset-url.ts`
state in their headers, so it is importable from unit tests, from `scripts/` under
plain `tsx`, and from server code.

Exports:

```typescript
export interface ParsedStorageUrl { bucket: string; key: string }
export function parseSupabasePublicUrl(value: string): ParsedStorageUrl | null
export function isExemptFromRewrite(bucket: string, key: string): boolean
export interface RewriteResult { changed: boolean; value: unknown; exempt?: boolean; unserveable?: boolean }
export function rewriteAssetUrl(value: unknown): RewriteResult
export function rewriteJsonAssetUrls(doc: unknown): { changed: number; exempt: number; unserveable: number; value: unknown }
```

Rules:

1. **No `toProxyPath` in this module.** `lib/storage/asset-url.ts` already owns
   path construction (`storageProxyPath`) and Phase 190's header says it is "the
   ONE place a same-origin asset URL is built". Import and delegate. A second
   emitter is exactly the drift that header exists to prevent.
2. **Contract reconciliation (deliberate, state it in the header):**
   `storageProxyPath` THROWS by design on an unserveable key — a persisted URL the
   proxy would refuse is a permanently dead image, and it is right to be loud at
   the *writer*. This module is a *bulk rewriter over existing production rows*,
   where one bad legacy row must not abort the run. So `rewriteAssetUrl` wraps the
   call in try/catch and converts a throw into `{ changed: false, unserveable:
   true }`, leaving the value untouched. **The throw is not swallowed** — the
   count is surfaced by the caller (Plan 02 prints `SKIPPED_UNSERVEABLE=<n>` and
   treats non-zero as a finding to investigate before applying). Both invariants
   hold: `storageProxyPath` stays loud, the rewriter never throws.
3. **Gate on `PERSISTABLE_PROXY_BUCKETS`, not `isProxyBucket`.** A parsed bucket
   outside the three persistable ones returns `changed: false`. Reference
   `asset-url.ts`'s reasoning in a comment so nobody widens it back to five.
4. **The video exemption.** `isExemptFromRewrite` returns true for any key whose
   first segment is `hero-bg-videos`. Carry a comment in the same voice as the
   writer's:

   > Phase 192 (URL-02) — DELIBERATE EXEMPTION, do not "finish" this.
   > Mirrors `app/admin/landing/actions.ts`'s writer exemption. The hero
   > background video stays on its absolute Supabase URL: the Phase 187 proxy is
   > whole-object pass-through with no Range/206 and no Accept-Ranges, and Safari
   > (desktop + iOS) refuses to play a `<video>` from an origin that does not
   > honour byte-range requests.
   > PREREQUISITE before rewriting: the asset proxy must support Range/206.
   > Tripwire: `tests/unit/storage/url-rewrite.test.ts` asserts a video leaf stays
   > absolute.

   Match on the key prefix, not on the file extension — the writer chooses the
   directory, and an `.mp4` uploaded elsewhere is not this asset class.
5. Parse with the `URL` constructor inside try/catch, not a hand-rolled regex.
   Require `protocol === 'https:'`, hostname matching
   `/^[a-z0-9-]+\.supabase\.(co|in)$/`, pathname starting with
   `/storage/v1/object/public/`, and empty `search`/`hash`.
6. `rewriteAssetUrl` returns unchanged for anything that is not a string, already
   starts with `/storage/` (use `isStorageProxyPath` from `asset-url.ts` rather
   than a prefix test), parses to `null`, is a non-persistable bucket, or is
   exempt. **Never throws.**
7. `rewriteJsonAssetUrls` recurses over arrays and plain objects, applying
   `rewriteAssetUrl` to every string leaf **individually** (value-level, not a
   document-level substitution), returning a structural copy plus the three
   counts. It is deliberately **key-agnostic**: enumerating `landing_content`'s
   field paths would rot the moment the landing editor adds a field. Only strings
   that parse as a Supabase public storage URL for a persistable, non-exempt
   bucket are ever touched.
8. Depth cap (e.g. 32) — exceeding it returns the subtree untouched rather than
   recursing forever.

Header must state: this module is the URL-02 translation layer; the inverse
operation is not a code path but the `storage_url_rewrites` table; and it never
constructs a path itself.

Write `tests/unit/storage/url-rewrite.test.ts` covering every bullet in

images plus one `hero-bg-videos/` video leaf asserted UNCHANGED**. Include the
matrix test that compares emitted paths against real `storageProxyPath` output.
