**Edge layer.** `xtimator.com` is proxied through Cloudflare (Free plan, zone
`f4526407a944ec6098b4c1e951c0e8cd`), SSL Full (strict), origin Hetzner
`188.245.112.3` behind Coolify/Traefik. **No cache rule exists** —
`/_next/static/*` caches on Cloudflare's default rules alone because those URLs
carry real file extensions. See `docs/CLOUDFLARE-CDN.md`.

**Why HIT is plausible without a new rule.** The proxy serves `platform-brand`
`public, max-age=31536000, immutable` and sets **no `Vary: Cookie`** on public
buckets. All 11 rewritten landing values end in `.webp`, which is on Cloudflare's
default cached-extension list.

**Why it might still not.** Cloudflare's default caching keys off the file
extension. Any rewritten key **without** an extension returns
`cf-cache-status: DYNAMIC` regardless of the origin's `Cache-Control`. That is the
only case that warrants a Cache Rule. Measure first; add a rule only on evidence.
Plan 04 recorded the extensionless list, if any.

**Landing images are `unoptimized`.** `components/landing/{hero,how-it-works,features}-section.tsx`
pass `unoptimized` to `next/image` (the self-hosted standalone container has no
`sharp`). The browser requests the raw `src`, so the cache key is the
`/storage/...` path itself — there is no `/_next/image?url=…` indirection.

**Query strings are part of Cloudflare's cache key** at the Standard cache level.
That is the cache-bypass mechanism for the fallback proof: append `?cb=<random>`
to force an origin fetch.

**The hero background video is deliberately still on Supabase** (no Range/206 in
the proxy; Safari refuses such a `<video>`). **None is configured in production
today**, so the "zero `*.supabase.co`" gate below is currently unconditional in
practice — but it filters out `hero-bg-videos/` explicitly so it stays correct the
day one is uploaded.

**The reversibility precondition, and the exact command.** The Supabase
read-through covers "object is in Supabase but not yet in R2". Removing `S3_*`
returns every read to Supabase **only while no object exists SOLELY in R2**. After
Phase 188 routed server writes and Phase 189 sent browser uploads to R2, that stops
being automatic. Enumerate the R2-only set with:

```bash
npm run migrate:r2 -- --verify-only
```

The `--` is **load-bearing**: `npm run migrate:r2 --verify-only` silently swallows
the flag (`scripts/r2-migrate.ts` documents this trap in its own docblock). The
signal is the **`[EXTRA]`** row label — a destination-only object with no source
counterpart. `--verify-only` is genuinely write-free: it never calls `copyObject`.

**Observability.** `X-Asset-Source: r2|supabase` is **edge-cached along with the
body on public buckets**, so a cached value can outlive the condition it described.
The authoritative signal is the server-side `[asset-proxy] fallback` warn line from
`lib/storage/asset-source.ts`. Any header-based check must bypass the cache with
`?cb=`.

**`$TMPDIR` is EMPTY in this shell** — every redirect resolves its own temp dir:
`T="${TMPDIR:-${TMP:-/tmp}}"`.
