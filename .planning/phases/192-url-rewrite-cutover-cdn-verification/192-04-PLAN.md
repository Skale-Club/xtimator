|---|---|---|

**CSP — and the inversion the video exemption creates.** `next.config.ts` ships a
**report-only** policy with
`img-src 'self' data: blob: https://*.supabase.co https://*.googleusercontent.com`,
`media-src 'self' blob: https://*.supabase.co`, and a collector at
`/api/csp-report`. `'self'` covers the new same-origin `/storage/...` images. But
because the hero background video **stays absolute on Supabase by design**,
`media-src` must **keep** `https://*.supabase.co` — narrowing it to `'self'` would
break video playback the moment an admin uploads one. That is a finding to hand to
Phase 190's URL-04, not something to change here.

**Schema note (do not repeat the stale claim):** `lib/schemas/admin.ts` uses
`assetUrlString()` from `lib/storage/asset-url.ts` — Phase 190 already relaxed it
to accept a same-origin path. It is **not** `z.string().url()`. The remaining risk
is not validation; it is that a save round-trip could rewrite the deliberately
absolute video field. `lib/schemas/admin.ts:99-107` says so explicitly: "A relaxed
validator is not permission to repoint the writer."

  <action>

   curl -s -o /dev/null -w "%{http_code} %{content_type} %{size_download}\n" "https://xtimator.com$P"

   `.webp` images, so all 11 must come back `image/*` (`image/webp`), never
   `application/octet-stream`. If any key is extensionless, note it: Plan 05 needs
   that list for the Cloudflare cache analysis.
6. Produce the 11-row table (path, bucket, status, content-type, bytes) for the
   summary. "11/11 OK" with the table beneath it is the acceptable evidence
   format; "N rows updated" is not.
7. Record two stated non-findings, with their reasons:
   - no rewritten value lives in a tenant-private bucket, so the proxy's ownership
     gate has no subject in this batch;
   - no `hero-bg-videos/` value exists, so the video exemption has no subject
     either — it is correct and currently untriggered.
  </action>
