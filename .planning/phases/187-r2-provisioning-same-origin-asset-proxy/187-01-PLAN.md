<objective>
Build the three provider-agnostic primitives the same-origin asset proxy stands on:
a pure policy module (which buckets exist, which keys are legal, what cache directive
each bucket gets), a single-source-of-truth S3 env mapping, and a server-only dual-source
reader that returns an object's bytes plus its **real** content type from R2 first and
Supabase second.

Purpose: PROXY-02's Supabase read-through is what makes the whole v4.24 milestone
reversible — with it in place, R2 can be completely empty and nothing breaks, so
objects may be copied in any order (Phase 191). PROXY-01's "content type preserved"
requirement is non-trivial precisely because real production keys have no extension
(`platform/1784854705622-kvwo24`), so the type must come from the stored object, never
from the path.

Output: `lib/storage/proxy-policy.ts`, `lib/storage/s3-config.ts`,
`lib/storage/asset-source.ts`, and unit tests. No route yet — Plan 03 consumes these.
</objective>

      - `cacheControlFor('photos'|'audio'|'pdfs')` → `'private, no-store'`
    - Regression assertions that encode *why*:
      - `cacheControlFor('logos')` does **not** contain `immutable` and its `max-age` is ≤ 3600
      - `cacheControlFor('logos')` **does** start with `public` (it must still reach the edge)
      - `cacheControlFor('photos'|'audio'|'pdfs')` contains neither `public` nor `immutable`
    - Matrix test: `Object.keys(CACHE_CONTROL_BY_BUCKET)` sorted equals `PROXY_BUCKETS` sorted, and every value is one of the three exported literals — so a sixth bucket cannot be added without an explicit choice (TypeScript's `Record<ProxyBucket, string>` enforces the same thing at compile time; the test enforces it at runtime too).

    Exports:
    ```typescript
    export const PROXY_BUCKETS = ['audio', 'photos', 'pdfs', 'logos', 'platform-brand'] as const
    export type ProxyBucket = (typeof PROXY_BUCKETS)[number]

    export const CACHE_IMMUTABLE = 'public, max-age=31536000, immutable'
    export const CACHE_REVALIDATE = 'public, max-age=300, stale-while-revalidate=86400'
    export const CACHE_PRIVATE = 'private, no-store'

    export const CACHE_CONTROL_BY_BUCKET: Record<ProxyBucket, string>

    export function isPubliclyReadableBucket(bucket: ProxyBucket): boolean
    export function normalizeProxyKey(segments: string[]): string | null
    ```

    **B1 — the two axes are deliberately separate and must not be re-collapsed:**
    - *Access* axis: `PUBLICLY_READABLE_BUCKETS = new Set<ProxyBucket>(['logos', 'platform-brand'])`
      → who may fetch it without authenticating.
    - *Cache* axis: `CACHE_CONTROL_BY_BUCKET` → how long a copy may be kept, per bucket.
      An earlier draft derived the cache directive from the access boolean; that is a
      **bug**, and the file header must say why so it is not "simplified" back:

      > `logos` writers all use a **stable key** with `upsert: true`
      > (`{companyUuid}/logo.webp`, `user-avatars/{userId}/avatar.webp`,
      > `{companyUuid}/clients/{clientId}/logo.webp`), so the URL is byte-identical
      > after the image changes. `immutable` for a year would pin the OLD logo in
      > Cloudflare's edge cache *and* in every browser that already fetched it —
      > and browser caches cannot be purged. `platform-brand` is the opposite: its
      > keys are timestamped (`hero-images/{Date.now()}-...`), so a new asset is a
      > new URL and `immutable` is exactly right.
      > `logos` may become immutable once its writers move to versioned keys —
      > tracked as a Phase 190 candidate.

      The private buckets' `private, no-store` is a security property, not a
      performance choice: `photos`/`audio`/`pdfs` hold tenant job-site data and must
      never enter Cloudflare's shared edge cache. State that in the header too.
    - `normalizeProxyKey`: reject when `segments.length === 0`; for each segment reject
      the empty string, `.`, `..`, and anything containing `/`, `\`, or `\u0000`. Also
      reject any segment whose `decodeURIComponent` form is `.` or `..` (Next already
      decodes route params — this is belt and braces, and a decode that throws is
      itself a rejection). Then `const key = segments.join('/')`; reject
      `key.length > 1024`; return `key`. Deliberately do NOT sanitize-and-continue — a
      suspicious key is refused, never repaired, so the caller cannot be tricked into
      reading a neighbouring object.
    - File header cites PROXY-03 (allowlist + traversal) and PROXY-04 (cache split).

    Flow:
    1. `const cfg = s3ConfigFromEnv()`. If non-null:
       - `const { createS3StorageProvider } = await import('./s3-provider')` — lazy, so
         the AWS SDK stays off the Supabase-only cold path (same rationale as the
         existing lazy require in `getServerStorage`). **Import only; never edit it.**

         user. The signed URL is used in-process and never returned or logged.

         would truncate the response. Otherwise parse `content-length`, returning
         `undefined` for a missing/NaN value.
