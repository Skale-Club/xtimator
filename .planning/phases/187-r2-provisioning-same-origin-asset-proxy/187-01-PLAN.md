<objective>
Build the two provider-agnostic primitives the same-origin asset proxy stands on:
a pure policy module (which buckets exist, which keys are legal, which buckets may
be edge-cached) and a server-only dual-source reader that returns an object's bytes
plus its **real** content type from R2 first and Supabase second.

Purpose: PROXY-02's Supabase read-through is what makes the whole v4.24 milestone
reversible — with it in place, R2 can be completely empty and nothing breaks, so
objects may be copied in any order (Phase 191) and pulling the R2 env vars returns
the app to Supabase with no data movement. PROXY-01's "content type preserved"
requirement is non-trivial precisely because real production keys have no extension
(`platform/1784854705622-kvwo24`), so the type must come off the stored object, never
off the path.

Output: `lib/storage/proxy-policy.ts`, `lib/storage/asset-source.ts`, and unit tests
for both. No route yet — Plan 03 consumes these.
</objective>

  <name>Task 1: Bucket allowlist, key normalization, and per-bucket cache policy</name>
  <files>lib/storage/proxy-policy.ts, tests/unit/storage/proxy-policy.test.ts</files>
  <behavior>
    Pure module — no `server-only`, no env reads, no I/O. It is the single place
    that answers "is this bucket real", "is this key legal", "may this be edge-cached".

    - `isProxyBucket('photos' | 'audio' | 'pdfs' | 'logos' | 'platform-brand')` → true
    - `isProxyBucket('estimates' | 'PHOTOS' | 'photos ' | '' | 'photos/../logos')` → false
    - `isPublicProxyBucket('logos' | 'platform-brand')` → true; the other three → false
    - `normalizeProxyKey(['co-uuid','proj','shot.webp'])` → `'co-uuid/proj/shot.webp'`
    - `normalizeProxyKey(['platform','1784854705622-kvwo24'])` → joined key (NO extension required — extensionless keys are the production norm and must be accepted)
    - `normalizeProxyKey` returns `null` for: `[]`, `['']`, `['..','secrets']`, `['a','..','b']`, `['.']`, `['a\\b']`, a segment containing `\u0000`, a segment containing `/`, and a joined key longer than 1024 chars
    - `normalizeProxyKey(['%2e%2e','x'])` → segments arrive already URL-decoded from Next; a segment that decodes to `..` is rejected. Assert `['..']` and `['%2e%2e']` both reject (belt and braces — reject any segment whose decoded form is `.` or `..`).
    - `cacheControlFor('logos')` and `cacheControlFor('platform-brand')` → `'public, max-age=31536000, immutable'`
    - `cacheControlFor('photos'|'audio'|'pdfs')` → `'private, no-store'` — contains neither `public` nor `immutable`
    - Matrix test: iterate `PROXY_BUCKETS` and assert every bucket resolves to exactly one of the two policies, so adding a sixth bucket later forces an explicit decision rather than defaulting to public.
  </behavior>
  <action>
    Create `lib/storage/proxy-policy.ts`. NO `import 'server-only'` — it must stay
    importable from tests and from any runtime.

    Exports:
    ```typescript
    export const PROXY_BUCKETS = ['audio', 'photos', 'pdfs', 'logos', 'platform-brand'] as const
    export type ProxyBucket = (typeof PROXY_BUCKETS)[number]
    export function isProxyBucket(value: string): value is ProxyBucket
    export function isPublicProxyBucket(bucket: ProxyBucket): boolean
    export function normalizeProxyKey(segments: string[]): string | null
    export function cacheControlFor(bucket: ProxyBucket): string
    ```

    Implementation notes:
    - `PUBLIC_PROXY_BUCKETS = new Set<ProxyBucket>(['logos', 'platform-brand'])`.
      Per the locked decision this is a **security property**, not a nicety:
      `photos`/`audio`/`pdfs` hold tenant job-site data and must never land in
      Cloudflare's shared edge cache. Write that reason in the file header.
    - `normalizeProxyKey`: reject when `segments.length === 0`; for each segment
      reject empty string, `.`, `..`, anything containing `/`, `\`, or `\u0000`.
      Then `const key = segments.join('/')`; reject `key.length > 1024`; return `key`.
      Deliberately do NOT sanitize-and-continue — a suspicious key is refused, never
      repaired, so the caller cannot be tricked into reading a neighbouring object.
    - `CACHE_PUBLIC = 'public, max-age=31536000, immutable'`,
      `CACHE_PRIVATE = 'private, no-store'` — export them as named constants so
      the route and the tests assert the same literals.
    - File header cites PROXY-03 (allowlist + traversal) and PROXY-04 (cache split).
  </action>

  <name>Task 2: Dual-source asset reader — R2 first, Supabase read-through</name>
  <files>lib/storage/asset-source.ts, tests/unit/storage/asset-source.test.ts</files>
  <behavior>
    `fetchStoredAsset(bucket, key)` resolves bytes + the object's own content type
    from whichever backend actually holds it.

    - R2 env vars absent → Supabase is used directly, `source: 'supabase'`, and **no**
      fallback warning is logged (that is today's steady state, not an anomaly).
    - R2 configured and object present → `source: 'r2'`; `contentType` equals the
      `content-type` header R2 returned; `requireServiceClient` is never called.
    - R2 configured, key `platform/1784854705622-kvwo24` (no extension), R2 responds
      `content-type: image/webp` → `contentType === 'image/webp'`. This is the PROXY-01
      crux: the type comes from the stored object, never from the path.
    - R2 configured and R2 returns 404 → falls through to Supabase, returns the bytes,
      `source: 'supabase'`, and exactly one `console.warn` starting `[asset-proxy] fallback`
      is emitted containing the bucket and key.
    - R2 configured and the R2 fetch throws (network) → same fallback, warning reason differs.
    - R2 hit → no fallback warning at all.
    - Both backends miss (R2 404 + Supabase download throws) → resolves `null` (no throw).
    - Supabase blob with empty `type` → `contentType === 'application/octet-stream'`.
    - The resolved object exposes only `{ body, contentType, contentLength?, source }` —
      assert it has no property whose value contains `X-Amz-Signature`, `X-Amz-Credential`,
      or the string `token=` (PROXY-03: no signed backend URL escapes this layer).
  </behavior>
  <action>
    Create `lib/storage/asset-source.ts`, starting with `import 'server-only'`
    (vitest aliases `server-only` to a stub — see vitest.config.ts).

    ```typescript
    export type AssetSourceName = 'r2' | 'supabase'
    export interface StoredAsset {
      body: ReadableStream<Uint8Array> | Blob   // both are valid BodyInit for `new Response(...)`
      contentType: string
      contentLength?: number
      source: AssetSourceName
    }
    export function isR2Configured(): boolean
    export async function fetchStoredAsset(bucket: ProxyBucket, key: string): Promise<StoredAsset | null>
    ```

    `isR2Configured()`: true only when ALL of `S3_ENDPOINT`, `S3_REGION`,
    `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` are present and non-empty.
    **Deliberately ignores `STORAGE_PROVIDER`** — document in the file header that the
    flag half-applies today (Phase 188), and that R2-first-with-Supabase-fallback is
    correct under every combination of flag and env, which is exactly why the fallback
    exists. This must not touch `getServerStorage()`.

    `fetchStoredAsset` flow:
    1. If `isR2Configured()`:
       - `const { createS3StorageProvider } = await import('./s3-provider')` — lazy, so
         the AWS SDK stays off the Supabase-only cold path (same rationale as the
         existing lazy require in `getServerStorage`). **Import only; never edit it.**
       - Build the provider from env exactly as `getServerStorage()` maps them:
         `{ endpoint, region, accessKeyId, secretAccessKey, forcePathStyle: process.env.S3_FORCE_PATH_STYLE !== 'false' }`.
         (Verified R2 settings are `S3_REGION=auto` + path style; nothing else is needed.)
       - `const url = await provider.getSignedUrl(bucket, key, 60)` then
         `const res = await fetch(url, { cache: 'no-store', redirect: 'follow' })`.
         Pass **no** inbound headers/cookies — this call must carry nothing from the
         end user. The signed URL is used in-process and never returned or logged.
       - `res.ok && res.body` → return `{ body: res.body, contentType: res.headers.get('content-type') || 'application/octet-stream', contentLength: parseLength(res.headers.get('content-length')), source: 'r2' }`.
       - Non-ok → `await res.body?.cancel()` (do not leak the socket), record fallback,
         fall through. Any thrown error → record fallback, fall through.
       - Rationale to put in a comment: a signed-URL round trip reuses the
         already-R2-verified provider with zero new S3 code AND takes the content type
         off the wire, which is the only place it is reliable for extensionless keys.
    2. Supabase read-through (the PROXY-02 guarantee):
       - `const { requireServiceClient } = await import('@/lib/supabase/service')`,
         `const { createStorage } = await import('./index')`,
         `const blob = await createStorage(requireServiceClient()).download(bucket, key)`.
       - Return `{ body: blob, contentType: blob.type || 'application/octet-stream', contentLength: blob.size, source: 'supabase' }`.
       - On throw → return `null` (caller renders 404). Never rethrow.
    3. Fallback observability (FUT-R2-01 later has to prove the fallback went unused):
       ```typescript
       function recordFallback(bucket: string, key: string, reason: 'r2-miss' | 'r2-error') {
         console.warn('[asset-proxy] fallback', JSON.stringify({ bucket, key, reason }))
       }
       ```
       Called ONLY when R2 was configured and did not serve the object. Never called
       when R2 is simply not configured. Never log the signed URL or any env value.

    Do not add retries, caching, or an in-memory index — 51 objects, 14.3 MB.

    Test file mocks: `vi.mock('@/lib/storage/s3-provider', ...)` returning a fake
    provider whose `getSignedUrl` resolves a dummy `https://example-r2.invalid/...`,
    `vi.stubGlobal('fetch', vi.fn())` for the R2 response, and
    `vi.mock('@/lib/supabase/service', ...)` + `vi.mock('@/lib/storage/index', ...)`
    (or a spy on `createStorage`) for the Supabase leg. Use `vi.stubEnv` for the
    `S3_*` vars with obvious fake values and `vi.unstubAllEnvs()` in `afterEach` —
    never a real credential, in any form, in any test file.
  </action>
