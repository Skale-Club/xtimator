    The script's decision logic is pure enough to test with `aws-sdk-client-mock`,
    with zero real credentials.

    - `verifyBuckets(client, EXPECTED_BUCKETS)` with HeadBucket resolving for all five
      → five `{ bucket, ok: true }` results.
    - HeadBucket rejecting for `pdfs` → that entry is `ok: false` with the error name captured.
    - `verifyScope(client, 'xtimator')` (a bucket deliberately outside the five — the
      deleted smoke bucket) → HeadBucket rejects with `AccessDenied`/`NotFound`
      → result is `ok: true` ("correctly denied"). A HeadBucket that **succeeds**
      → `ok: false` ("credential is broader than the five buckets"). This inversion is
      the whole point of the check and must be covered by a test.
    - `formatReport(results)` returns a printable table and an `allPassed` boolean;
      `allPassed` is false when any entry is `ok: false`.
    - A `SKIPPED` public-access entry does not make `allPassed` false, but it never
      counts as a PASS either — assert `formatReport` renders it distinctly.
    - The module does not execute `main()` when imported (test asserts importing it
      performs no S3 call and does not touch `process.exit`).
  </behavior>
  <action>
    Create `scripts/r2-verify.ts` modelled on `scripts/storage-smoke.ts` (same docblock
    style, same inline-env convention, same `[tag] message` logging).

    Structure:
    ```typescript
    export const EXPECTED_BUCKETS = ['audio', 'photos', 'pdfs', 'logos', 'platform-brand'] as const
    export interface CheckResult { name: string; ok: boolean; detail: string; skipped?: boolean }
    export async function verifyBuckets(client: S3Client, buckets: readonly string[]): Promise<CheckResult[]>
    export async function verifyScope(client: S3Client, forbiddenBucket: string): Promise<CheckResult>
    export async function verifyRoundTrip(bucket: string): Promise<CheckResult>   // uses createS3StorageProvider
    export async function verifyPublicAccessDisabled(bucket: string): Promise<CheckResult>
    export function formatReport(results: CheckResult[]): { text: string; allPassed: boolean }
    export async function main(): Promise<void>
    ```

    - `verifyBuckets`: `HeadBucketCommand` per bucket (a bucket that exists and is
      readable by the credential answers 200). Capture `err.name` on failure.
    - `verifyScope`: HeadBucket against a name outside the five (default `'xtimator'`,
      the deleted smoke bucket; overridable via `process.argv[2]`). Denied/NotFound = PASS.
      Success = FAIL with detail "token reaches a bucket outside the allowlist".
    - `verifyRoundTrip`: reuse the exact `storage-smoke.ts` sequence via
      `createS3StorageProvider` — upload a tiny text payload to
      `verify/${Date.now()}-r2-verify.txt`, `getSignedUrl(bucket, key, 60)`,
      `download`, compare content, `delete`. Run it for **every** one of the five
      buckets (51 objects / 14.3 MB of production data — five 60-byte round trips is
      nothing). Always delete, even on assertion failure (`finally`).
    - `verifyPublicAccessDisabled(bucket)`: only when BOTH `CLOUDFLARE_API_TOKEN` and
      `CLOUDFLARE_ACCOUNT_ID` are set — `GET https://api.cloudflare.com/client/v4/accounts/${accountId}/r2/buckets/${bucket}/domains/managed`
      with `Authorization: Bearer …`. PASS only when the response parses and the
      managed-domain `enabled` field is exactly `false`. A non-200, an unparseable
      body, or a missing `enabled` field is a **FAIL**, never a pass. When the two env
      vars are absent, return `{ ok: true, skipped: true, detail: 'set CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID inline to assert public access is disabled' }`.
      Explain in a comment why this cannot be checked from the S3 side: a bucket with
      public access enabled gets an unguessable `pub-<hash>.r2.dev` hostname, so the
      absence of public access is not observable through the S3 API.
    - `main()`: build the `S3Client` from `S3_ENDPOINT` / `S3_REGION` /
      `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` (`forcePathStyle: true`), fail fast
      with a clear message naming the missing var, run all checks, print the report,
      `process.exit(allPassed ? 0 : 1)`.
    - Guard direct execution so the test can import the module safely:
      ```typescript
      import { pathToFileURL } from 'node:url'
      if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
        void main()
      }
      ```
    - Docblock must state: MIG-03; buckets already provisioned 2026-08-06 — this script
      asserts, it never provisions; run with **inline** env vars; placeholders only.

    Test file uses `mockClient(S3Client)` exactly as `tests/unit/storage/s3-provider.test.ts`
    does. No network, no real keys, no `process.exit` (test only the exported helpers).
  </action>
