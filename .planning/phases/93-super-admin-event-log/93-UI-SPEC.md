# Phase 93 — UI Design Contract

> Visual and interaction contract for the Super Admin Event Log. Operator-focused, information-dense diagnostics UI — NOT a marketing surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Prime directive:** This phase REUSES the existing `app/admin/` design language. It introduces NO new design tokens, NO new color system, NO new typography scale. The single net-new visual artifact is the **per-attempt vertical step-timeline** (D-07), composed entirely from existing tokens/components specified below. Everything else (attempts table, controls, counts, empty states) is a composition of primitives already shipped in this repo.

## Spacing Scale

Inherited from the admin pages (Tailwind 4 default 4px base + the project's `--space-stack-*` hints). All values multiples of 4. No exceptions introduced by this phase.

| Token | Tailwind | Value | Usage in this phase |
|-------|----------|-------|---------------------|
| xs | `gap-1` / `p-1` | 4px | Icon→label gap inside badges, chip groups (`gap-0.5`/`gap-1` per `data-table.tsx`) |
| sm | `gap-2` / `px-2` | 8px | Controls-row gaps (search/select/refresh), badge inner padding |
| md | `px-4 py-3` | 16/12px | Table cell padding (matches `companies/page.tsx` `px-4 py-3`) |
| lg | `space-y-6` / `gap-6` | 24px | Card internal stack (`Card` default `gap-6 py-6`), gap between timeline steps |
| xl | `space-y-8` | 32px | Page section stack — page title block → controls → table → pagination (matches admin pages `space-y-8`) |
| 2xl | `py-12` | 48px | EmptyState vertical padding (inherited from `EmptyState`) |
| 3xl | `px-8 py-8` | 64px-ish | Page gutter — supplied by `app/admin/layout.tsx <main className="px-8 py-8">`; do NOT add page-level padding |

**Concrete placements:**
- Page root container: `className="space-y-8"` (title block, controls, table, pagination as direct children).
- Table cells: `px-4 py-3` (dense, operator-readable — matches `companies/page.tsx`).
- Controls row: `flex flex-wrap items-center gap-2` (search grows, selects + refresh inline; mirrors `data-table.tsx` line 132).
- Timeline: each step `Card` separated by `gap-6` in a `flex flex-col` (or `space-y-6`); inner step content `space-y-2`.

Exceptions: none. This phase adds no spacing tokens.

## Typography

Inherited from `app/globals.css` (`--font-size-*` / `--font-weight-*`). Operator-dense surface → bias toward `sm`/`xs` for tabular data, exactly as `companies/page.tsx` and `billing-table.tsx` do. Declared roles (4 sizes, 2 weights):

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Page heading (h1) | `text-[clamp(28px,3.5vw,40px)]` | semibold (600) | tight (`tracking-tight`) | List + detail page `<h1>` (exact match to `companies/page.tsx` L32 / `companies/[id]/page.tsx` L57) |
| Section heading (h2) | 18px (`text-lg`) | medium (500) | ~1.4 | Detail "Steps" section header, count-summary label |
| Body / description | 14px (`text-sm`) | normal (400) | 1.5 (`leading-normal`) | Page description, step error messages, metadata values |
| Table / label / meta | 12px (`text-xs`) | medium (500) for headers, normal (400) for cells | 1.33 (`leading-tight`) | Table header (`text-xs uppercase tracking-wide`), cell meta, timestamps, IDs |

**Rules:**
- Exactly **2 weights** used: normal (400) and semibold (600); medium (500) is permitted only where the existing primitives already apply it (`Badge` uses `--font-weight-medium`, table headers use `font-medium`) — this matches the established admin pages and is not a third declared weight for new content.
- Monospace (`font-mono text-xs`) for all opaque identifiers: `attempt_id`, `project_id`, `estimate_id`, `user_id`, `error_code`, `provider`, `duration_ms` — exact precedent in `companies/page.tsx` L79 and `companies/[id]/page.tsx` L63. Operators scan IDs; mono prevents ambiguity (0/O, 1/l).
- Table headers: `text-xs uppercase tracking-wide text-muted-foreground font-medium` (verbatim from `companies/page.tsx` L55).

## Color

Theme is `[data-theme="admin-dark"]` (defined in `app/globals.css` L82–117). The 60/30/10 split below maps the admin shell's existing tokens — NOT new colors.

| Role | Token | Value (admin-dark) | Usage |
|------|-------|--------------------|-------|
| Dominant (60%) | `--background` | `hsl(240 6% 6%)` | Page background (from layout) |
| Surface (30%) | `--glass-bg` / `--card` | `rgba(20,24,33,0.60)` / `hsl(240 4% 11%)` | Glass cards, table container, nav, timeline step cards |
| Accent (10%) | `--primary` | `var(--platform-primary, --system-primary)` = `hsl(224 86% 60%)` | See reserved list below |
| Destructive | `--destructive` / `--danger` | `hsl(0 62.8% 45%)` / `hsl(0 72% 55%)` | Failed-status pills + failed step left-rail only |

**Accent (`--primary`) reserved EXCLUSIVELY for:**
- Active nav item indicator (existing `AdminNav` gradient rail — already applied to the new "Event Log" entry automatically).
- The Refresh button if rendered as `variant="default"`/primary (recommend `variant="outline"` to keep it quiet — see Discretion note).
- Row "view detail" link affordance (`text-[hsl(var(--primary))] hover:underline`, exact precedent `companies/page.tsx` L89).
- Active filter chip (`Button variant="default"` when selected; `ghost` when not — precedent `data-table.tsx` L164).
- Pagination current-page indicator.

Accent is NEVER used for: status meaning, table row backgrounds, generic text, or borders. Status semantics use the dedicated status palette below — accent and status are kept orthogonal.

### Status color map (D-03 / specifics — the load-bearing semantic rule)

This is the single most important color contract in the phase. Use the project's **semantic status tokens** (`--success`, `--warning`, `--danger` from `globals.css` L67–78 / L104–116), expressed via the existing `Badge` variants and a soft-fill pill idiom matching `billing-table.tsx`'s `TierBadge`:

| Attempt / step status | Semantic | Pill treatment | Left-rail (timeline) |
|-----------------------|----------|----------------|----------------------|
| `succeeded` | success / green | `bg-[hsl(var(--success)/0.15)] text-[hsl(var(--success))]` rounded-full px-2 py-0.5 text-xs font-medium | `bg-[hsl(var(--success))]` dot + connector |
| `failed` | danger / red | `Badge variant="destructive"` (or `bg-[hsl(var(--danger)/0.15)] text-[hsl(var(--danger))]`) | `bg-[hsl(var(--danger))]` dot + connector |
| `started` / in-progress (no terminal) | warning / amber-muted | `bg-[hsl(var(--warning)/0.15)] text-[hsl(var(--warning))]` | `bg-[hsl(var(--warning))]` dot, hollow/pulse connector |

**Rationale & rule:** Reuse the `TierBadge` soft-fill idiom from `billing-table.tsx` (L37–51) verbatim — `bg-<color>/15 text-<color>` rounded-full pills — but bind it to the SEMANTIC status tokens (not the hardcoded `blue/emerald/purple` tier colors). This keeps the dense table legible on the dark surface and reuses an established repo pattern. Status color is the ONLY signal that may use green/red/amber; never use them decoratively.

Counts summary uses the same three semantic colors as tiny stat figures (e.g. green number = succeeded, red = failed, amber = in-progress).

## Net-New Component Spec — `EventStepTimeline` (detail page)

The only net-new visual artifact. Lives at `app/admin/events/[attemptId]/page.tsx` as a vertical timeline. Built from existing tokens only.

**Header (attempt summary)** — a `Card variant="glass" className="p-6 space-y-4"`:
- h1 `Attempt {short attempt_id}` (mono short id) + back link above it (`companies/[id]` pattern).
- A summary line: user/company · project/estimate · `input_type` Badge · terminal-status pill (status color map). All IDs mono `text-xs`. Missing values render `—` (precedent `billing-table.tsx` L90).
- If failed: `Failed at step: {step}` in danger color.

**Timeline body** — `flex flex-col gap-6`, one item per `pipeline_events` row (ordered `created_at ASC`, D-07):
- Layout: a **left rail** (status dot 8–10px + vertical connector line `bg-border`) + a **step `Card variant="glass" className="p-4 space-y-2 flex-1"`**.
- Dot color = status color map; connector = `bg-border`; failed step connector segment may use `bg-[hsl(var(--danger)/0.4)]`.
- Step card contents (whitelist — ADMINLOG-05 / D-08, render ONLY these safe columns):
  - Row 1: `step` name (semibold `text-sm`) + status pill (right-aligned) + `created_at` time (`text-xs text-muted-foreground` mono/localized).
  - Row 2 (meta, `flex flex-wrap gap-x-4 gap-y-1 text-xs text-muted-foreground font-mono`): `Provider {provider}` · `{duration_ms} ms` · `retry ×{retry_count}` — omit any that are null.
  - Row 3 (only when `status = failed`): error block — `rounded-md border bg-[hsl(var(--danger)/0.08)] px-3 py-2`: `error_code` (mono, semibold) on first line, `error_message` (`text-sm`) below.
- **HARD GUARD (ADMINLOG-05):** the component accepts ONLY the whitelisted safe fields (`id, attempt_id, project_id, estimate_id, user_id, company_id, input_type, step, status, error_message, error_code, provider, duration_ms, retry_count, created_at`). It MUST NOT accept or render audio bytes, transcripts, or any raw provider payload. There is no "raw JSON" or "payload" affordance anywhere in the timeline.

**A11y / states:**
- Status conveyed by BOTH color AND text label (the pill always shows the status word) — never color alone (WCAG 1.4.1).
- `prefers-reduced-transparency` already collapses glass → solid card via `globals.css` L355 — inherited, no extra work.
- In-progress connector "pulse" must be gated on `prefers-reduced-motion: no-preference` if added (recommend static for v1).

## Claude's-Discretion Resolutions (auto-mode — chosen + noted)

Per `--auto`, remaining detail picks made consistent with the existing admin UI and locked decisions:

1. **Filters as `Select` (not chips)** for `status` / `input_type` / `step` — three independent multi-value dimensions read cleaner as labeled Selects (precedent `billing-table.tsx` Select usage). The status *quick-filter* may additionally surface as the count chips (clickable). Planner may keep chips for status only if preferred; both are existing patterns.
2. **Counts are filter-scoped** (D-06 recommendation) — reflect the current search+filter set, computed server-side.
3. **Refresh = `Button variant="outline" size="sm"` with `RefreshCw` icon**, right-aligned in the controls row (`ml-auto`) — keeps accent reserved and matches the quiet admin-control idiom.
4. **Page size = 50** (D-04 default).
5. **List table = server-rendered `Table`** (mirrors `companies/page.tsx`), NOT `data-table.tsx` — to honor server-side pagination (D-04). `data-table.tsx` borrowed for the search-input + chip + empty-state visuals only.
6. **Nav icon = `ScrollText`** (lucide) for the "Event Log" entry — diagnostic-log connotation, distinct from existing nav icons.
7. **Timeline visual = left-rail dot+connector + glass step cards** (specified above) — the most legible operator-dense treatment using existing tokens.
