<objective>
MARK-01 — server-derived unit_price from cost + markup, never-trust-LLM. Add OPTIONAL per-item
`cost` + `markup_pct` as AI INPUTS (schema/types + both adapters). The SERVER derives
`unit_price = round2(cost × (1 + markup_pct/100))` when both are present and no explicit unit_price
was anchored — the AI provides cost/markup, the server does the arithmetic (GUARD-03 / ENG-01).
Persist cost + markup_pct per item.

Purpose: pricing by cost+margin (the price book's cost/markup model) flows through the same
deterministic engine; the AI never computes the marked-up price.
Output: widened schema/types/adapters, markup resolution in compute-totals, persisted cost/markup,
a hand-computed markup golden + a schema-parse test.

PRECEDENCE (documented & LOCKED for this plan): an explicit AI-supplied `unit_price > 0` WINS;
markup derives `unit_price` ONLY when the AI provided `cost` + `markup_pct` and supplied no positive
explicit unit_price (or unit_price is 0/absent). Price-book ANCHORING + CLAMP (GUARD-02) are
UNCHANGED and still run AFTER — a price-book match overrides any markup-derived price. Markup is a
later resolution layer; anchoring/clamp precedence stays exactly as today.

LOCKED guardrails: server-side + deterministic; EXTEND compute-totals.ts; byte-identical when
cost/markup absent; the AI NEVER computes the marked-up price.
</objective>
